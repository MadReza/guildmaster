Status channel

The only way a worker talks back: it appends one line to state/<id>.status in its supervisor's home. Each line is an event that wakes Firstmate, not a statement of what is true now.

Read against Firstmate commit ada21f5b. Owner of the grammar and folds: bin/fm-classify-lib.sh. Worker-facing rules: bin/fm-brief.sh:426-446. Up: Communication.

What it is

Every brief tells the worker to report by appending exactly one line (bin/fm-brief.sh:426-431):

echo "{state} [at=<epoch>]: {one short line}" >> '<home>/state/<id>.status'

The file lives in the supervisor's home, outside the worker's worktree, and is only ever appended to. The brief warns that "each append wakes firstmate, so report sparingly" and lists the states working, needs-decision, blocked, paused, done, failed (bin/fm-brief.sh:428-434). How an append becomes a signal: wake and how the watcher decides whether to absorb it belongs to Supervision.

The same file is written by more than the worker: Firstmate closes answered decisions there (decisions), the pending-reply guard opens and closes escalations there (pending replies), and for a secondmate this same file in the parent home is its parent channel.

The captain-relevant set is done:|needs-decision:|blocked:|failed: plus legacy free-text tokens PR ready, checks green, ready in branch, merged for old lines without a verb; FM_CAPTAIN_RE replaces the whole set for a home (bin/fm-classify-lib.sh:66-78). The check is verb-aware: working: rebased onto merged #76 is not captain-relevant just because it contains "merged" (bin/fm-classify-lib.sh:204-229). The pause verb, its cadence, and the until parser are at bin/fm-classify-lib.sh:80-100 and bin/fm-classify-lib.sh:267-282.

The emission-time tag

New writers may put [at=<epoch>] before the colon. The grammar rules are strict and one-sided (bin/fm-classify-lib.sh:285-293):

  • A missing, malformed, or duplicated tag means the time is unknown.
  • Time is never inferred from file mtime, a wake, or when the line was read.
  • Time describes history only and "must never decide current state or decision closure".
  • Relays preserve the source's tags and leave legacy source events unstamped; status_stamp_line stamps only newly emitted lines and keeps an existing tag even if malformed (bin/fm-classify-lib.sh:317-332).

A worker-written tag can never move the head/note boundary. A readable time such as [at=10:30] contains colons, so every reader that asks where the head ends first strips anything shaped like a time tag (bin/fm-classify-lib.sh:372-396). That protects the case where a worker leaves the brief's <epoch> placeholder unsubstituted, which the brief itself warns against: "a stamp that is not plain digits records no time at all" (bin/fm-brief.sh:429).

An event, not current truth

Firstmate's charter states it twice: "A state/<id>.status line is a wake event, not current-state truth; bin/fm-crew-state.sh owns current-state reconciliation" (AGENTS.md:163, AGENTS.md:434). Two concrete reasons come from the code:

  1. A later line can hide an earlier open question. Reading "last line wins" cannot represent "an earlier decision is still open after a later, unrelated event": a subsequent done, paused, or working line silently masks a still-open needs-decision (bin/fm-classify-lib.sh:413-421).
  2. The worker stops writing when others take over. Once a worker's change is in a no-mistakes validation run, its own log gets no new entries, so an active run step or busy pane outranks even a captain-relevant log line (bin/fm-watch.sh:22-27).

So the library offers two different reads, and names them differently:

last_status_line: an event read
The last recognised event, ignoring continuation prose and blank lines. Reads the last 200 lines first and widens to the whole file only if that window holds no event (bin/fm-classify-lib.sh:131-153). Decision-closing events are kept, because skipping a resolved line would revive its opener (bin/fm-classify-lib.sh:159).
status_open_decisions: a fold
Walks the whole log and returns every decision still open, as key\tverb\tsummary lines (bin/fm-classify-lib.sh:725-754). This is "the durable open-set the fleet snapshot and any point-in-time consumer must use instead of trusting the last status line".
status_current_line: the combination
If any decision is open, the most recently opened one wins; otherwise the last event. Actual run and pane evidence is still reconciled separately by fm-crew-state.sh (bin/fm-classify-lib.sh:756-771).

Retries and duplicates

status_event_recorded answers "is this line already in the file?" ignoring only one well-formed time tag; every other byte, correlation token included, still identifies the event (bin/fm-classify-lib.sh:398-411). So a stamped retry of a recorded event is never counted as new. Writers that publish on someone else's behalf, like the parent channel, use it before appending (bin/fm-parent-channel-lib.sh:132-145).

Firstmate's own lines that must not wake Firstmate

When Firstmate itself writes bookkeeping into a status file in the same turn that already handled it (a resolved close after answering, a pending-reply escalation close, a captain-held transfer), waking itself again would waste a turn. fm_wake_status_append_self_announced appends and then advances the watcher's seen-marker across exactly those bytes, but only if it can prove no one else's bytes are in the way (bin/fm-wake-lib.sh:2178-2212):

  • This home had already read every byte before the append, or the only unread bytes are keyed needs-decision/blocked lines that the OPEN DECISIONS digest already listed.
  • The file grew by exactly the appended bytes: no other writer interleaved.
  • The watcher's own classifier finds nothing actionable in the span.

Under any other condition the lines are still appended but the marker is left alone, so the watcher surfaces the file normally. Return codes: 0 appended and self-announced, 1 appended but left for the watcher (the safe direction), 2 the append failed (bin/fm-wake-lib.sh:2210-2253).

Limits and refusals

  • A status file that is a symlink is not read by the folds (bin/fm-classify-lib.sh:733-741).
  • Rendered status lines are capped at 220 characters in the digests (bin/fm-line-cap-lib.sh:25); a writer that stamps after capping must reserve the stamp's width (bin/fm-classify-lib.sh:334-346).
  • Routine internal chatter does not belong here: the secondmate brief says "Routine internal supervision, heartbeats, retries, and crewmate churn stay inside your own home and must not touch that status file" (bin/fm-brief.sh:342).
