Communication

Every path along which Firstmate's parts talk to each other and to the captain: what each one carries, what it promises, and how it fails. The common design is that the durable record on disk is the message, and anything typed into a terminal is only a nudge to go and read it.

Read against Firstmate commit ada21f5b. Level: C4 Level 3 (components) inside the Firstmate system. Up: Level 2 containers.

Four ideas that run through every channel

The record is the delivery
A steer is a numbered file in the task's inbox; a captain note is a file in state/inbox/; a mail or mention is a wake row plus a journal entry. The terminal gets at most a fixed "look in your inbox" line, and ringing it twice is harmless (bin/fm-task-inbox-lib.sh:14-23).
Acknowledgement is a move
A worker acknowledges a steer by moving it to handled/; Firstmate acknowledges a captain note the same way with fm-inbox.sh drain --ack (bin/fm-brief.sh:254-257, AGENTS.md:441). Without the move, the sender rings again and eventually escalates.
A status line is an event, not the truth
Workers talk back by appending one line to state/<id>.status. That line wakes Firstmate, but current state is always reconciled separately, and open decisions come from a fold over the whole log, never from the last line (AGENTS.md:163, bin/fm-classify-lib.sh:413-421).
Text and lifecycle never share a channel
What an agent should read goes through fm-send; stopping or replacing an agent goes through fm-control's three allowlisted verbs. A lifecycle command sent as a message is reasoned about, not obeyed (docs/agent-control.md:10-12).
