SSH transport and entrypoint

fm-on.sh runs exactly one tracked Firstmate script in a configured remote home over plain SSH, and fm-remote-entrypoint.sh is the one fixed program on the far side that will accept it: encoded argument vectors only, never a shell command string.

Read against Firstmate commit ada21f5b.

What problem it solves

Every remote operation in Firstmate, whether launching a mate, steering it, reading its replies, handing off backlog, or retiring it, needs to run code in another machine's home. The transport gives all of them one shape: name a route and a tracked bin/fm-*.sh command, pass arguments, get back stdout, stderr, and an exit status. The usage line is fm-on.sh [--stdin] <secondmate-id|unambiguous-ssh-alias> <fm-command> [args...] bin/fm-on.sh:4-5. There is no per-command table; any genuine tracked executable in the fm-*.sh namespace is allowed bin/fm-on.sh:10-11. What keeps that safe is where the command is resolved and how many times it is re-checked, described below.

Three authorization layers

Layer 1: fm-on.sh on the primary

Route resolution

Routes come only from remote records in data/secondmates.md. A remote record carries host: (an SSH config alias), root: (the remote Firstmate code clone), and home: (the remote FM_HOME) bin/fm-on.sh:7-9. The parser recognises the remote form by that parenthesised tail bin/fm-secondmate-registry-lib.sh:37. A host alias may be used as the route only when exactly one record selects it; otherwise the call is refused with "use a secondmate id" bin/fm-on.sh:77-93.

The route argument itself must match [A-Za-z0-9._-] and must not start with - bin/fm-on.sh:64, which is what stops an option-shaped route such as -oProxyCommand=bad; the test suite asserts exactly that tests/fm-on.test.sh:463-466. The configured alias, root, and home are re-validated after lookup: safe alias characters, absolute paths, no tab, CR, or LF, no /../ or /./ components, and no empty components bin/fm-on.sh:94-101.

Command authorization

The command must be a basename in the fm-*.sh namespace with no slash and no .., must be a regular non-symlink executable in this checkout's bin/, and must be tracked by git in this checkout bin/fm-on.sh:65-74. The local check proves the caller is asking for something Firstmate ships; it does not prove the remote copy is the same, which is why the far side checks again.

Encoding and the SSH call

The root and home are each base64-encoded, and the whole argv (command first) is written as one NUL-delimited stream and base64-encoded bin/fm-on.sh:103-105. The remote command line is therefore always fm-remote-entrypoint.sh 1 <root_b64> <home_b64> <argv_b64> bin/fm-on.sh:120. Base64 output contains only letters, digits, +, /, and =, so none of the four values carries anything a remote shell would interpret. The documents state the rule ("It never accepts a shell command string" docs/remote-secondmates.md:28-29); that the encoding is the means of keeping arguments shell-inert is this page's reading of the code, not a sentence in the source.

Every call passes these options, regardless of the user's SSH configuration bin/fm-on.sh:114-121:

OptionEffect
ForwardAgent=noThe remote account never gets the primary's SSH agent.
ClearAllForwardings=yesAny configured local, remote, or dynamic forwarding is dropped for this call.
SendEnv=-*Configured SendEnv patterns are cleared, so no local environment variable is offered to the server.

-- before the hostEnds option parsing, so the alias can never be read as an option.

The header explains why keepalives do not kill long jobs: the remote sshd answers keepalive probes independently of what the remote command is doing bin/fm-on.sh:30-33. Public-key authentication and strict host-key checking stay in the operator's normal ~/.ssh configuration bin/fm-on.sh:23 docs/remote-secondmates.md:15-17. FM_SSH_BIN can substitute the ssh binary, which the tests use for a deterministic SSH boundary bin/fm-on.sh:106.

stdin and the exit status

The remote command's stdin is /dev/null unless the caller passes --stdin, because remote staging reads stdin to EOF and an open caller stream would block staging indefinitely bin/fm-on.sh:14-17. Payload callers, such as provisioning and backlog handoff, pass --stdin and pipe a file.

fm-on.sh execs ssh, so ssh's exit status is returned unchanged, and OpenSSH is never told to retry. Exit 255 "means unavailable transport or unknown remote completion and must be reconciled by the semantic caller, never blindly repeated by this layer" bin/fm-on.sh:18-21. What each caller does with 255 is on the Recovery page.

Layer 2: the fixed entrypoint

Installation

The operator clones Firstmate on the remote host at an absolute path and symlinks that clone's bin/fm-remote-entrypoint.sh into a directory on the account's non-interactive SSH PATH, for example ~/.local/bin docs/remote-secondmates.md:20-26. The entrypoint resolves its own real path (Python os.path.realpath, then realpath, then the raw path) and sources the job library from that real directory, so the symlink selects which clone is trusted bin/fm-remote-entrypoint.sh:35-41. The doctor can recreate the symlink when it is absent, but never overwrites a file there that is not its own symlink docs/remote-secondmates.md:119.

Validation, in order

  1. Exactly four arguments, and the protocol must equal the entrypoint's own PROTOCOL=1; a mismatch names both sides bin/fm-remote-entrypoint.sh:83-84.
  2. Root and home decode as base64, are non-empty, and contain no NUL, LF, or CR bin/fm-remote-entrypoint.sh:52-59 bin/fm-remote-job-lib.sh:329-331.
  3. Root canonicalises to an existing directory with a real AGENTS.md and a real bin/; home canonicalises with at most one absent leaf bin/fm-remote-entrypoint.sh:122-125 bin/fm-remote-job-lib.sh:353-377.
  4. Root and home are separate and neither contains the other bin/fm-remote-entrypoint.sh:126-128.
  5. argv[0] is an fm-*.sh basename naming a regular, non-symlink executable in <root>/bin bin/fm-remote-entrypoint.sh:130-138.
  6. The command is tracked by git in the configured root, using a git resolved only from the operator portion of the composed PATH, before <root>/bin is prepended. A checkout-local bin/git therefore cannot vouch for an untracked command bin/fm-remote-entrypoint.sh:139-145 bin/fm-remote-job-lib.sh:298-308 docs/remote-secondmates.md:56-57. The tests prove the checkout-local git is never consulted tests/fm-on.test.sh:426-429.

Failures exit 64 by default; staging and wait failures exit 70 bin/fm-remote-entrypoint.sh:43 bin/fm-remote-entrypoint.sh:178-185.

The doctor bootstrap and its digest pin

The readiness doctor is the one command not staged. It is exec'd directly in the SSH process under env -i with only PATH (the composed child PATH), HOME, FM_HOME, FM_ROOT_OVERRIDE, and FM_REMOTE_DOCTOR_BOOTSTRAP=1 (plus two test-only overrides when set) bin/fm-remote-entrypoint.sh:154-173. This is what lets read-only mode report worker gaps without depending on the worker, and lets --fix install the worker in the first place bin/fm-remote-entrypoint.sh:10-12.

Because the doctor must be able to report "git is missing", it cannot always be authorized by git. When no operator git resolves, the entrypoint accepts fm-remote-doctor.sh only if its SHA-256 matches the digest pinned in the entrypoint itself; every other command is refused with the install-or-wrapper diagnostic bin/fm-remote-entrypoint.sh:34 bin/fm-remote-entrypoint.sh:146-153 docs/remote-secondmates.md:31. At ada21f5b the pinned digest matches the doctor file byte for byte. Nothing regenerates the pin automatically; the only guard is a test that runs the repository's own doctor through a git-less bootstrap and then proves a one-byte change fails closed tests/fm-on.test.sh:431-461. Any edit to the doctor therefore requires editing the entrypoint in the same change.

Staging, waiting, relaying

For every non-doctor command the entrypoint calls fm_remote_job_ensure_worker, stages the argv and stdin as a job record, waits for the published result, prints stdout to stdout and stderr to stderr, reaps the record, and exits with the job's own status bin/fm-remote-entrypoint.sh:175-193. On Darwin a missing Aqua login session fails before staging with the console-login diagnostic bin/fm-remote-entrypoint.sh:12-15 bin/fm-remote-job-lib.sh:1205-1211.

Header and implementation differ

The entrypoint header says "Every other command is staged after the worker is ready" bin/fm-remote-entrypoint.sh:11-12, and the document says every other command "verifies" the worker docs/remote-secondmates.md:32. The function it calls does more than verify: when the LaunchAgent plist does not match its contract, the loaded job is stale, or the running worker's code identity differs, fm_remote_job_ensure_worker rewrites the plist and reloads it on macOS, or restarts the worker on Linux bin/fm-remote-job-lib.sh:1204-1237. An ordinary fm-on call can therefore repair the job worker by itself. The Herdr agent, the entrypoint symlink, and tool wrappers are repaired only by the doctor's --fix.

Cancellation when the caller goes away

A staged job whose caller disappears is cancelled rather than left to run for nobody. The EXIT trap cancels any staged-but-unfinished job; HUP, INT, PIPE, and TERM are mapped to exits 129, 130, 141, and 143 so the trap runs bin/fm-remote-entrypoint.sh:104-115. Because an ssh channel can die without delivering any signal, the entrypoint also records its parent pid at start and, while waiting, probes about once per second whether it has been reparented; only an observed parent change cancels, and an unreadable probe never does bin/fm-remote-entrypoint.sh:23-30 bin/fm-remote-entrypoint.sh:90-102 bin/fm-remote-job-lib.sh:317-324. What the worker does with a cancelled record is on the job worker page.

Layer 3: the worker's own check

Before running anything, the worker re-reads the staged record and refuses (exit 126) unless the staged root equals its own configured FM_ROOT, the root is still a real checkout, the command is a genuine fm-*.sh executable, and an operator git confirms it is tracked. The child then runs under env -i bin/fm-remote-job-worker.sh:683-766. The worker header states the contract: it "executes only a tracked non-symlink fm-*.sh under this worker's configured FM_ROOT/bin" bin/fm-remote-job-worker.sh:6-8.
