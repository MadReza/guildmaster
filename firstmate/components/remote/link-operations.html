Link operations

What actually crosses the link once a remote home is running: steers delivered as durable records, replies mirrored from an append-only log, bounded reads, backlog handoff through a confined scratch file, relaunch, and guarded retirement.

Read against Firstmate commit ada21f5b.

Every operation here uses the same commands a local secondmate uses; the remote case diverges only inside them. The shared models (steering inbox, doorbell, marked requests, pending replies, open decisions) are owned by Communication and Backlog and decisions; this page covers what the machine boundary adds.

Steering a remote mate

FM_HOME=<primary-home> bin/fm-send.sh fm-<id> '<request>'

"A routed request is delivered as a durable record in the remote home's steering inbox plus a best-effort doorbell, never by typing the payload into the pane; exit 0 means the record durably exists" docs/remote-secondmates.md:178-182. The parent's leg runs fm-on.sh <id> fm-remote-secondmate-control.sh send <id> <message> [fire-and-forget]; on the host, cmd_send locks the endpoint metadata, re-validates the endpoint, and writes the message idempotently into <home>/state/parent-route/<id>.inbox bin/fm-remote-secondmate-control.sh:256-282. That inbox is the one the rewritten remote charter names, "so a steer never lands on a parent-home path the remote host cannot reach" docs/remote-secondmates.md:194.

  • If deduplication lands on a record the mate already moved to handled/, the send succeeds without ringing again bin/fm-remote-secondmate-control.sh:283-290.
  • Otherwise the constant doorbell is rung into the recorded pane, best-effort. Outcomes 1 (composer holds pending text), 2 (did not reach the pane), and 3 (agent exited) only print notices; the record is the delivery bin/fm-remote-secondmate-control.sh:291-296.
  • Every remote attempt is bounded by FM_SEND_REMOTE_BUDGET seconds, default 30, validated as a positive integer bin/fm-send.sh:141-144 bin/fm-send.sh:775-782.
  • An unconfirmed transport (255) is retried identically once, safe because the remote write deduplicates. A budget expiry is not retried, since completion is unknown. Either outcome keeps a reply-bearing request's pending-reply expectation docs/remote-secondmates.md:183-184 bin/fm-send.sh:133-144.
  • If delivery stays unconfirmed, only the printed FM_PENDING_REPLY_EXISTING_CORR=<id> resend is safe: it keeps the body and lets the remote enqueue deduplicate onto the same record. "A plain rerun mints a different correlation and is not idempotent." An unconfirmed fire-and-forget request exits 3 and names its delivery id docs/remote-secondmates.md:185-186 bin/fm-send.sh:137-141.
  • "The remote host runs no doorbell re-ring ladder of its own"; a swallowed doorbell for an ordinary request surfaces through the parent's pending-reply recovery, whose recovery request rings again docs/remote-secondmates.md:187.

Mirroring replies back

The remote charter appends replies to state/parent-replies.status in the remote home, and the remote home's own outcome publishers append there too docs/remote-secondmates.md:192-193. bin/fm-procevent-remote-reply.sh turns that log into the parent's state/<id>.status. It is explicitly "a status-stream MIRROR, not a correlated-reply channel": a remote mate must present the same model as a local one, whose whole status stream lands in the parent's status file, so ingest leaves every semantic judgement to the parent's shared consumers bin/fm-procevent-remote-reply.sh:38-50. The machine boundary adds only cursor continuity, explicitly offered documents, replay deduplication, control-byte normalization, and a caught-up watermark bin/fm-procevent-remote-reply.sh:52-65.

The delta-read protocol

fm-remote-delta-read.sh <relative-log> <offset> <prefix-sha256> [wait-seconds] "validates continuity by hashing the exact prefix represented by the caller's cursor. It then blocks until at least one complete appended line is available, returns at most 65536 payload bytes, and never truncates or consumes the source" bin/fm-remote-delta-read.sh:2-11. It opens the log with O_NOFOLLOW, confined to FM_HOME bin/fm-remote-delta-read.sh:45-97. Output is a schema=fm-remote-delta.v1 header block (status, path, from_offset, to_offset, from_prefix_sha256, to_prefix_sha256, payload_sha256, payload_bytes, reason), a blank line, then the payload bin/fm-remote-delta-read.sh:164-174. status=continuity-broken carries a reason of truncated, prefix-changed, missing, or line-exceeds-bound bin/fm-remote-delta-read.sh:139-184. The wait is capped at 300 s; exit 75 means the window closed with no complete line bin/fm-remote-delta-read.sh:13-17 bin/fm-remote-delta-read.sh:122. This is the one preemptible job class on the worker.

What ingest guarantees

  • Applied at capture. autohandle is the runner's own entry into handle, "so applying a reply never depends on a handler remembering to run it" bin/fm-procevent-remote-reply.sh:21-25 docs/remote-secondmates.md:208.
  • One announcement. Bytes it applies land in the parent's status stream, whose ordinary signal-scan announcement wakes firstmate once; only a capture it could not fully apply is published as a separate check wake bin/fm-procevent-remote-reply.sh:27-36.
  • Replay identity. Each normalized source line, before its pointers are rewritten, is recorded as delivered; a retry or whole-log recapture never appends a second spelling docs/remote-secondmates.md:197-200 bin/fm-procevent-remote-reply.sh:421-425. The document is candid that the first recapture after upgrading can append one duplicate of a legacy line, which can read as reopening a resolved decision docs/remote-secondmates.md:199-200.
  • Correlation is per line, never a gate. Progress lines and newly raised decisions carry no corr= and travel the same path; "no single line can stop or wedge the relay or hold the cursor back" docs/remote-secondmates.md:201-202. A mirrored line with a correlation token settles its pending-reply record and closes that request's escalation docs/remote-secondmates.md:209.
  • Normalization. NUL, every other C0 control except tab and newline, and DEL become ?; printable ASCII and high bytes (UTF-8) pass unchanged; blank separators are dropped bin/fm-procevent-remote-reply.sh:398-407.
  • Documents only on offer. Only a structured report=data/….md pointer (or its bracketed form), bounded at a token boundary, offers a document; a bare path in prose is a mention bin/fm-procevent-remote-reply.sh:279-299 docs/remote-secondmates.md:196. It is fetched with fm-remote-file.sh get, capped at 262144 bytes by default bin/fm-procevent-remote-reply.sh:76.
  • Fail open on a refused document. The line is mirrored with its original pointer, the cursor advances, and one unkeyed note records the reader's reason. The note never enters the open-decision fold, because the reader cannot tell "a report that is still being written from one that will never exist" docs/remote-secondmates.md:204-206 bin/fm-procevent-remote-reply.sh:555-561. A 255 while fetching instead leaves the delta uncommitted for the runner's retry docs/remote-secondmates.md:207.
  • Continuity break. A shortened or changed prefix appends blocked [key=remote-reply-continuity-<id>] and the source is not re-armed; the cursor is never silently reset bin/fm-procevent-remote-reply.sh:19 bin/fm-procevent-remote-reply.sh:530-540 docs/remote-secondmates.md:214.
  • Caught-up watermark. When the reader exits 75, the adapter records the window's start time as the moment the parent is proven to have read through the end of the remote log bin/fm-procevent-remote-reply.sh:247-267. The pending-reply logic treats a missing correlated report as missed only after that, so an answering mate is never asked to repost while its answer is in flight, and a genuinely missing answer gets exactly one repost docs/remote-secondmates.md:210-211.

Cursor state lives in state/remote-replies/; the default wait window is FM_REMOTE_REPLY_WAIT_SECONDS=55 bin/fm-procevent-remote-reply.sh:73-76. The process-event runner itself is documented under Supervision.

Reads: peek, state, observe, summary

  • Peek. For a selector whose metadata has remote_host=, fm-peek.sh routes the capture to the host's capture verb, clamped to 100 lines; the host output is capped at 64 KiB. An unreachable host "fails loudly naming the host; the local backend adapters are never asked to read a remote target", and the error says the mate "is not thereby dead" bin/fm-peek.sh:6-10 bin/fm-peek.sh:26-39 bin/fm-remote-secondmate-control.sh:308-316.
  • State. fm-crew-state.sh asks the host's state verb. alive reports activity from the routed status log; dead or missing is reported as the host's own verdict; an unreachable or unreadable endpoint is unknown-remote … (not proof of death) bin/fm-crew-state.sh:245-281.
  • Observe. observe returns the pending-reply backend observation of the remote pane for the parent's reply recovery bin/fm-remote-secondmate-control.sh:318-326 bin/fm-pending-reply-lib.sh:1533.
  • Home summary. The fleet snapshot fetches state/home-summary.json with fm-remote-file.sh get bin/fm-fleet-snapshot.sh:1448. get resolves a home-relative path through ordinary directories to one non-symlink regular file inside the home, bounded before output bin/fm-remote-file.sh:8-9. Fleet views belong to Observability.

Backlog handoff

bin/fm-backlog-handoff.sh <id> <item-key>...

For a remote route, tasks-axi mv first moves the dependency-closed set atomically from the primary backlog into data/handoff/<id>.outbox.md; the outbox is copied to the remote handoff scratch directory, and fm-backlog-receive.sh ingests every destination-absent key under the remote backlog's own lock docs/remote-secondmates.md:229-230. Concretely bin/fm-backlog-handoff.sh:664-730:

  1. A handoff generation is advanced and the outbox snapshot is sent with fm-on.sh --stdin <id> fm-remote-file.sh put state/handoff/<id>.outbox.md 1048576 <bytes> <sha256> <generation>. put is "deliberately narrower" than get: it can only atomically replace that one scratch file, and there is no delete bin/fm-remote-file.sh:10-12.
  2. fm-on.sh <id> fm-backlog-receive.sh <rel> <bytes> <sha256> <generation> checks every item is Queued, skips keys already present, and moves the rest in one dependency-closed tasks-axi mv; it is idempotent on an ambiguous retry, may clear only its own dead lock at least 30 s old, and removes the scratch file on confirmed receipt bin/fm-backlog-receive.sh:2-16.
  3. Only then is the local outbox deleted and a best-effort receiver wake attempted; a wake that cannot be sent stays pending for a later resume or handoff bin/fm-backlog-handoff.sh:701-729.

Either transport step failing keeps the outbox: "handoff transfer to <id> was unavailable or completion is unknown; outbox preserved" bin/fm-backlog-handoff.sh:689-700. Bootstrap retries pending outboxes and wakes and emits SECONDMATE_HANDOFF: only when an outbox remains; there is no two-phase journal docs/remote-secondmates.md:232-233.

Relaunch

A live remote mate is restarted with the ordinary relaunch of the control plane, executed on that host: "the endpoint record there was written by a host-local launch and carries no remote placement, so the transaction, its checkpoint, and its postconditions are the local ones" docs/remote-secondmates.md:242. The host verb relaunch <id> <harness> <model|default|-> <effort|default|-> runs fm-control.sh <id> relaunch with the same session and skip-convergence overrides as launch bin/fm-remote-secondmate-control.sh:213-254. The primary always passes the profile explicitly, using default for an unpinned axis, because config/secondmate-harness is not inherited and "letting the far side re-resolve it would silently move the mate onto another runtime" docs/remote-secondmates.md:243. The parent side is fm-secondmate-restart.sh bin/fm-secondmate-restart.sh:46 bin/fm-secondmate-restart.sh:166.

Retirement

bin/fm-teardown.sh <id>          # guarded
bin/fm-teardown.sh <id> --force  # explicit discard, captain authority

The parent-side remote path bin/fm-teardown.sh:923-990:

  1. Refuse unless the task metadata is a secondmate and its host, root, and home match the registry route exactly.
  2. Without --force, refuse while a backlog outbox is pending or a routed reply is unresolved; refuse while the reply source still holds an unhandled capture.
  3. Call fm-on.sh <id> fm-remote-secondmate-control.sh retire <id> [--force]. On the host this runs fm-guard.sh for the home and then the ordinary fm-teardown.sh against the private parent-route state, which refuses while the remote home has child work bin/fm-remote-secondmate-control.sh:397-420 docs/remote-secondmates.md:257.
  4. On 255: "remote retirement completion is unknown; preserving the route and local records for same-host reconciliation". On another failure, re-arm the reply source.
  5. On success: finalize the reply source, clean the outbox (force only), pending replies, and receiver wake, then remove the registry line and task record.

Retirement closes only that mate's panes or 2ndmate-<id> workspace, never the shared session or a sibling's docs/remote-secondmates.md:258. A home already absent reports already-retired bin/fm-remote-secondmate-control.sh:400-404. "No generic remote delete or write surface exists: remote writes are confined to inherited allowlist files and backlog handoff scratch files, and remote home removal is reachable only through guarded secondmate retirement" docs/remote-secondmates.md:261.
