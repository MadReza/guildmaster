Security posture

What the remote link switches off on every call, what it re-verifies at every hop, what it confines and bounds, and what it deliberately never does on its own.

Read against Firstmate commit ada21f5b.

The trust model the source states

The primary trusts the operator's own OpenSSH configuration for authentication: "The SSH alias keeps normal public-key and strict host-key policy in ~/.ssh" bin/fm-on.sh:23. The operator is asked to use "ordinary public-key authentication, strict host-key verification, and a dedicated remote account where practical", and not to enable agent forwarding docs/remote-secondmates.md:16-17. Firstmate adds its own controls on top of SSH rather than replacing it. One risk is recorded as accepted: "The captain accepts this config/data parent TOCTOU within Firstmate's single-user trust boundary" bin/fm-remote-inherit.sh:63.

Verified, and verified again

  • Command identity, three times. A genuine, non-symlink, git-tracked bin/fm-*.sh in the primary checkout bin/fm-on.sh:65-74; the same in the remote root, tracked according to an operator git that cannot be a checkout-local shim bin/fm-remote-entrypoint.sh:130-153; and again in the worker, which also requires the staged root to equal its own configured root bin/fm-remote-job-worker.sh:683-725.
  • The doctor without git. Accepted only when its SHA-256 equals the digest pinned in the entrypoint bin/fm-remote-entrypoint.sh:34 bin/fm-remote-entrypoint.sh:146-150.
  • Protocol version. Both sides must agree on 1 bin/fm-remote-entrypoint.sh:84.
  • Paths. Root and home are absolute, free of control bytes, traversal, and empty components, canonicalised, separate, and non-overlapping, on both sides bin/fm-on.sh:94-101 bin/fm-remote-entrypoint.sh:117-128.
  • Home identity. Every control verb requires the .fm-secondmate-home marker to name the requested id bin/fm-remote-secondmate-control.sh:73-82.
  • Endpoint identity. Backend must be herdr, session fm-remote, target inside that session; otherwise access is refused bin/fm-remote-secondmate-control.sh:86-112. The primary re-checks the launch reply bin/fm-spawn.sh:998-1022.
  • Route identity. Spawn and teardown refuse metadata whose host, root, or home disagree with the registry bin/fm-spawn.sh:891-903 bin/fm-teardown.sh:931-940.
  • Project origins, twice. Validated by the origin library on the primary and again on the host before cloning docs/remote-secondmates.md:137.
  • Worker code identity. A running worker whose git hash-object identity no longer matches the checkout is reloaded bin/fm-remote-job-lib.sh:1048-1077.
  • Process identity. Every recorded pid is paired with its start time; a recycled pid never passes bin/fm-remote-job-lib.sh:1005-1020.
  • Herdr server birth. On macOS only a server proven born in the Aqua session is accepted; an unprovable one is treated as foreign bin/fm-remote-herdr-owner-lib.sh:48-51.
  • Readiness after repair. A repair is never trusted on its own word; a final read-only run decides bin/fm-remote-readiness-lib.sh:7-10.

Confined and bounded

  • No generic write or delete. "Remote writes are confined to inherited allowlist files and backlog handoff scratch files, and remote home removal is reachable only through guarded secondmate retirement" docs/remote-secondmates.md:261. fm-remote-file.sh put can replace only state/handoff/<id>.outbox.md and has no delete bin/fm-remote-file.sh:10-12; fm-remote-inherit.sh writes only allowlisted paths bin/fm-remote-inherit.sh:8-10.
  • Reads stay inside the home. get resolves through ordinary directories to one non-symlink regular file inside FM_HOME bin/fm-remote-file.sh:8-9; the delta reader opens its log with O_NOFOLLOW and refuses a parent outside the home bin/fm-remote-delta-read.sh:45-97. The reply adapter only fetches data/*.md paths without traversal bin/fm-procevent-remote-reply.sh:269-277.
  • Size bounds. Job argv, stdin, stdout, and stderr at most 1 MiB each bin/fm-remote-job-lib.sh:29-30; provisioning manifest 1 MiB bin/fm-remote-home-seed.sh:34; delta payload 64 KiB bin/fm-remote-delta-read.sh:9; fetched document 256 KiB bin/fm-procevent-remote-reply.sh:76; pane capture 100 lines and 64 KiB bin/fm-remote-secondmate-control.sh:312-315.
  • Time bounds. Queue deadline and execution timeout default to 360 s and cannot exceed 3600 s bin/fm-remote-job-lib.sh:123-131; send attempts are capped by FM_SEND_REMOTE_BUDGET bin/fm-send.sh:141-144; dead peers surface within about interval × count seconds bin/fm-on.sh:28-34.
  • Private state. Job records are mode 0700 with 0600 files bin/fm-remote-job-lib.sh:631-663; the remote charter is written mode 600 bin/fm-remote-home-provision.sh:242-244.
  • Byte hygiene. Control bytes from the remote log are rewritten to ? before they enter the parent's status file bin/fm-procevent-remote-reply.sh:398-407.
  • Nothing secret copied. Seeding "does not copy project trees or the primary process environment"; the parent's filesystem path is never sent docs/remote-secondmates.md:144 bin/fm-remote-home-seed.sh:207-213.

Deliberately never automated

These are reported with an exact action: step and left to a person at the remote machine docs/remote-secondmates.md:110-119 bin/fm-remote-doctor.sh:48-54:

  • Creating a GUI login session, or configuring automatic login; "SSH cannot create a GUI session from nothing".
  • Writing an auto-login password, changing FileVault, or storing any account password.
  • Installing packages, including any missing required tool that no safe wrapper can resolve.
  • Each worker runtime's own /login and keychain prompts.
  • Overwriting a non-Firstmate file at a wrapper path or at ~/.local/bin/fm-remote-entrypoint.sh.
  • Migrating an endpoint recorded outside fm-remote; there is no live cutover docs/remote-secondmates.md:165.
  • Failing a remote route over to a local replacement docs/remote-secondmates.md:5.
  • Discarding a remote mate with outstanding work: --force "requires the same captain authority as local secondmate discard" docs/remote-secondmates.md:260.

What the posture does not narrow

These are properties of the design as written, stated here so a reader does not assume more than the source provides.

  • The whole tracked namespace is callable. "No per-command table exists": any genuine, tracked bin/fm-*.sh in the remote root can be run by a caller who can reach the entrypoint bin/fm-on.sh:10-11. The controls are about which code runs (tracked, unmodified-by-shim, from the configured root), not which verbs are exposed.
  • "No generic write surface" is a property of the purpose-built verbs, not of the transport. The document's statement that remote writes are confined to allowlist and handoff files docs/remote-secondmates.md:261 holds for the remote-specific scripts (fm-remote-file.sh, fm-remote-inherit.sh). Because the transport accepts any tracked fm-*.sh, other tracked scripts that write in their FM_HOME are equally reachable through fm-on.sh. This page reads the two statements together; the source does not reconcile them.
  • SSH access equals authority. The entrypoint does no authentication of its own; anyone who can log in to the remote account and run the entrypoint is treated as the parent. The source relies on OpenSSH and a dedicated account for that boundary docs/remote-secondmates.md:15-17.
  • The remote account is trusted. Wrappers in ~/.local/bin come first on the tool PATH bin/fm-remote-job-lib.sh:258-261, so whoever controls that account controls which tools jobs run, apart from git, which must sit in the operator PATH but can itself be a ~/.local/bin wrapper docs/remote-secondmates.md:60-62.
Not settled by the source

The source does not say whether a dedicated remote account is required or only recommended beyond "where practical", nor whether the SSH key is expected to carry a forced command or other authorized_keys restrictions pointing at the entrypoint. Neither is mentioned in the remote documents or scripts.
