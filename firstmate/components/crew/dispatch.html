Dispatch

bin/fm-spawn.sh is the only way a worker comes into existence. It checks every gate before it creates anything, creates the endpoint, worktree, and record in a fixed order under locks, and reports success only after the backlog agrees the task is in flight.

Read against Firstmate commit ada21f5b. Up: Crew. The launch itself (the brief the worker reads, the staged command, the environment) is on Launch and the injected prompt.

Responsibility and contract

The header opens: "Spawn a direct report: a crewmate in a treehouse or Orca worktree, or a secondmate in its isolated firstmate home" bin/fm-spawn.sh:2-3. The supervisor contract makes it exclusive: "Spawn only through bin/fm-spawn.sh after the profile and backend checks in section 4", and "a failed isolation assertion stops the task" AGENTS.md:329-330. The header is about 390 lines long, and the script uses that header as its own --help text bin/fm-spawn.sh:403-408.

What it guarantees on success. A worker is running in an isolated, clean, current worktree (or its secondmate home). state/<id>.meta names its exact endpoint with a new spawn_gen. For ship and scout tasks the backlog row reads In flight. It prints exactly one line bin/fm-spawn.sh:381:

spawned <id> harness=<name> kind=<ship|scout|secondmate> [mode=<mode> yolo=<on|off>] window=<backend-target> worktree=<path>

The loop lives in bash because the tool shell is zsh, which "does not word-split unquoted $vars and silently breaks ad-hoc for … in $pairs loops" bin/fm-spawn.sh:236-244. A failed pair is reported and skipped, and the exit is non-zero if any pair failed bin/fm-spawn.sh:1327-1332.

The gate order

The order matters. Every check that can be made before an endpoint exists is made first, because "a refusal here costs nothing to unwind, while the same refusal after publication would strand a live pane" bin/fm-spawn.sh:3099-3103.

Step notes with evidence

1 · Preflight
Three local config files are parsed once, and a malformed one refuses before any mutation bin/fm-spawn.sh:458-518. fm_refuse_if_gate_agent stops a no-mistakes gate agent that has wandered into a Firstmate checkout. It refuses on either the NO_MISTAKES_GATE marker or a git common dir under a no-mistakes gate repo bin/fm-spawn.sh:559-561 bin/fm-gate-refuse-lib.sh:19-29. The watcher guard runs once (once per batch) bin/fm-spawn.sh:562-564.
3 · Role and capacity
A fresh spawn is main-owned while attended, so the supervision-branch actor is refused unless the away-posture record relocates queued work to it bin/fm-spawn.sh:1396-1410. The away record's spend_max_concurrent_workers caps ordinary task records (secondmates exempt) bin/fm-spawn.sh:1411-1441. The per-home task-set lock is taken with try-acquire and "Refusing rather than waiting is the fail-closed direction" bin/fm-spawn.sh:1474-1505.
4 · Backend and task lock
Resolution order and validation are on Session backends bin/fm-spawn.sh:1518-1543. A backend refusal is terminal and must never be silently retried on another backend bin/fm-spawn.sh:87-89. The per-id lock state/.spawn-<id>.lock serializes same-id spawns even across backends bin/fm-spawn.sh:1545-1550.
5 · Harness and profile
See Harness adapters and Dispatch profiles. Secondmate harness refusals: bin/fm-spawn.sh:2109-2134.
6 · Brief and contract
A fresh Treehouse-backed spawn takes the project-identity lock before allocation and refuses on contention bin/fm-spawn.sh:2708-2718. It then refuses a missing brief, leftover {TASK}/{FIRSTMATE_SPEC}, an empty Task, or an intent line addressed to the captain bin/fm-spawn.sh:2719-2735. It renders launch-brief.md bin/fm-spawn.sh:2747-2769 and checks the brief's delivery line bin/fm-spawn.sh:2785-2804.
7 · Backlog preflight
Only when the backlog gate applies (not for secondmates, manual-backend homes, or markdown homes with no backlog file). The row must read queued no no or in_flight no no, meaning state, not held, not blocked bin/fm-spawn.sh:3104-3138 bin/fm-backlog-transition-lib.sh:821-826. The error names the fix: bin/fm-tasks-axi.sh add <id> '<title>' --kind <kind> bin/fm-spawn.sh:3111. A leftover state/<id>.backlog-close also refuses bin/fm-spawn.sh:3140-3143.
8 · Endpoint and worktree
The endpoint is created first. Then, on every backend except Orca, the literal text treehouse get is typed into the new pane, and the pane's current directory is polled until two consecutive reads agree on an isolated worktree bin/fm-spawn.sh:3842-3902. Details on Worktrees and slot claims.
9 · Trust and wiring
Claude is "the one harness whose pre-launch setup can REFUSE the spawn": the directory is registered in Claude's trust store, and a failed registration stops the spawn bin/fm-spawn.sh:352-360 bin/fm-spawn.sh:3953-3964. agy's registration is non-fatal bin/fm-spawn.sh:3944-3951. A private /tmp/fm-<id> root holds Go's GOTMPDIR bin/fm-spawn.sh:3976-3996. Per-harness turn-end hooks are written outside git's view bin/fm-spawn.sh:3997-4000.
10 · Publish the record
Written to a temp file under the meta lock and published atomically; a new spawn_gen token is minted bin/fm-spawn.sh:4436-4516. The Treehouse project lock and task-set lock are released only now bin/fm-spawn.sh:4584-4596.
11 · Launch
See Launch delivery. kimi and rovo launch bare and receive a typed brief pointer after readiness and delivery gates; agy must show a busy turn bin/fm-spawn.sh:4844-4912.
12 · Commit
"This is the commit point": the backlog transition runs under the same meta lock, retried once. On failure, a fresh spawn removes its record so "no worker is left that the backlog does not own" bin/fm-spawn.sh:4914-4957. HUP, INT and TERM are deferred across the commit. An interrupted spawn re-reads the row and the record, and reports only what it verified bin/fm-spawn.sh:4538-4568 bin/fm-spawn.sh:4959-4977.

What it refuses to guess

  • The delivery contract. The mode is never looked up from data/projects.md; that file "holds the captain's standing posture as context, not as this task's answer" bin/fm-spawn.sh:9-11.
  • The harness, when profiles exist. With config/crew-dispatch.json present, a crewmate or scout spawn with no explicit harness refuses, "so firstmate cannot silently skip dispatch profile consultation" bin/fm-spawn.sh:146-150 bin/fm-spawn.sh:2088-2090.
  • Unsupported profile axes. They are "omitted from that harness's launch rather than guessed" bin/fm-spawn.sh:64-69.
  • A fallback backend. A backend refusal is terminal for that backend bin/fm-spawn.sh:87-89.
  • Herdr placement by label. Herdr "enforces no label uniqueness, so a label cannot tell two 'firstmate' workspaces apart". The worker goes into the launcher's exact workspace, and an unreadable or contradictory parent identity stops the spawn bin/fm-spawn.sh:90-99.
  • Version-dependent flags. Pi's --tui-mode regular is added only when the resolved binary's --help advertises it. pi-signed "never falls back to pi" bin/fm-spawn.sh:155-160.
  • A transient cwd. A pane still reporting the project or the primary checkout while treehouse get works is "waited out as a transient rather than adopted and then refused" bin/fm-spawn.sh:205-211.
  • A remedy for a stale submodule. It names each submodule and both pins but prints no fix command, because its containment test reads local refs only and could be fooled bin/fm-spawn.sh:226-234.
  • A relaunch identity. Backend, kind, project, worktree and endpoint come from the validated record, never the command line bin/fm-spawn.sh:38-44.

Failure behaviour and cleanup

An EXIT trap, spawn_abort_cleanup, releases every lock the run holds and removes an unpublished temporary record. It drops the slot claim only while the project lock is still held, retires a relaunch's replacement wiring, cleans an exact Herdr projection, and closes an Orca terminal and worktree bin/fm-spawn.sh:1140-1272. It closes no tmux, zellij or cmux endpoint. Refusals after step 8 instead print the endpoint to inspect, for example "treehouse get did not enter an isolated worktree within 60s (last seen …); inspect window $T" bin/fm-spawn.sh:3897-3899. The kimi, rovo and agy launch gates are the exception: they run after publication, so they close their own endpoint rather than leave "an orphaned autonomous agent outside task control" bin/fm-spawn.sh:3736-3742.

Not settled by the source

The source does not say who removes a tmux, zellij or cmux endpoint left behind by a refusal in steps 8 to 11. No record names that endpoint yet, so fm-teardown.sh <id> cannot find it. The error text leaves it to the operator.
