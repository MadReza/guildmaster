Session backends

A session backend is the terminal system that holds a worker's endpoint: tmux, Herdr, Zellij, Orca, or cmux. bin/fm-backend.sh hides them behind one opaque target per task, and the differences that remain are about what each backend can prove: whether an agent is alive, whether a pane is gone, which keys it can deliver.

Read against Firstmate commit ada21f5b. Up: Crew. How the watcher polls or subscribes to these backends belongs to Supervision.

The abstraction

bin/fm-backend.sh is "runtime-backend selection, meta helpers, selector resolution, and dispatch for firstmate's session-provider abstraction". It was built in phases: P1 extracted the original tmux command sequences into bin/backends/tmux.sh "with those SAME command sequences", then Herdr (P2), Zellij (P3), Orca (P4) and cmux (P5) were added bin/fm-backend.sh:1-31. Every script above it uses the same verbs: capture, visible capture, send key, verified text submit, kill, busy state, composer state, target existence, agent state, and push-event transitions bin/fm-backend.sh:716-1037.

A backend is framed as an event source. tmux has no native push, so "fm-watch.sh's poll loop over the pull primitives … IS the default event-source implementation" bin/fm-backend.sh:40-48. Every spawn writes the opaque target into window=. Every downstream operation treats it as routing data through fm_backend_resolve_selector, and every non-tmux backend adds its own identity fields docs/configuration.md:152-157.

Compatibility contract. A default tmux spawn writes no backend= line, and every reader treats an absent line as tmux, "so existing and newly spawned default-path metas stay byte-identical" bin/fm-backend.sh:33-38.

How a backend is chosen

The flag is narrow on purpose. An explicit --backend requires "current authority for that exact task alone … never later-task precedent by analogy" docs/configuration.md:137, and the supervisor contract repeats it AGENTS.md:240-241. Detection checks $TMUX first because tmux sets it in every process inside it, even a tmux started inside Herdr. cmux comes last because "it is a terminal application (the outermost layer…), not a session multiplexer" bin/fm-backend.sh:94-116.

Why "recovery-grade agent state" is the key difference

Recovery must never start a second agent on a live worktree. The tmux probe checks exact window membership, then reads process names from two independent sources to tell a running harness from a bare shell. It returns alive, dead, missing, unreadable, or ambiguous, and "Only dead and missing authorize recovery because a false dead result could launch a duplicate agent" docs/tmux-backend.md:47-60. Herdr's registered agent state is not trusted alone: a registration can outlive the process, so the adapter verifies it against the real process table with the same shared classifier docs/herdr-backend.md:280-303.

Backends without that classifier (Zellij, Orca, cmux) cannot prove an agent stopped. So fm-control.sh exit and relaunch refuse on them docs/agent-control.md:155-156, fm-crew-state.sh keeps reading a failed capture as gone bin/fm-crew-state.sh:1179-1180, and a dead Zellij secondmate "is reported inconclusive rather than auto-respawned" docs/zellij-backend.md:98-100.

Only Herdr can prove that an endpoint is gone rather than unreachable, because every Herdr read is scoped to the session the record names. That is why endpoint reclaim is Herdr-only (Control plane).

Per-backend notes

tmux
If the first mate runs inside tmux, tasks become windows in its session. Otherwise Firstmate creates or reuses a detached session named firstmate. Each window is named fm-<id>, and typing into it is "authoritative direct intervention" docs/tmux-backend.md:17-38. Spawn pins the name and captures a stable window id, so a captain's tmux config cannot rename the window away mid-spawn bin/fm-spawn.sh:3238-3243.
herdr
Every call carries an explicit --session <name>, because "An environment variable alone is not reliable when another Herdr server is running" docs/herdr-backend.md:219-225. Workers go into the launcher's exact workspace, never a label match, since Herdr "does not enforce workspace or tab label uniqueness" docs/herdr-backend.md:46-64. From Herdr 0.8.0, each crewmate or scout also gets a disposable one-task "presentation space" by default. It is presentation only and "never endpoint or ownership authority" docs/herdr-backend.md:81-86 docs/agent-control.md:125. Destructive lab work is confined to bin/fm-herdr-lab.sh with fm-lab- session names docs/herdr-backend.md:334-345.
zellij
One shared session for all homes, with home-scoped titles to prevent id collisions. It has no native busy signal, no push events, and no agent-process liveness docs/zellij-backend.md:34-47 docs/zellij-backend.md:94-104.
orca
The app owns both worktree and terminal, so spawn never runs Treehouse. The composite orca_worktree_id=<repo id>::<path> is the cleanup authority. Escape is unsupported. The Claude trust check may refuse an Orca worktree if Orca clones instead of linking docs/orca-backend.md:29-45 docs/orca-backend.md:70-78.
cmux
A fresh surface's read-screen errors until something is written, so readiness uses the structural list-panes. Worktree discovery wraps pwd in markers, because current_directory does not follow treehouse get's subshell. Workspace ids do not survive an app relaunch docs/cmux-backend.md:84-95 docs/cmux-backend.md:115-124.

Codex App: a documented non-backend

Codex App is "not a selectable Firstmate runtime backend". Its host tools can create and supervise visible threads, but "Firstmate has no supported shell-callable bridge to those host tools. A manual thread ledger is not a backend" docs/codex-app-backend.md:1-5. The acceptance contract lists what any future backend must do: create an endpoint with a durable id, send instructions and later messages, read live state, stop the exact endpoint, and let the thread append Firstmate's lifecycle lines to state/<id>.status. "The status return channel is mandatory" docs/codex-app-backend.md:7-18. That list is the best statement in the source of what a backend fundamentally is.
