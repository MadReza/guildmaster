Scout promotion

bin/fm-promote.sh turns a finished scout into a ship task without replacing the worker. The window, worktree, and loaded context stay; only the contract changes, and teardown's full ship protection comes back.

Read against Firstmate commit ada21f5b. Up: Crew. Related: Scout, Teardown.

Why promote rather than spawn again

A scout that reproduced a bug already holds the context needed to fix it. The supervisor contract says: "When implementation is separately authorized, promote the existing scout through bin/fm-promote.sh rather than creating a duplicate task" AGENTS.md:415. The scout brief tells the worker up front that "firstmate may promote this task in place" bin/fm-brief.sh:468. A report on its own authorizes nothing: "A report may recommend implementation but does not authorize it" AGENTS.md:412.

The contract

fm-promote.sh <task-id> --mode <no-mistakes|direct-PR|local-only> --yolo <on|off>

"Promote a scout task to a ship task in place: the crewmate keeps its window, worktree, and loaded context; only the contract changes. Flips kind= to ship in state/<task-id>.meta so fm-teardown.sh applies the full ship-task teardown protection again" bin/fm-promote.sh:2-5. Because a scout records no delivery posture, "promotion is where this task's delivery contract is decided: --mode and --yolo are REQUIRED". The script never looks up the project's standing mode, and it refuses no-mistakes-prod-only bin/fm-promote.sh:21-27 bin/fm-promote.sh:80-99.

What it does, in order

  1. Lock and check. It takes state/.control-<id>.lock, the same lifecycle lock fm-control.sh uses, and refuses with "another lifecycle action is already running". The record must be safe and contain kind=scout exactly bin/fm-promote.sh:102-145.
  2. Validate the scout brief. It refuses leftover {TASK}/{FIRSTMATE_SPEC}, an empty Task, a Captain-addressed intent line, or a legacy brief with no provenance-marked captain words bin/fm-promote.sh:147-168.
  3. Render the ship instructions to data/<id>/ship-instructions.md: the captain's intent preserved from the scout brief; a new ship-time ## Firstmate spec; and a delivery contract rendered by bin/fm-dod-lib.sh, "the single owner an ordinary ship brief also uses" bin/fm-promote.sh:176-231 bin/fm-promote.sh:6-14.
  4. Append the same contract to brief.md. "a replacement worker is launched from brief.md. Publish the same explicit precedence contract there so a later relaunch cannot revive the original scout delivery rules" bin/fm-promote.sh:233-258.
  5. Rewrite the record under the meta lock: drop the old kind=, mode= and yolo= lines, append kind=ship, mode= and yolo=, and publish atomically bin/fm-promote.sh:259-273.
  6. Print the next step, for example next: FM_HOME=… bin/fm-send.sh fm-<id> "$(cat …/ship-instructions.md)". When the Relay public-follow-up plane is active, it also prints a fm-public-followup.sh rechain hint bin/fm-promote.sh:281-385.

What the promoted worker is told to do

The ship-time spec is fixed text bin/fm-promote.sh:181-190:

  1. Verify isolation before anything else.
  2. Inventory scratch state with git status and git log.
  3. Return to a clean default-branch base, then git checkout -b fm/<id>.
  4. Carry over only the intended fix, leaving scratch commits, debug edits, and experiment files behind.
  5. Turn a reproduced bug into a regression test.
  6. Treat the scout-time spec as context, not intent.
  7. Keep the status protocol, inbox, escalation, and safety rules.

It opens with an idempotence rule: "If these promotion steps were already completed before a relaunch, preserve the existing fm/<id> branch and continue from its current state". The supervisor contract states the same obligations AGENTS.md:416.

The delivery section says it supersedes the scout rules explicitly: "Any earlier 'Never push' or scout-only delivery language in this file is superseded" bin/fm-promote.sh:191-207. For no-mistakes it also includes the ask-user escalation block, closing what a code comment calls "the delivery hole this file used to leave open" bin/fm-promote.sh:170-175.

Effects on other parts

  • Teardown. kind=ship brings back the dirty and landed-work checks, and the backlog close records a PR or local-main note instead of a report bin/fm-teardown.sh:1521-1537.
  • Relaunch. A later relaunch reads brief.md, which now carries the ship contract; the worker role contract is still rendered first at launch (Launch).
Not settled by the source

fm-promote.sh rewrites the task record and the brief, but it makes no backlog call beyond the record publication helper bin/fm-promote.sh:42-45 bin/fm-promote.sh:267. The backlog row was created with --kind scout bin/fm-spawn.sh:3111. The "Recently Landed" selector counts a merged completion as a delivery only when the row's kind is not scout bin/fm-landed-lib.sh:57-69. The source does not show whether anything later updates the row's kind, so it does not settle whether a promoted scout's merged PR appears in "Recently Landed".

Observation

The printed command addresses the worker by its legacy label fm-<id>. Selector resolution checks an exact task id before falling back to that label, so it still reaches the right task docs/configuration.md:158-161.
