Control plane

bin/fm-control.sh drives a running worker's lifecycle with a closed set of verbs (interrupt, exit, relaunch) addressed to an exact task id, with per-harness mechanics taken from a table and a verified postcondition for every action. It never tears anything down.

Read against Firstmate commit ada21f5b. Up: Crew. The data plane (fm-send.sh, the steering inbox) belongs to Communication.

Why a separate control plane

Firstmate talks to a running agent over two channels. The data plane, bin/fm-send.sh, carries text for the agent to read. For a secondmate that text always carries the from-firstmate routing marker. "The split exists because the data plane's marking is exactly right for a message and exactly wrong for a lifecycle command. A routing-marked /quit arrives as ordinary chat - [fm-from-firstmate] /quit - which the agent reasons about instead of executing." Before the split, the workaround "lived only in agent prose, so it failed again every time a session did not happen to recall it" docs/agent-control.md:3-12. The supervisor contract forbids using fm-send for lifecycle control AGENTS.md:338-339.

What it owns

bin/fm-control-lib.sh is "the single executable owner of three capability tables, which have no side effects, so they can be read as a contract" docs/agent-control.md:14-28:

  • The verb allowlist: interrupt, exit, relaunch. There is "no arbitrary-text and no generic raw-key entry point" bin/fm-control-lib.sh:49-62.
  • Per-harness mechanics: the interrupt key (Escape everywhere except grok's Ctrl+C), the repeat count (opencode needs two), the composer clear (only muse restores the cancelled prompt and needs Ctrl+U), the acknowledgement source (only muse's session log confirms a cancel), the exit command (/exit or /quit), and the task kinds each adapter supports bin/fm-control-lib.sh:113-193.
  • Per-backend capability: which keys a backend can deliver (Orca has no Escape or Ctrl+U), and whether it has a recovery-grade agent-state classifier (tmux and herdr only) bin/fm-control-lib.sh:195-261.

It also owns one non-table function, the endpoint-absence proof fm_control_endpoint_absence_verdict, so that "exit and relaunch cannot reach two different answers about one endpoint" bin/fm-control-lib.sh:262-292 docs/agent-control.md:105-108.

The verbs

fm-control.sh <task-id> interrupt
fm-control.sh <task-id> exit
fm-control.sh <task-id> relaunch [--harness <name>] [--model <name>] [--effort <level>] (--note <text> | --note-file <path>)
VerbEffectPostcondition
interruptDelivers the verified interrupt sequence; the agent keeps running.Delivery succeeded, the endpoint exists, and the agent is alive where classifiable. A cancel is confirmed only by an adapter acknowledgement, otherwise cancel=unconfirmed.
exitInterrupts if busy, requires an empty composer, then types the exit command. Endpoint, worktree, and every uncommitted change are preserved.The recovery-grade classifier reports the agent gone. Already stopped is idempotent success. Unproven is exit=unconfirmed.
relaunchReplaces the agent in the same worktree, and the same endpoint when it still exists, on the same or a new harness, model, or effort.The new agent is alive on the endpoint the record names, and the record names the harness actually running.

Sources: bin/fm-control.sh:5-79, docs/agent-control.md:31-52.

Deliberately absent. "Teardown and discard are NOT verbs here and never will be" bin/fm-control.sh:80-83. resume is not a verb either: it "is not deterministic across the verified adapters", and relaunch covers the need "because the brief on disk, not a harness-private session, is the durable instruction" bin/fm-control.sh:85-88 docs/agent-control.md:54-56.

Relaunch is a transaction

Relaunch is the only verb that changes durable records. It keeps a journal at state/<id>.control-relaunch, with the prior record and brief preserved beside it (.meta-prior, .brief-prior, .note) bin/fm-control.sh:569-581.

  • Profile. A ship or scout keeps its recorded harness "because that harness comes from firstmate's dispatch-profile judgment at intake and must not be silently re-read from configuration". A secondmate re-resolves its config/secondmate-harness pin, so "setting the pin and relaunching is the ordinary way to move a secondmate's runtime". A harness change resets model and effort unless they are named too docs/agent-control.md:62-67.
  • The note. A ship or scout relaunch requires --note, "because the replacement inherits the local copy but none of the conversation". It is appended to data/<id>/brief.md under ## Progress note (<timestamp>), and a retried relaunch leaves one block per attempt docs/agent-control.md:73-74 docs/agent-control.md:114.
  • A harness switch is not special. "Switching harness is therefore one ordinary relaunch rather than a separate mechanism" docs/agent-control.md:79.
  • Launch owner checks. fm-spawn --relaunch independently refuses unless the endpoint is positively agent-free, and requires the shell to be in the recorded worktree. On tmux a drifted shell refuses at once; on Herdr it is sent one cd and must confirm the move bin/fm-spawn.sh:3809-3841. It clears the previous harness's per-task wiring before arming the new one bin/fm-spawn.sh:44-46.

Reclaiming a task whose endpoint is gone

A Herdr pane can be destroyed by churn or a server restart while the worktree and all its work survive. Two endpoint verdicts license a relaunch: dead (it exists and holds no agent), which is adopted, and gone, proven, where one fresh endpoint is created in the recorded worktree and the record is rebound to it docs/agent-control.md:81-93.

A backend's missing "conflates the endpoint was destroyed with the endpoint is unreachable from here right now", so absence has to be proven:

  • Herdr can prove it. Reads are scoped to the session the record names. The proof starts that session's server if needed and re-reads the recorded pane; only a second missing proves it gone. Starting a server is a real side effect, which can leave an idle Herdr server behind docs/agent-control.md:96-100.
  • tmux cannot. list-windows -a sees only the server the current process addresses, and a record carries no socket identity. "There is no read available that closes that gap, so tmux always refuses" docs/agent-control.md:101-103.

A reclaim is "not a teardown", does "not change the task's identity", is "not a peer seat's operation", and does "not cover a secondmate" docs/agent-control.md:110-117. The new tab goes into the session the record names, but the workspace follows the reclaiming seat, so herdr_workspace_id can move docs/agent-control.md:119-124.

Known limitation, documented

"a refusal before the record is republished leaves a stray husk pane". It holds a bare shell and self-heals on the next reclaim only if that reclaim resolves the same workspace docs/agent-control.md:127-131 bin/fm-spawn.sh:3180-3184.

Fail-closed boundaries

  • Exact targeting. Only a bare task id with a state/<id>.meta in this home that passes endpoint-identity validation. Legacy fm-<id> labels and raw session:window targets refuse, since "a lifecycle command delivered to the wrong endpoint is far worse than a loud refusal" bin/fm-control.sh:90-95.
  • Remote secondmates refuse by name. Their relaunch runs on their own host through bin/fm-on.sh <id> fm-remote-secondmate-control.sh relaunch … docs/agent-control.md:145-148.
  • Kind checks before the stop. An adapter not verified for the task's kind refuses "while its agent is still up", not after docs/agent-control.md:151-152.
  • Classifier required. exit and relaunch need tmux or herdr; Zellij, Orca and cmux refuse "rather than reported as successful blind" docs/agent-control.md:155-156.
  • Composer. exit requires an exact empty verdict; pending refuses by naming the text docs/agent-control.md:48.
  • One lifecycle action at a time, through state/.control-<id>.lock, which fm-promote.sh also takes bin/fm-promote.sh:102-133.
