Teardown

bin/fm-teardown.sh retires a finished task: it returns the worktree, closes the endpoint, clears volatile state, and closes the backlog item. It refuses whenever that could destroy work that has not landed, or work that belongs to another task.

Read against Firstmate commit ada21f5b. Up: Crew. Clone refresh after a merge belongs to Delivery; the backlog close to Backlog and decisions.

Contract

fm-teardown.sh <task-id> [--force] [--legacy-record]

"Tear down a finished task: return the treehouse worktree, release the Orca worktree, or retire a secondmate home; kill the recorded runtime endpoint, clear volatile state, and transition this home's backlog item for ship and scout tasks before reporting success …, then refresh/prune the project's clone for PR-based ship tasks" bin/fm-teardown.sh:2-7. The header runs to about 280 lines. When to call it is set by the supervisor contract: "Tear down a ship task only after landing is confirmed. A teardown refusal for uncommitted or unlanded work is a stop-and-investigate result, never an obstacle to bypass. Never force teardown without explicit discard authority" AGENTS.md:401-403.

On success it prints one of: teardown <id> complete (window …, worktree …); the same with a legacy-record note; or, when the slot had been reassigned, "pool slot … left to task … which it was reassigned to" bin/fm-teardown.sh:3709-3714.

The landed-work test (ship tasks)

"REFUSES if the worktree holds work that has not LANDED, because cleanup hard-resets/removes the worktree and kills its processes" bin/fm-teardown.sh:44-45. The implementation is validate_worktree_teardown_safety with its helpers bin/fm-teardown.sh:1780-1843.

  • "Landed" first means "not only local". Work has landed "when it is reachable from any remote-tracking branch (a fork counts as a remote, …)" bin/fm-teardown.sh:46-48. A branch that has been pushed but whose PR is still open therefore passes this test. Merge itself is enforced by the supervisor contract ("only after landing is confirmed"), not by the script.
  • Squash merges. A squash-merged PR whose branch was deleted leaves the commits on no remote, so teardown asks GitHub. It accepts a merged PR whose head contains the current local work, either as an ancestor or with every unpushed commit's patch id present in the PR. It falls back to a three-way merge of HEAD into the freshly fetched default branch, which must reproduce the default tree exactly bin/fm-teardown.sh:48-59 bin/fm-teardown.sh:1441-1509.
  • What it deliberately rejects. "A diverged copy is not treated as landed: path-set coverage, git cherry, and merge-tree containment each fail to prove content landed without also accepting unlanded edits to the same paths" bin/fm-teardown.sh:53-58.
  • A missing pr= does not cause a false refusal. The PR is looked up by head branch, and its head is fetched through refs/pull/<n>/head when the branch is gone. A gh error falls back to the content check, and an inconclusive result refuses bin/fm-teardown.sh:60-68.
  • "Uncommitted changes are never landed" bin/fm-teardown.sh:68. Only Firstmate's own untracked hook files are ignored by the dirty check bin/fm-teardown.sh:1796.

The other kinds

Scout
The worktree "is declared scratch and the report at data/<task-id>/report.md is the work product" bin/fm-teardown.sh:72-75. Without --force, a missing report refuses ("The report is the work product"), and so does a failed fm-captain-hold.sh verify, the shared unresolved-decision completion gate bin/fm-teardown.sh:3280-3292.
Secondmate
"Normal teardown refuses while their home has in-flight crewmate meta files; --force is the approved discard path". The forced path locks each descendant home's task set before enumerating it, and a retired leased home releases its durable Treehouse lease bin/fm-teardown.sh:147-163 bin/fm-teardown.sh:3264. A secondmate is never a backlog item, so no transition runs bin/fm-teardown.sh:5-6.

The order of work

The pre-cleanup sequence

Three fixes run after every safety refusal has passed and before anything destructive bin/fm-teardown.sh:225-278:

  1. Conclude the task's own parked no-mistakes run. A run left parked at a gate with no worker to answer it "sits there holding a fleet slot indefinitely (observed 2026-08-03: runs parked 7h39m …)". Teardown aborts it only when branch and code identity prove it is this task's run. Runs still executing are left alone, because they work in no-mistakes' own clone.
  2. Reap leaked processes. Any process whose current directory is this task's worktree or tasktmp gets TERM, then KILL, for example "two go test binaries … pinning CPU for hours". An lsof failure refuses rather than guessing bin/fm-teardown.sh:2092-2185.
  3. Sweep abandoned remote job workers, best effort, through bin/fm-remote-job-reap-orphans.sh.

Endpoint close must be provable

"An endpoint whose close could not do its job REFUSES before any record naming it is removed: those records are the only thing that names what survived" bin/fm-teardown.sh:8-14. --force overrides this at exactly one site, the generic close, because the worktree has already been returned by then bin/fm-teardown.sh:3062-3090. On Herdr, a refused or unconfirmed close keeps every record, and only a structured not-found proves the pane gone bin/fm-teardown.sh:3580-3585. A Herdr presentation journal "never authorizes cleanup", and teardown never calls workspace close bin/fm-teardown.sh:139-146.

Record and backlog are one step

"Removing state/<id>.meta and landing the backlog transition are one step, not two". The intended transition is first written to state/<id>.backlog-close, because the completion links (PR, report path, local-main note) live only in the record being removed. A crash between the halves is replayed at the next session start bin/fm-teardown.sh:15-29. The completion link is --report for a scout, --note "local main" for local-only, and --pr otherwise bin/fm-teardown.sh:1521-1537. A row still open as a captain call is reopened with its deliverable recorded instead of closed, and "--force does not lift the deferral" bin/fm-teardown.sh:30-43.

Refusals --force does not lift

  • Another live task's slot: "--force authorizes discarding THIS task's unlanded work, never another task's live work" bin/fm-teardown.sh:131-135.
  • An unreadable slot-owner claim. "never remove it, since an absent claim proceeds" bin/fm-teardown.sh:109-112.
  • Project-lock contention, or a slot identity that changed while locks were being taken bin/fm-teardown.sh:1055-1069.
  • A record with no single spawn_gen (use --legacy-record once the endpoint is confirmed dead) bin/fm-teardown.sh:500-520 bin/fm-teardown.sh:1074-1096.
  • An open captain call: its close becomes a reopen bin/fm-teardown.sh:38-43.
  • An owed public reply through the Relay bin/fm-teardown.sh:3295-3312.
  • A Herdr or Orca endpoint whose close cannot be proven bin/fm-teardown.sh:3073-3085.

Git index locks

A killed worker can leave an index.lock that makes treehouse return fail. "the fix is patience, not rm". Teardown retries up to 3 times, 1 second apart, and removes the lock only when it is provably stale: no lsof holder and older than 30 seconds bin/fm-teardown.sh:195-224.

After teardown

For PR-based ship tasks (not scouts, secondmates, or local-only), teardown runs fm-fleet-sync.sh on the project clone bin/fm-teardown.sh:3701-3703. The supervisor contract then asks Firstmate to "record completion, retain only the configured recent Done history, and re-evaluate queued work" AGENTS.md:404.
