Watcher poll loop

bin/fm-watch.sh is a bash process that blocks between supervisor turns, classifies every candidate event itself, absorbs the benign majority without spending a model token, and exits with one reason line the moment something needs judgment.

Read against Firstmate commit ada21f5b. Up: Supervision.

Responsibility

The watcher is deliberately one-shot: "one actionable reason closes one watcher cycle" (docs/watcher-continuity.md:3). Its header states the classification contract it keeps: in normal mode it "absorbs benign wakes and keeps blocking; it queues and exits only for actionable wakes" (bin/fm-watch.sh:2-4). The rationale is cost: "most wakes during a long crew validation are benign (a working: note or turn-end while a pipeline runs, a no-change heartbeat). Rather than wake firstmate's LLM for each, this watcher classifies every wake in bash and ABSORBS the benign majority" (bin/fm-watch.sh:247-251).

It does not decide what to do about an event. Deciding is the supervisor's job after the drain presents the durable row. It does not keep itself alive either: continuity belongs to the layer above it.

The shape of one cycle

The order of the loop body is load-bearing. Each step that can produce a wake calls wake(), which prints and exits, so a later step never runs in a cycle an earlier step closed. The code says so explicitly for checks: they are "Evaluated BEFORE the signal scan: wake() exits the cycle, so a check placed after the signal scan would be starved whenever a chatty sibling crewmate keeps producing signals" (bin/fm-watch.sh:2364-2370).

Singleton lock and refusal to double-arm

The lock is a directory-or-symlink lock from bin/fm-wake-lib.sh with dead-owner stealing serialized by a .steal mutex (bin/fm-wake-lib.sh:933-1031). When the watch lock is stolen from a dead owner, the library publishes downtime to the recovery marker before removing the stale lock (bin/fm-wake-lib.sh:1010-1016), so a crash of the previous watcher is always visible to the next one.

A live holder produces one of three outcomes (bin/fm-watch.sh:2090-2108):

  • a stale beacon beyond WATCHER_STALE_GRACE: refuse with "inspect or stop that watcher before re-arming" and exit 1;
  • no beacon at all and a lock older than the grace: refuse the same way;
  • otherwise print watcher: already running pid=N and exit 0. The arm wrapper never relies on this line; it verifies health itself (Continuity).

The grace defaults to max(300, POLL + 60) through fm_poll_derived_grace, because a healthy beacon can legitimately age up to one full poll between touches (bin/fm-watch.sh:221-229, bin/fm-wake-lib.sh:107-124).

Absorb only on positive evidence

The single rule behind every triage branch: a wake is silently absorbed only when there is positive evidence that nothing needs the supervisor. The header states it for the no-verb signal and stale path: "a wake is absorbed only when the crew shows it is still working through an actively running no-mistakes step or a backend busy signal … Every other no-verb wake surfaces, so a crew that finishes (or stops and waits) is never silently swallowed" (bin/fm-watch.sh:5-10).

The authoritative proof is crew_is_provably_working, which reads one line from bin/fm-crew-state.sh and answers working only for source run-step or pane (bin/fm-classify-lib.sh:2104-2146). The second absorb class is a declared bounded wait, covered in Wedges and declared waits. A third, opt-in proof, pane churn for bare turn-ends, exists only in homes that create config/turnend-churn-absorb (bin/fm-watch.sh:512-563), because some harnesses have no verified busy source and every turn boundary would otherwise wake the supervisor with nothing to act on.

Absorbing still records something: the suppression marker advances and a line goes to the size-capped state/.watch-triage.log, which "carries no lifecycle semantics" and is "safe to delete" (docs/watcher-continuity.md:113, AGENTS.md:157).

The pane-staleness backbone

Layer 1 of detection needs no cooperation from the worker at all: "Two consecutive identical hashes with no busy signature means the crewmate finished, is waiting, or is wedged" (bin/fm-watch.sh:2613-2617). Per recorded window, each poll:

  1. captures the last 40 lines through the backend adapter and hashes them with md5 (bin/fm-watch.sh:2639-2640);
  2. reads the busy verdict once and reuses it for the whole cycle (bin/fm-watch.sh:2648-2653);
  3. on an unchanged hash, increments .count-<key>; at two or more with a non-busy pane the stale triage runs, once per distinct hash (.stale-<key> remembers which hash was classified) (bin/fm-watch.sh:2654-2781);
  4. on a changed hash, records it and resets the count, while a busy pane that has gone BUSY_TURN_MAX_SECS without a completed turn is routed to the wedge bound (bin/fm-watch.sh:2802-2832).

A secondmate's idle pane is healthy by design, so a mate enters this path only to serve a status-declared wait's bounded recheck (bin/fm-watch.sh:2629-2638). The per-window marker key is derived in exactly one place, window_key, because "a second copy is how a future change to it silently orphans a window's markers" (bin/fm-watch.sh:405-417).

What the stale triage decides for each case (terminal status, provably working, paused, none) is on Wake kinds; the timer that follows a provably-working stale is on Wedges.

Heartbeat and its backoff

The interval is FM_HEARTBEAT × 2^streak, the streak capped at 12 and the product at FM_HEARTBEAT_MAX (defaults 600 and 7200 seconds) (bin/fm-watch.sh:2839-2843). A no-change heartbeat increments the streak; wake() increments it for a surfaced heartbeat and resets it to 0 for any other surfaced wake (bin/fm-push-transition-lib.sh:88-93). In normal mode the heartbeat surfaces only when heartbeat_scan_finds_actionable finds a captain-relevant status event past the position already surfaced — "the fail-safe backstop" for an event the per-wake path absorbed by mistake (bin/fm-watch.sh:1954-1986).

Header and code differ slightly

The header lists one heartbeat trigger, "fleet-scan backstop found an unsurfaced captain-relevant status" (bin/fm-watch.sh:113-114). The code has a second: when the scan finds nothing but the surfaced markers cannot be written, it queues and wakes a heartbeat anyway (bin/fm-watch.sh:2862-2867). This is the fail-toward-waking direction, but the header does not mention it.

Why cadences survive restarts

The watcher is relaunched after every actionable wake, so in-memory counters would never reach a threshold on a busy fleet. The check and heartbeat schedules are therefore file mtimes (.last-check, .last-heartbeat): "Check and heartbeat cadence must survive actionable exits and restarts … Persist the schedule as file mtimes instead" (bin/fm-watch.sh:1695-1704). A missing file reads as age 999999, "due immediately". Signal detection likewise compares against persisted .seen-* signatures rather than a startup timestamp, "so signals that land while no watcher is running are caught by the next one" (bin/fm-watch.sh:1706-1715).

The native event fast path

For windows on a push-capable backend (herdr), event_wait_or_sleep waits on the backend's transition stream for up to one poll instead of sleeping. It "only ever SHORTENS latency; it can never drop an escalation (the poll loop is the permanent fail-closed backstop)", and it is a short-lived subprocess of this watcher, not a second watcher (bin/fm-watch.sh:1988-1998). Secondmate endpoints are excluded, the capability probe is memoized per backend and session, and three consecutive connect failures disable the path for the rest of the process (bin/fm-watch.sh:305-316, bin/fm-watch.sh:2044-2062). An actionable transition becomes stale: <window> (herdr: agent <state> - waiting on human, escalated immediately, not via wedge timer) unless the task's last status declares a wait (bin/fm-push-transition-lib.sh:141-168).

Away mode turns the watcher one-shot

While state/.afk exists, "the daemon owns triage and this watcher queues and exits on every wake" (bin/fm-watch.sh:19-20). afk_present short-circuits the absorb branches so "the daemon's digest/injection layer" sees every wake, and the watcher "never runs the costly provably-working read" (bin/fm-watch.sh:263-265, bin/fm-watch.sh:318-322). Two exceptions keep the away window quiet: a captain-held pane is never handed over while the away-posture record exists, and a busy pane's crossed turn bound hands the daemon a plain wake once per declaration (bin/fm-watch.sh:2665-2676, bin/fm-watch.sh:1385-1430). See Away and quiet postures.

What it deliberately refuses to do

  • It never interrupts, signals, or restarts a worker: escalation is "for human inspection only - never an automatic interrupt, signal, or restart of the worker or its tool process" (bin/fm-watch.sh:75-78).
  • It never executes an unauthenticated state check; rejected paths surface as their own check: wake (bin/fm-watch.sh:108-109, bin/fm-watch.sh:2476-2481).
  • It never consumes or rewrites a secondmate's queue; "the receiving home owns acknowledgement" (bin/fm-watch.sh:726-732).
  • It never double-triages under away mode (bin/fm-watch.sh:263-265).
  • It uses no associative arrays, so it runs on stock macOS Bash 3.2 (bin/fm-watch.sh:615-618).

Failure behaviour

  • A failed queue append is fatal (fm_wake_append … || exit 1 at every call site), so the watcher never reports a wake it could not make durable. The arm wrapper turns the nonzero exit into watcher: FAILED - watcher cycle exited N without an actionable reason (bin/fm-watch-arm.sh:528-540).
  • On any exit, watcher_cleanup stops a running check's process group, removes snapshots, and, if it still owns the lock, publishes downtime to the recovery marker while releasing the lock (bin/fm-watch.sh:2198-2218).
  • wake() ignores HUP, INT, and TERM while it prints, so a signal cannot split "reason printed" from "delivery recorded" (bin/fm-push-transition-lib.sh:94-108).
  • Portable stat is chosen once per platform because the GNU/BSD fallback form "silently kills the watcher mid-cycle" under set -u (bin/fm-watch.sh:202-215).

Findings worth keeping

  • Not every check: reason is appended by the watcher. check: rearm-resurface and check: inactive-outcome are printed only; their rows already exist or are written by bin/fm-inactive-reconcile.sh. The contributions check appends its own rows under the queue lock (bin/fm-contributions.sh:283-303) and the watcher only prints its contribution-wake: lines (bin/fm-watch.sh:2419-2437, bin/fm-watch.sh:2483-2485).
  • The inactive-outcome scan is invoked every cycle (bin/fm-watch.sh:2355), while the session-start comment speaks of "the watcher's separate 900-second cadence" (bin/fm-session-start.sh:705-708). The two agree: the gate lives inside the scanner, which evaluates "at most once per FM_INACTIVE_RECONCILE_SECS (default 900 …) per home" (bin/fm-inactive-reconcile.sh:29-30), so the watcher calls it cheaply every poll.
