Durable wake queue

state/.wake-queue is the one place an actionable wake exists between the moment the watcher decides it matters and the moment the supervisor has finished handling it; a generation-bound acknowledgement is the only thing that removes a row.

Read against Firstmate commit ada21f5b. Up: Supervision. Owners: bin/fm-wake-lib.sh (append, locks, recovery marker) and bin/fm-wake-drain.sh (presentation and acknowledgement).

Why a queue at all

A reason line printed by a watcher is ephemeral: the harness might drop it, the supervisor turn might be interrupted, the session might be restarted before handling finishes. The queue makes the wake survive all three. AGENTS.md:145 describes it as "durable queued wakes retained until post-handling acknowledgement", and the drain's own header keeps two facts separate: "Keep sequence-bound row consumption independent from generation-bound episode retirement" (bin/fm-wake-drain.sh:9-10).

Append: evidence first, then the row

fm_wake_append takes state/.wake-queue.lock and calls the locked core, which does three things in a fixed order (bin/fm-wake-lib.sh:1823-1865):

  1. publish downtime to the recovery marker state/.watcher-down;
  2. increment the sequence file;
  3. append the row.

A failure at any step stops the later ones and returns nonzero, and every watcher call site treats that as fatal (|| exit 1). Callers that must commit another record atomically with the append hold the lock themselves and call fm_wake_append_locked, because "holding this lock excludes the drain's acknowledgement, which deletes consumed rows under the same lock" (bin/fm-wake-lib.sh:1831-1836). The contributions check is one such caller (bin/fm-contributions.sh:291-296).

Producers other than the watcher: bin/fm-contributions.sh, bin/fm-inbox.sh, bin/fm-inactive-reconcile.sh, bin/fm-mail.sh, bin/fm-procevent.sh, bin/fm-merge-outcome-lib.sh, and bin/fm-startup-network.sh all call the same append.

Presentation: fm-wake-drain.sh

With no arguments the drain presents; with --ack-through SEQ --recovery-generation G (exactly four arguments) it acknowledges (bin/fm-wake-drain.sh:196-208). A presentation does, in order:

  1. Take the queue lock, bounded. A live holder after FM_STATUS_PRESENTATION_LOCK_TIMEOUT (default 10 s) prints WAKE DRAIN SKIPPED: queue lock remains held by live pid … and exits 0 before any claim or mutation; acknowledgement keeps a blocking acquire (bin/fm-wake-drain.sh:627-641).
  2. Repair. Reclaim a branch grant whose owner process is gone, and, for main only, retire structurally unusable rows (fewer than five fields or a non-numeric sequence), printing up to 20 of them verbatim "because the queue was their only durable record" (bin/fm-wake-drain.sh:73-117, docs/watcher-continuity.md:85-86).
  3. Claim. Main claims every row a live branch grant does not reserve and records the set in state/.main-eligible-rows (bin/fm-wake-drain.sh:142-157). If nothing is left for main while a grant holds rows, it prints one WAKE ROWS HELD BY SUPERVISION BRANCH line instead of exiting silently (bin/fm-wake-drain.sh:788-805).
  4. Open handling. Move the recovery marker into its handling phase for the current generation (bin/fm-wake-drain.sh:807-828).
  5. Dedupe and print. Rows are deduplicated by kind and key, keeping the latest line in first-seen order; all heartbeats collapse to one (bin/fm-wake-lib.sh:1982-2002). The cutoff is the highest presented sequence (bin/fm-wake-drain.sh:830-851).
  6. Print the acknowledgement contract on stderr: WAKE_ACK_REQUIRED: after handling completes run bin/fm-wake-drain.sh --ack-through SEQ --recovery-generation G (bin/fm-wake-drain.sh:858-861).
  7. Status presentation, under its own bounded lock: annotations for every unread status line of each presented signal, then four sections (bin/fm-wake-drain.sh:551-610).
  8. Liveness assertion. Run the pull guard, whose failure never changes the drain's exit status (bin/fm-wake-drain.sh:212-225).

Sections are prepared into a file first and their presentation receipt is committed only after the bytes reach stdout: "If the consumer closes or fails, leave the receipt behind so the next drain can recover the presentation" (bin/fm-wake-drain.sh:566-577). The supervisor treats OPEN DECISIONS as actionable even with no queued wake (AGENTS.md:430). The decision fold itself belongs to Backlog and decisions.

Acknowledgement, and why it comes after handling

The rule, in the supervisor's own contract: "After handling all emitted wakes and reconciling the OPEN DECISIONS and UNREAD STATUS sections, run the exact generation-bound --ack-through command printed as WAKE_ACK_REQUIRED; interruption before that acknowledgement deliberately leaves the work durable for idempotent re-handling" (AGENTS.md:433). Every harness protocol repeats it as step 1 (for example docs/supervision-protocols/claude.md:5-6).

The reasoning follows from the alternatives. Acknowledging at presentation would make presentation and loss the same event: a turn that crashed, was interrupted, or was replaced after printing but before acting would lose the wake with no trace. Acknowledging after handling means the worst case is handling twice, and handling is required to be idempotent. The away daemon follows the same order in bash: it classifies every row, and "acknowledges only after routing completes", retaining the rows if classification fails (bin/fm-supervise-daemon.sh:35-40, bin/fm-supervise-daemon.sh:1506-1516).

What --ack-through SEQ --recovery-generation G does (bin/fm-wake-drain.sh:646-761):

  1. Blocking queue lock; re-claim so rows that arrived after presentation but before this acknowledgement are covered by main's "original whole-cutoff acknowledgement contract".
  2. Collect inactive-outcome fingerprints at or below the cutoff, release the lock, record their receipts, re-take the lock.
  3. Delete only rows that are this actor's claim and at or below SEQ; commit secondmate stall receipts.
  4. If the queue is now empty, retire the episode: the generation must match, otherwise the result is "moved".
  5. Report. Consuming nothing while a presented row above the cutoff waits prints the exact command for the current row, "so the remedy is never 'drain again'"; a moved generation says to re-drain and use the new command.

Row consumption and episode retirement are separable on purpose: "A generation mismatch therefore does not block consumption of rows through that sequence" (docs/watcher-continuity.md:62-63).

Recovery episodes: state/.watcher-down

The marker holds one line with the grammar <pending|announced|acked>:<handling|downtime>:<generation> (bin/fm-wake-lib.sh:627-645). A generation is minted as <pid>.<epoch>.<random> and written through an atomic temp-and-rename (bin/fm-wake-lib.sh:651-663). AGENTS.md:146 calls it "private generation-bound recovery state coupling watcher downtime, durable wake presentation, and post-handling acknowledgement; never touch".

The contract, in the owner's words

docs/watcher-continuity.md:55-67 owns it. The load-bearing sentences:

  • "An unacknowledged downtime generation is announced at most once: the first recovery marks that generation announced, and later arms wait until a new down stretch mints a new generation."
  • "Every watcher close and every durable queue append publishes downtime, so a downtime republication of any pending episode reuses its generation instead of minting a new one … That reuse keeps a watcher close inside the handling window from orphaning the acknowledgement already presented."
  • "A concurrently appended wake has a higher sequence, remains queued, and keeps the episode pending for presentation."
A consequence the source implies but does not state

A non-successor watcher re-runs arm-check at the top of every cycle (bin/fm-watch.sh:2286-2292). A row appended by another producer (an inbox note, a procevent runner, the contributions check) while that watcher is blocking publishes downtime and flips an acked marker to pending (bin/fm-wake-lib.sh:1852). On the next cycle arm-check therefore returns recover and the watcher wakes with check: rearm-resurface. Read this way, the recovery marker is also how foreign producers' rows reach the supervisor between turns. The owning documents describe the marker only in terms of recovery episodes, so this is a reading of the code, not a stated purpose.

Handling successors, the watchers that Pi, omp, and OpenCode start before delivering a wake, skip both reopen and resurface: "Re-announcing from this cycle is what turned a lost handshake into an unbounded recovery loop" (bin/fm-watch.sh:2280-2285).

Per-actor claims

On Pi, two actors may drain: main and the supervision branch. The actor is FM_SUPERVISION_ACTOR, unset or main everywhere except inside the branch's own bash calls, where the extension injects branch "deterministically … never agent memory" (docs/watcher-continuity.md:71). A branch grant lives in state/.branch-eligible-rows, bound to the live branch process and extension generation in state/.branch-eligible-owner (format fm-branch-eligible-owner-v1, pid, identity, generation) (bin/fm-wake-lib.sh:2016-2038). A branch drain without a valid snapshot refuses loudly because that is "a wiring bug, never 'nothing eligible'" (bin/fm-wake-drain.sh:170-181). The pull guard counts only rows the calling actor can itself present or retire (bin/fm-wake-lib.sh:2046-2082). Routing rules are on Pi supervision branch.

Failure behaviour

  • An unreadable queue is never reported as empty: fm_wake_actor_pending_count prints 1 when awk fails, "so callers still raise the alarm on a queue nobody can prove is drained" (bin/fm-wake-lib.sh:2075-2081).
  • A retirement that cannot be written "is reported and never fails the drain" (docs/watcher-continuity.md:86).
  • Durable wakes with an invalid marker stop the drain with an error rather than presenting them without an episode (bin/fm-wake-drain.sh:809-813); a legacy queue with no marker is adopted by publishing one (bin/fm-wake-drain.sh:814-817).
  • A lock-refused, read-only session start leaves the queue untouched and only counts it (bin/fm-session-start.sh:721-726).
