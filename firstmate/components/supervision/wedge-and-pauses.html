Wedges and declared waits

A pane that looks busy but never moves might be wedged; a pane that is idle on purpose must not be. The wedge escalation ladder surfaces the first case on a fixed schedule for human inspection, and the declared-wait absorb keeps the second off that ladder while still rechecking it on a long, finite cadence.

Read against Firstmate commit ada21f5b. Up: Supervision. All behaviour below lives in bin/fm-watch.sh; the prose contract is docs/architecture.md:30-60.

The wedge escalation ladder

A stale pane whose crew is provably working (an active no-mistakes step or a busy verdict) is absorbed, but a timer starts in state/.stale-since-<key> "so a genuinely frozen run still escalates past STALE_ESCALATE_SECS" (bin/fm-watch.sh:2738-2758). On every later poll of the same hash, wedge_timer_check repairs a missing or corrupt timer ("self-heals a watcher restart between recording the hash and recording the timer") or, once the timer reaches FM_STALE_ESCALATE_SECS (default 240), runs the at-threshold branch (bin/fm-watch.sh:1229-1286).

demand-deep-inspection

Without it, "a pane that keeps re-wedging on the SAME stale hash - each escalation gets absorbed again as 'still validating' one poll later, since the hash never changes - can otherwise repeat forever with no signal that this is no longer a one-off" (bin/fm-watch.sh:867-877). At FM_WEDGE_DEMAND_INSPECT_COUNT (default 3) the reason becomes stale: <w> (idle Ns, possible wedge, escalation n, demand-deep-inspection: same pane has wedge-escalated n times in a row - do not re-absorb on the run-step/pane state alone) (bin/fm-watch.sh:1275-1278). The supervisor's duty changes with it: "a deep-inspection reason also requires current-state and validation-log inspection" (AGENTS.md:440).

After an escalation the timer file is removed (bin/fm-watch.sh:1279-1282). On the ordinary non-terminal path the next poll of the same hash repairs the timer, so a pane frozen on one hash escalates about once per STALE_ESCALATE_SECS with a rising count. On the path where an active run overrode a captain-relevant status line, the next poll of the same hash finds no timer and does nothing further until the hash changes (bin/fm-watch.sh:2725-2734).

Inspection only, never an interrupt

Every form of this escalation is "for human inspection only - never an automatic interrupt, signal, or restart of the worker or its tool process" (bin/fm-watch.sh:75-78). Recovery is the supervisor's decision through the stuck-crewmate-recovery skill (AGENTS.md:588).

The three deliberate deferrals

Each is a deferral, not a cancellation: the idle timer restarts so the next window probes again, and the escalation counter "is neither advanced (this is not an escalation) nor reset (a later genuine escalation must still carry the demand-deep-inspection history it had already earned)" (bin/fm-watch.sh:904-917). Because the timer restarts, "a wait that ends is escalating again within one STALE_ESCALATE_SECS, which is why the worst-case detection time for a pane that stops waiting does not move" (bin/fm-watch.sh:1057-1062).

1 · Wait evidence

wedge_wait_evidence answers "is this quiet a bounded wait?" from two independent records (bin/fm-watch.sh:956-1055):

  • The worker's own last status line: a verified captain-held transfer, or a paused: declaration whose optional until time has not passed. "The declaration is what the worker said about its OWN silence, so it outranks a liveness verdict that only says something is running."
  • Only in a home with config/wedge-defer-parked-gate: a no-mistakes gate whose findings table owes an ask-user answer and an open needs-decision keyed nm-<run>-<step> for that same run. Both signals are needed: the gate says a human owes an answer, and the open decision proves "firstmate was actually told about THIS gate and has not answered yet".

The evidence travels as a five-field record — kind, subject, whom, action, age anchor — joined with the ASCII unit separator rather than TAB, because "consecutive tabs collapse under read, so a record with an empty middle field would not fail to parse, it would SHIFT every later field left" (bin/fm-watch.sh:930-954). wedge_defer_wait refuses a malformed record and escalates instead, because "deferring is what takes the ladder away" (bin/fm-watch.sh:1100-1121). The recheck names who owes the answer: an external dependency for paused:, the captain for a hold, firstmate itself for a parked gate (docs/architecture.md:37-38).

2 · Worktree writes

"The pane and the run step both say nothing is happening; the worktree says otherwise, and files appearing in it is the harder signal to fake" (bin/fm-watch.sh:904-908). crew_worktree_written_since walks the task's recorded worktree for a file newer than the quiet window, pruned (FM_WORKTREE_WRITE_PRUNE), depth-bounded (FM_WORKTREE_WRITE_MAXDEPTH, 6), and time-bounded (FM_WORKTREE_WRITE_TIMEOUT, 10 s) (bin/fm-classify-lib.sh:2215-2263). A .writing-since-<key> marker ages the whole deferral chain so it still resurfaces once per PAUSE_RESURFACE_SECS, so "a crew whose worktree churns without real progress cannot stay invisible". A secondmate's worktree is never probed, because its own supervision keeps writing inside it (docs/architecture.md:51).

3 · Dead record

"Is there still an agent here to BE wedged?" Two finished lanes on one live fleet once reached "226 and 203 consecutive escalations, roughly one every FM_STALE_ESCALATE_SECS, which is what drowns the alarms that matter" (docs/architecture.md:52). wedge_dead_record reads fm_backend_agent_state once; only dead (endpoint present, no agent) and missing (endpoint gone) license it, and every other verdict — alive, ambiguous, unreadable, unverified, a failed read — "keeps the unchanged escalation schedule, reason and count" (bin/fm-watch.sh:1162-1196). The report is sent once per verdict and agent incarnation (the busy gen, or the pane hash when no gen is readable), appended before its marker so a failed append cannot be absorbed on retry (bin/fm-watch.sh:1197-1227). It "decides nothing about the record's fate, because such a lane routinely still holds unlanded work that teardown is right to refuse" (docs/architecture.md:55).

The busy-pane bound

A busy pane would otherwise be unconditional proof of liveness. BUSY_TURN_MAX_SECS (default 3600) bounds it: past the bound with no completed turn or native progress, busy_turn_bound_check hands the pane to the same wedge timer, with the same reason, count, and deep-inspection marker — unless the crew declared the wait itself, which takes the pause cadence (bin/fm-watch.sh:1363-1430). Under daemon-backed away mode a declared wait there is handed to the daemon as a plain stale: <window> once per declaration, keyed on the status-log signature rather than the pane hash, because "a busy pane's harness footer ticks on every capture, so a hash-keyed one-shot would re-fire on every poll" (bin/fm-watch.sh:1389-1424).

Declared waits and why they are absorbed

Two status verbs let a worker account for its own silence (bin/fm-classify-lib.sh:231-266):

paused: <why>
"A declared paused: event means a bounded external wait expected to clear on its own, while blocked: means firstmate action is needed" (AGENTS.md:435). The generated brief tells workers to use it "ONLY when you are deliberately idling on a known external wait"; firstmate "then leaves your idle pane alone and rechecks it on a long cadence instead of treating it as a possible wedge" (bin/fm-brief.sh:438). An optional until <YYYY-MM-DDTHH:MM[:SS]Z> makes the wait condition-aware; a malformed time "falls back to the cadence rather than silencing the wait" (bin/fm-classify-lib.sh:268-285).
captain-held
A verified transfer of the work to the captain. It gets the same cadence but a different recheck wording, because "they block on DIFFERENT humans" (bin/fm-classify-lib.sh:244-255).

Why absorb rather than escalate: "A crew that declared a pause is idling on a known external wait, so its stale pane is absorbed rather than wedge-escalated", while the recheck is "far longer than the wedge threshold, but finite so a forgotten wait cannot rot invisibly" (bin/fm-watch.sh:289-299). Without the absorb, a worker waiting on an upstream release would climb the ladder every four minutes for hours.

The recheck cadence

  • Length. FM_PAUSE_RESURFACE_SECS, default 14400 s (four hours) (bin/fm-classify-lib.sh:106, bin/fm-watch.sh:300).
  • Anchor. The wait is aged from the status file's mtime, "so a churny idle pane (a ticking clock, a token counter) cannot keep resetting the cadence the way a hash-tied timer would" (bin/fm-watch.sh:1302-1311).
  • Throttle. resurface_absorbed fires once per window per cadence, scoped to the declaration's status-log signature so a new declaration starts its own window (bin/fm-watch.sh:879-902, bin/fm-watch.sh:1550-1556).
  • until. Not rechecked before the declared time; rechecked once as soon as it passes; a declared time beyond the cadence "cannot extend the ordinary recheck cadence" (bin/fm-watch.sh:14-18, bin/fm-watch.sh:1340-1354).
  • Away. While the away-posture record exists, "an item held for the captain is never rechecked at all, in either posture": "there is nobody to answer it, the return brief lists it, and a recheck would only churn (the 2026-09-07 away-window audit counted hourly rechecks of captain-held items as pure noise)" (bin/fm-watch.sh:324-337). External waits keep their cadence.

Which crews earn the cadence

pause_state_class reconciles the declaration with authoritative crew state (bin/fm-watch.sh:1455-1513):

  • a crew whose current state is working (an active run started after the pause) reports working and takes the wedge timer — run-step precedence wins over the line;
  • an ordinary crew whose agent the backend confidently reports dead is admitted as paused;
  • a live or ambiguously read agent reports none, so "a worker genuinely waiting on a decision is never silenced" — its first sight surfaces, and later sights are held to the cadence by surface_nonterminal_stale (bin/fm-watch.sh:1612-1693);
  • a secondmate earns the cadence on its declaration alone, "because its endpoint liveness is deliberately never read" (bin/fm-watch.sh:291-295).

A captain hold recorded only in the backlog (the worker's last line is still done) is a second record of a wait; captain_call_stale_bound reads it through bin/fm-captain-hold.sh open so the alarm does not "re-fire for the captain's whole thinking time", binding the throttle to the call's own identity so a released-then-reheld call is a new first sight (bin/fm-watch.sh:1515-1610). Hold records are owned by Backlog and decisions.

The herdr push path absorbs an immediate transition for a declared wait too, "leav[ing] the bounded re-surface to the watcher's own pause cadence" (bin/fm-push-transition-lib.sh:149-157).

Secondmate wake-loop stalls

A related liveness check that is not a pane wedge: "Agent endpoint liveness and queue-consumption liveness are separate" (docs/architecture.md:65). The parent times how long the oldest actionable row in a local mate's queue has not changed, ignores rows that declare an external pause, and emits one check: secondmate wake-loop stalled per no-progress episode, with receipts that survive watcher and handling crashes (bin/fm-watch.sh:726-865).

Open questions

Throttle scope for churning parked gates

docs/architecture.md:46-47 records "a known bound: the recheck throttle is scoped to the pane hash", so a parked gate whose display churns is rechecked once per idle window rather than on the long cadence. The code for the wait deferral uses a per-window throttle file, .waiting-resurfaced-<key>, that clear_stale_hash_tracking removes whenever per-hash state resets (bin/fm-watch.sh:1442-1447). The two are consistent, but whether this residual is still intended after the declaration-scoped throttles were added for paused: is not stated.
