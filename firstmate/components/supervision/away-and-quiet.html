Away and quiet postures

When the captain steps away (/afk) or asks for fewer interruptions while staying (/quiet), supervision changes owner: a bash sub-supervisor daemon wraps the watcher, handles the routine majority itself, and injects only batched, distilled escalations into the supervisor's pane.

Read against Firstmate commit ada21f5b. Up: Supervision. Scripts: bin/fm-supervise-daemon.sh, bin/fm-afk-contract.sh, bin/fm-afk-launch.sh, bin/fm-afk-start.sh, bin/fm-afk-return.sh. The /afk and /quiet skills themselves belong to Prompts and skills.

The mode is read by exactly one owner, fm_afk_mode: only an exact first line quiet reads as quiet, and every other content — missing, empty, unreadable, or the legacy bare epoch — reads as away, "the safe default" (bin/fm-wake-lib.sh:348-368). The record is read wherever captain-held rechecks are decided: while it exists, an item held for the captain is never rechecked, in either supervision shape (bin/fm-watch.sh:324-330).

"ENTRY IS THE GO. /afk itself is the captain's go: enter writes the record in the same turn, before any other work, and never waits for a further human response, because the captain who typed /afk may not look at the screen again" (bin/fm-afk-contract.sh:14-18). "NO PARSER, TOKENIZER, CLASSIFIER, OR GRAMMAR READS THE WORDS HERE, BY THE CAPTAIN'S MANDATE"; what stays mechanical is a merge green at its live head, synchronous merges only, the spend cap, and the never-set, and "destructive, irreversible, and security-sensitive actions are never pre-authorizable whatever the words say" (bin/fm-afk-contract.sh:20-33).

The sub-supervisor daemon

Contract

The daemon "SELF-HANDLES the routine majority in bash (no firstmate turn) or ESCALATES a batched, distilled digest to the supervisor pane on captain-relevant events plus bounded declared-wait rechecks"; routine wakes "cost zero firstmate context" (bin/fm-supervise-daemon.sh:2-13). Its reliability model (bin/fm-supervise-daemon.sh:34-60):

  • Nothing is lost: the watcher "enqueues every wake to state/.wake-queue BEFORE advancing its suppression markers, so a crash/restart/missed injection is recovered on the next fm-wake-drain.sh"; the daemon acknowledges "only after routing completes".
  • Fail-safe-to-escalate: "any wake the classifier cannot confidently mark routine is escalated".
  • Bounded wedge latency: a stale pane without a declared wait escalates after STALE_ESCALATE_SECS, "rechecked once"; declared waits get PAUSE_RESURFACE_SECS, and captain-held transfers are not rechecked while the posture record exists.
  • Max-defer alarm: a digest undelivered past FM_MAX_DEFER_SECS (300) retries a flush, writes state/.subsuper-inject-wedged, and fires the configured active alert, rate-limited to once per window (bin/fm-supervise-daemon.sh:1036-1054, docs/wedge-alarm.md:3-6).
  • Catch-all: every HEARTBEAT_SCAN_SECS the daemon greps every status log for a captain-relevant line the per-wake classifier might have missed.

Classification reuses the same library as the watcher: "The SAME library backs the always-on watcher's triage, so the captain-relevant verb set and the classification predicates have exactly one definition" (bin/fm-supervise-daemon.sh:173-178). A decision-owned row arrives with payload needs-decision: and is classified as a signal, so its suppression markers commit and the digest names the decision instead of reporting an unknown wake (bin/fm-supervise-daemon.sh:1332-1336).

Sharing one input channel with the captain

The daemon types into the same pane the captain types into. Every injection is built by bin/fm-operational-input.sh as the away-supervisor kind after the U+2063 FIRSTMATE_OP: prefix, which "A human cannot type … from a normal keyboard at the start of a message" (bin/fm-supervise-daemon.sh:23-32). An unmarked message means the captain is back; should_exit_afk keeps away mode only for a marked message or a /afk command and biases everything else toward exit, since "A false exit is self-correcting" (bin/fm-supervise-daemon.sh:281-296). Injection defers while the supervisor pane is busy and "on anything that is not affirmatively 'empty'", because typing an escalation into a shell "could execute it" (bin/fm-supervise-daemon.sh:1268-1284).

Crash and pane guards

A missing supervisor pane backs off without losing work; a watcher that exits nonzero or with no reason is a crash, and a tight crash loop backs off; a non-wake stdout line such as watcher: already running "is NOT a wake" and idles instead of flooding the buffer (bin/fm-supervise-daemon.sh:1705-1760, bin/fm-supervise-daemon.sh:1316-1329). Supervisor backends are tmux and herdr only; zellij, orca, and cmux are refused at startup (bin/fm-supervise-daemon.sh:75-91).

Who owns supervision while away

  • The watcher turns one-shot and never absorbs (Watcher).
  • The Claude auto-arm exits 0 and "NEVER rewake[s] the primary", and re-checks at translation time (bin/fm-claude-stop-autoarm.sh:22-24, bin/fm-claude-stop-autoarm.sh:279-285).
  • The turn-end guard accepts a live, identity-matched daemon with a fresh beacon in place of a watcher (Turn-end guards).
  • The model: "While state/.afk exists, the daemon owns supervision; do not arm a separate watcher" (AGENTS.md:468).
  • On Pi the daemon is never launched: start refuses on Pi and pi-signed, and "the ordinary supervision session keeps running in both postures" with main parked while the branch takes every safe row (bin/fm-afk-launch.sh:17-22, AGENTS.md:469). See Pi supervision branch.

Entry and the daemon's terminal

bin/fm-afk-launch.sh owns entry and exit. Harnesses with a native tracked background tool (Claude, Grok) run bin/fm-afk-start.sh directly; a harness without one needs a terminal manufactured for it, and splitting the captain's pane "visibly shrinks it", so the launcher creates a non-visible herdr tab or detached tmux session and passes the captain pane in as FM_SUPERVISOR_TARGET, never using shell & (bin/fm-afk-launch.sh:26-40, bin/fm-afk-start.sh:20-32). stop "SIGTERM[s] the daemon so its cleanup flushes WHILE state/.afk is still present", then clears the flag, then archives the record last (bin/fm-afk-launch.sh:58-64).

Return

bin/fm-afk-return.sh renders the return brief "from durable records, never from conversation memory", in a fixed order: supervisor health across the away window, the captain's away words verbatim and every action taken under them, what waits on the captain, what failed, landed work still owing teardown, what was handled, and cost; "The health snapshot is taken BEFORE the daemon shutdown so the shutdown itself cannot read as a gap" (bin/fm-afk-return.sh:14-33). A durable catch-up gate, state/.afk-return-catchup, is written before shutdown "so a crash between stopping, wake presentation, and blocker handling fails closed", and every open blocked: must be remediated and closed before ordinary captain requests proceed (bin/fm-afk-return.sh:35-58).

Quiet mode

/quiet is "the same token-saving daemon tradeoff as /afk, made explicit for a captain who is staying, watching the session, and does not want to exit the mode just by chatting" (.agents/skills/quiet/SKILL.md:13-16). It sets the same flag with first line quiet (FM_AFK_MODE=quiet); "Every mechanism below … is owned once by the afk skill and is IDENTICAL in quiet mode"; only an explicit /quiet off exits it, through the same unchanged bin/fm-afk-return.sh. It is "presentation only": decisions, failures, credentials, and review-ready work escalate every time (.agents/skills/quiet/SKILL.md:18-78). A refresh without a mode preserves the on-disk mode, which "keeps a refresh from silently flipping a captain's quiet mode back to away underneath them" (bin/fm-afk-start.sh:117-128).

Both postures change "how aggressively firstmate surfaces things, never who approves what" (.agents/skills/quiet/SKILL.md:64-67); the Pi branch's relocation of standing authority under the away record is the one place authority moves, and only through guarded scripts (Pi supervision branch).

Findings

A stale writer comment

afk_enter in the daemon writes only an epoch into state/.afk and says it is "Called by the /afk skill (enter)" (bin/fm-supervise-daemon.sh:269-275). No script under bin/ or .agents/ calls it; the live writer is fm_afk_flag_write, which writes the mode line and then the epoch (bin/fm-afk-start.sh:113-135). An epoch-only file still reads as away through fm_afk_mode, so the stale helper is harmless, but its comment no longer describes the entry path.
