Wake kinds and triage

Every actionable event reaches the supervisor as exactly one of four kinds — signal, stale, check, heartbeat — and each kind has its own producers, its own absorb rules in the watcher, and its own handling duty for the supervisor.

Read against Firstmate commit ada21f5b. Up: Supervision. Record format: Durable wake queue.

A closed set of four

The queue refuses any other kind: fm_wake_append_locked accepts only signal|stale|check|heartbeat and returns 2 otherwise (bin/fm-wake-lib.sh:1840-1843). The arm wrapper, the Claude auto-arm, and the Codex checkpoint all recognise an actionable close by the same leading-token pattern, ^(signal:|stale:|check:|heartbeat($|:)) (bin/fm-watch-arm.sh:353-368, bin/fm-claude-stop-autoarm.sh:289, bin/fm-watch-checkpoint.sh:91). Anything else on the watcher's stdout, such as watcher: already running, is not a wake.

A status line is "a wake event, not current state"; before acting on an old decision, blocker, or pause, the supervisor must use bin/fm-crew-state.sh (AGENTS.md:434-435).

signal

Producers

  • Workers append lines to state/<id>.status (grammar owned by Communication).
  • Harness turn-end hooks touch state/<id>.turn-ended; on Claude the worker's Stop hook runs touch …turn-ended before applying the idle busy event (bin/fm-spawn.sh:4088). These markers "remain wake NOTIFICATIONS owned by the watcher, not current-state truth" (bin/fm-busy-lib.sh:10-12).

Detection

scan_signals is a pure read that prints one line per file whose signature differs from its .seen-* marker: status files use a signature that includes readability, turn-ended markers use size and mtime (bin/fm-watch.sh:1706-1732, bin/fm-wake-lib.sh:2094-2104). On the first change the watcher sleeps SIGNAL_GRACE and rescans, so a status write and the same turn's turn-end become one wake (bin/fm-watch.sh:2488-2496).

Triage

Three details carry the correctness:

  • Span, not last line. signal_files_actionable classifies every byte appended since the classified offset in the .seen-* marker, so a working: note landing during the grace window cannot hide the needs-decision, blocked, failed, or done that arrived just before it (bin/fm-watch.sh:1883-1932).
  • Decision-owned payload. A file whose new span carries a decision-owned class is queued with payload needs-decision:<files> instead of signal:<files>. The reason line stays byte-identical; only the row payload changes, and two readers branch on it: the Pi branch dispatcher, which keeps such rows on main, and the away daemon (bin/fm-watch.sh:2539-2556).
  • Unreadable is actionable. A span that cannot be classified surfaces, commits no classified position, and so is classified again once readable; the reported signature still advances, which "bounds an unreadable log to one report per distinct file state" (bin/fm-watch.sh:1914-1921, bin/fm-watch.sh:2560-2564).

A secondmate's .status signal is never absorbed as provably working, because "that stream is the mate's routed-reply channel, so every append is parent-directed content" (bin/fm-classify-lib.sh:2296-2303).

stale

Producers

  • The pane-staleness backbone, for a pane whose hash is unchanged for two polls and which is not busy (bin/fm-watch.sh:2654-2781). Reason: stale: <window>.
  • The wedge timer, for a provably-working stale idle past STALE_ESCALATE_SECS: stale: <window> (idle Ns, possible wedge, escalation N), gaining demand-deep-inspection at the third consecutive escalation (bin/fm-watch.sh:1273-1283). Details on Wedges and declared waits.
  • Deferral rechecks, which reuse the stale kind so they flow through the same handling: declared-wait, captain-held, worktree-write, and dead-record reports (bin/fm-watch.sh:892-1227).
  • The herdr push path: stale: <window> (herdr: agent <to> - waiting on human, escalated immediately, not via wedge timer) (bin/fm-push-transition-lib.sh:163).
  • The steering-inbox ladder, when a firstmate instruction stays unacknowledged after its doorbell budget, when its bookkeeping is unwritable, or when the worker's agent is dead or missing (bin/fm-watch.sh:419-510). The ladder policy is owned by bin/fm-task-inbox-lib.sh (Communication).

Triage of a first-sight stale hash

The terminal branch exists because of a real incident class. A crew's status log gets no new entry once firstmate hands it to a no-mistakes validation, so a pre-validation done: line would otherwise re-surface the crew as stale "every few minutes despite an actively-running pipeline" — the "Root cause of the 2026-07 herdr false-surface incidents" (bin/fm-watch.sh:2677-2691). A provably-working verdict therefore outranks even a captain-relevant log line.

The non-terminal none branch is deliberately loud: pause_state_class "answers none for a still-LIVE agent even under a declared wait, so a worker genuinely waiting on a decision is never silenced" — but its repeats are bounded to the pause cadence, keyed to the declaration and not to the pane hash, because an idle parked pane keeps ticking (bin/fm-watch.sh:1612-1630).

check

A check is any wake that is not about a worker's own pane or status stream. Every check: reason is actionable; the watcher does not absorb check output (bin/fm-watch.sh:86).

A check-kind row is main-owned on the Pi branch while attended, "so it is never part of a branch claim and never defers one" (docs/watcher-continuity.md:92).

heartbeat

The only kind with no single subject. It is a time-based backstop run inside the watcher on a doubling interval (Watcher). In normal mode it surfaces only when heartbeat_scan_finds_actionable sees a captain-relevant event past the per-task .hb-surfaced-* offset; "Because every captain-relevant signal/stale already marks itself surfaced when it wakes firstmate, this normally finds nothing and the heartbeat is absorbed" (bin/fm-watch.sh:1954-1963). It enqueues first and marks second, preserving enqueue-before-suppress (bin/fm-watch.sh:2853-2861). Under away mode every heartbeat is queued, because the daemon runs its own catch-all scan (bin/fm-watch.sh:2849-2852). At presentation all heartbeat rows collapse to one (bin/fm-wake-lib.sh:1982-2002).

A heartbeat demands a whole-fleet review, and the Pi branch has its own all-or-nothing rule for taking one (Pi supervision branch).
