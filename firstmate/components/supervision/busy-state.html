Busy state and turn ends

The semantic busy-state contract answers one question for the watcher — is this worker provably inside a turn right now? — and it answers unknown rather than idle whenever it cannot prove the answer.

Read against Firstmate commit ada21f5b. Up: Supervision. Owners: bin/fm-busy-lib.sh (the one owner of the contract) and bin/fm-busy-event.sh (its only writer).

What problem it solves

A pane that has not changed for two polls might be a finished worker, a worker waiting for a human, or a worker inside a long silent tool call. The watcher must not wake the supervisor for the third case, and must never swallow the first two. Earlier designs guessed from rendered text. The contract's design source, "the captain-approved semantic busy-state redesign (2026-07-28)", replaced that: "each harness adapter reports turn lifecycle through a machine-readable semantic source it owns, classification always exposes which source produced it, and missing, malformed, stale, unsupported, or unverified semantic data is UNKNOWN - never idle" (bin/fm-busy-lib.sh:4-12).

Endpoint death is "the only process-level override and yields dead, never busy". Child processes, CPU, sleep state, marker mtimes, and "the old global UI-regex OR are not state signals" (bin/fm-busy-lib.sh:8-11).

Record and incarnation (Level 4)

state/<id>.busy-state is exactly one line, atomically replaced (bin/fm-busy-lib.sh:14-17):

v1 gen=<token> seq=<uint> state=<busy|idle|unknown> source=<token> event=<token> ts=<epoch>

state/<id>.busy-gen holds one token minted when the task's busy wiring is armed. "Every event must present the current gen; an event or record carrying any other gen is a stale incarnation and is rejected (written events) or classified unknown (read records). seq is a strictly increasing integer per gen, advanced under the writer's lock, so an out-of-order apply can never regress a newer record" (bin/fm-busy-lib.sh:19-25). The gen is also what identifies an agent incarnation elsewhere: the wedge ladder's dead-record marker keys on it so a relaunched agent's own later death is reported again (bin/fm-watch.sh:1183-1195).

Sources: bin/fm-busy-event.sh:6-38, bin/fm-spawn.sh:4213-4223. Exit 1 is a refusal (stale gen, unarmed task, lock timeout), and "Adapter hook command lines append || true so a refusal never breaks the harness's own lifecycle" (bin/fm-busy-event.sh:36-38).

Trusted sources per harness

A record classifies only if its source is trusted for the task's recorded harness, "so one adapter's writer can never classify another adapter" (bin/fm-busy-lib.sh:27-47). fm_busy_sources_for_harness maps claude* to claude-hook, opencode* to opencode-plugin, gemini* to gemini-hook, pi|pi-signed to pi-ext, omp to omp-ext, and appends the firstmate-owned fm-spawn fm-interrupt fm-recovery; Codex and Kimi trust nothing until a verification gate opens, and Grok and muse trust nothing because they have no writer (bin/fm-busy-lib.sh:213-240). Codex classifies unknown codex-unverified because neither its app-server lifecycle nor its hooks were observable on codex-cli 0.145.0 (bin/fm-busy-lib.sh:153-183).

Classification precedence

The launch-prompt exception exists because a launch whose record never advanced past the seed "is indistinguishable, from the record alone, between 'still reading its brief' and 'parked on an interactive prompt the harness never gets past without a human'", which would otherwise read as busy for a full hour (bin/fm-busy-lib.sh:74-92).

Turn-ended markers are notifications, not state

Two different files come out of the same hook. On a Claude worker the Stop hook runs touch state/<id>.turn-ended and then applies idle … --event stop (bin/fm-spawn.sh:4078-4091). On a Pi worker turn_end touches the marker and agent_settled applies idle (bin/fm-spawn.sh:4207-4212). The marker's only job is to make the watcher's signal scan fire. The contract is explicit: "state/<id>.turn-ended files remain wake NOTIFICATIONS owned by the watcher, not current-state truth" (bin/fm-busy-lib.sh:11-12). A bare turn-end is therefore a no-verb signal that surfaces unless the crew is provably working (signal triage).

Claude fires no hook for a manual interrupt, so "fm-control preserves the adapter-owned state, while the legacy fm-send --key Escape path records idle/fm-interrupt" (bin/fm-spawn.sh:4078-4084).

How the watcher uses it

window_is_busy
Classifies through the task's metadata and returns 0 only for an exact busy verdict; "idle, unknown, and dead all return 1, so a converted adapter whose semantic state is missing, malformed, stale, or unverified is treated as not-provably-working and surfaces rather than being absorbed" (bin/fm-watch.sh:343-363). It is read once per window per poll and reused (bin/fm-watch.sh:2648-2653).
crew_is_provably_working
The authoritative proof for absorbing a signal or a stale: bin/fm-crew-state.sh reports working with source run-step (an active no-mistakes step) or pane (a busy verdict). It is not a pure read — it "may make a bounded no-mistakes call, so callers run it only on no-verb signal and first-sighting stale paths, never every wake" (bin/fm-classify-lib.sh:2104-2146).
busy_turn_over_age and BUSY_TURN_MAX_SECS
A busy pane is exempt from staleness, but "a hung foreground call can remain hidden even while its rendered busy footer changes every poll". The bound (default 3600 s) ages the newest of state/<id>.turn-ended, state/<id>.progress, or the spawn record; past it the pane is routed to the wedge timer unless it declared a wait (bin/fm-watch.sh:267-281, bin/fm-watch.sh:1288-1300).
Secondmate active-turn gate
A mate whose queue is frozen is deferred only while it is provably busy and the freeze is under the same bound, because a mate's turns end in its own home and leave no completed-turn evidence here (bin/fm-watch.sh:753-771).

What it refuses to do

  • It never promotes unknown to either pole; fm_busy_is_busy is the boolean view and returns false for everything but busy (bin/fm-busy-lib.sh:1202-1211).
  • It invents no UI signature for a harness without a verified source. Kimi's spinner "is deliberately NOT a state source" because it "is locale- and emoji-font-sensitive" (bin/fm-busy-lib.sh:125-134); Cursor's ctrl+c to stop footer is likewise excluded (bin/fm-busy-lib.sh:104-110).
  • It arms nothing that no writer could clear: "Listing a source here without a writer that can clear it would seed a busy record nothing could ever settle" (bin/fm-busy-lib.sh:213-220).
