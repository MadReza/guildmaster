Prompt economy and the startup memory budget

What Firstmate spends context on before the first real turn, what it deliberately defers until a trigger, and how the one growing part of startup, curated memory, is held to a per-home budget.

Read against Firstmate commit ada21f5b. Up: Prompts and skills. Sizes are bytes measured on that commit; token figures use Firstmate's own estimator, ceil(UTF-8 bytes / 3), "a conservative portable approximation rather than a provider-exact tokenizer" docs/configuration.md:264.

The principle

Every always-loaded byte is paid "by every session of every fleet member, every time, whether or not that session ever hits the situation the new lines describe", while a skill's cost "is paid only by the sessions that actually load it" .agents/skills/firstmate-coding-guidelines/SKILL.md:62-63. Firstmate applies that split to every instruction channel it controls.

Economy after startup

The same thinking governs every later turn, mostly by keeping text out of the supervisor's context:

  • Read once. The digest's contract forbids re-reading what it printed bin/fm-session-start.sh:806-812.
  • Sparse status. Workers are told "Each append wakes firstmate, so report sparingly … No step-by-step FYI progress lines; firstmate reads your pane for that." bin/fm-brief.sh:519-522
  • Silent waiting. "Waiting on a healthy supervision cycle is silent; empty polls, elapsed time, and no-change updates are not captain-facing progress." AGENTS.md:451 On Claude the arm itself runs "with no model command and no model tokens" docs/supervision-protocols/claude.md:7.
  • Pointer, not payload. An ask-user escalation points to a findings file; "The status line only points at the file; it never restates or summarizes a finding's content." bin/fm-dod-lib.sh:243
  • Bounded drains. OPEN DECISIONS and RECORD DIVERGENCE are bounded sections AGENTS.md:194 AGENTS.md:197; only UNREAD STATUS is unbounded, "so an answer buried under a later routine line is not dropped" AGENTS.md:196, which trades cost for not losing an answer.

The startup memory budget

Curated memory is the only startup input that grows by itself as a home learns, so it is the one with an explicit allowance.

What it covers
"config/startup-memory-budget is the primary-authoritative per-home allowance for the startup prompt-memory surface: data/captain.md, data/captain-shared.md, and data/learnings.md together." docs/configuration.md:257 The two registries printed in the same digest section, projects.md and secondmates.md, are outside it.
Default and authority
"The locked mutable bootstrap path materializes its visible default of 7500 estimated tokens in a primary home when the file is absent." A secondmate "does not create an independent default" and receives the primary's value through inherited local material docs/configuration.md:258-260 bin/fm-bootstrap.sh:1372-1382.
Format
"one positive base-10 integer followed by exactly one newline in a regular, single-linked file"; anything else is "rejected rather than treated as a default" docs/configuration.md:261-262, surfacing as STARTUP_MEMORY_BUDGET: invalid …, a bootstrap-diagnostics trigger whose instruction is "do not infer the default or propagate it" .agents/skills/bootstrap-diagnostics/SKILL.md:38-39.
Measurement
bin/fm-startup-memory-budget.sh read prints the validated value; report prints each file's bytes and estimate, the total, budget_status=within-budget or over-budget, and in a secondmate the special case primary-owned-shared-file-alone-exceeds-budget bin/fm-startup-memory-budget.sh:41-75.
Enforcement
By curation, not truncation. The internal /stow skill "owns curation and its automatic secondmate cascade, which accounts every home against this same per-home allowance separately rather than against a fleet total" docs/configuration.md:266.
The budget is not a hard cap

Nothing on the startup path reads budget_status. Bootstrap only validates and materializes the file bin/fm-bootstrap.sh:1372-1382, and the digest prints each memory file in full whatever its size bin/fm-session-start.sh:945-951. The only consumer of over-budget in bin/ is the report itself, used by /stow. So an over-budget home still injects everything; the budget binds only when someone runs /stow. The digest's ordering puts memory last so that a truncating harness drops it first bin/fm-session-start.sh:90-95, which is the only automatic protection against oversized memory.

How /stow keeps memory under budget

/stow is user-invocable and also meant for "before a session reset or context compaction, or periodically" .agents/skills/stow/SKILL.md:3. Its curation model:

  • Tiers with clocks. pinned entries never decay; aging entries go stale after 30 days (or 10 unreinforced passes with the opt-in pass horizon); perishable entries after 7 days (or 3 passes) and must name a checkable expiry condition .agents/skills/stow/SKILL.md:37-40 .agents/skills/stow/SKILL.md:70-71. Captain files default to pinned, learnings to aging .agents/skills/stow/SKILL.md:45.
  • Costed bookkeeping. "Marker and header-pointer bytes count toward the startup-memory budget … which is why the spellings above are as short as they are": <!--a:YYYY-MM-DD-->, <!--p:…-->, <!--P--> .agents/skills/stow/SKILL.md:21-25 .agents/skills/stow/SKILL.md:47.
  • A cold tier. "Stale never means deleted": pruned entries move to data/memory-archive.md, "never-injected" and "never counted by the budget report" .agents/skills/stow/SKILL.md:134.
  • An ordered reduction ladder. Archive stale and low-utility entries, consolidate, offload eligible conditional entries to an existing on-demand owner, then evict aging entries oldest-first, but only if doing so can actually reach the budget .agents/skills/stow/SKILL.md:112-115.
  • No accepted exceptions. "Finish at or below the effective budget, or open a concrete captain decision before ending the pass … Never end a pass over budget as an accepted exception." .agents/skills/stow/SKILL.md:119 .agents/skills/stow/SKILL.md:126
  • Pinned entries are the captain's. No automatic process moves a pinned entry; the only exit is explicit, per-item captain approval .agents/skills/stow/SKILL.md:116-117.

Offload is where memory economy meets the skills system: knowledge "current and durable but relevant only in a nameable context, and therefore wrong to pay for in every session of every fleet member" moves to a home-local, git-excluded skill whose description is its trigger .agents/skills/stow/SKILL.md:150 .agents/skills/stow/SKILL.md:174-179. That is the same tier-1-versus-tier-2 decision the coding guidelines apply to AGENTS.md, applied to private memory.

What the economy costs

  • A missed trigger is a missed rule. Deferred text only helps if the agent loads it; Firstmate's defence is naming triggers as concrete conditions and strings, not a mechanism that forces loading. See skills.
  • Frozen text. A loaded skill or contract never refreshes in-session .agents/skills/updatefirstmate/SKILL.md:20.
  • Two sections dominate the contract. The layout tree and task lifecycle are 44% of AGENTS.md; see the section map.
  • Tokens are estimated, not counted. The bytes-divided-by-three estimate is portable and conservative, not the provider's tokenizer docs/configuration.md:264.
