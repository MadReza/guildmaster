How the path changes

The captain adds a requirement mid-task
The supervisor appends the captain's words, unlabelled, to the brief's ## Captain's intent and relays them through fm-send; Firstmate's own constraints go into ## Firstmate spec or the steer AGENTS.md:371. The worker receives the relay as an inbox record plus doorbell, which on Claude its system prompt already marks as first-party bin/fm-spawn.sh:1857.
The project is no-mistakes
The launch brief gains the intent overlay; the worker first reports done on its commit, then is told to run /no-mistakes and passes only the captain's intent as --intent bin/fm-dod-lib.sh:280-289. An ask-user finding returns as a keyed needs-decision, which triggers ask-user-authority in the supervisor AGENTS.md:382-383.
The worker gets stuck
A stale: wake or a looping pane triggers stuck-crewmate-recovery AGENTS.md:440 AGENTS.md:588.
The work belongs to a secondmate's scope
Steps 4 to 11 happen inside that secondmate's home under its own copy of this same path; the main supervisor sends one marked request and later reads one correlated line on the parent channel AGENTS.md:299 bin/fm-brief.sh:312-316. See Secondmate charter.
The session restarts halfway
Nothing in the conversation is needed: the next digest reprints the task's meta and status tail, and the durable queue still holds any unacknowledged wake. "A restart must be a non-event because durable state and live backend inventory, not conversation memory, are authoritative." AGENTS.md:256

What was loaded, in the end

Across the whole path the supervisor loaded two skill bodies (diagnostic-reasoning, harness-adapters) and three of the sixteen harness references, on top of AGENTS.md, the index, and one digest. The worker saw only its launch brief, one system-prompt paragraph, and its project's own instructions. Every other skill, snippet, and reference stayed on disk. That is the economy described on the prompt economy page, observed on one task.
