Session-start digest

A single bounded script output that replaces every unconditional startup read with one ordered prompt, delivered once per session and governed by a contract that forbids re-reading what it printed.

Read against Firstmate commit ada21f5b. Up: Prompts and skills. The lock, bootstrap, and wake-queue stages it composes are mechanism owned by Supervision and Persistence; this page covers the digest as a prompt.

The problem it solves

Before this script, starting a session meant "six-plus separate reads": run bootstrap, read five memory and registry files, lock, drain wakes, then read the backlog, every task's metadata, and every status log. "Every one of those reads is UNCONDITIONAL at every session start, so they belong in a script, not in N agent turns." bin/fm-session-start.sh:4-12

AGENTS.md keeps only the obligation: "Run bin/fm-session-start.sh exactly once at session start. Its header is the single owner of composed commands, ordering, and digest contents." AGENTS.md:168-169 And the consumption rule: "Read the complete digest once and trust it as this turn's startup and recovery input. If the harness shows only a preview and persists the full output to a file, read that file before acting." AGENTS.md:174-175

Composition, not duplication

The script "calls fm-lock.sh, fm-bootstrap.sh, fm-wake-drain.sh, and fm-startup-network.sh as real subprocesses and prints their real output. It never re-implements their logic" bin/fm-session-start.sh:14-17. The only seam it needed in a composed script is an opt-in flag: bootstrap's "detect-only diagnostics without its six mutating sweeps" is FM_BOOTSTRAP_DETECT_ONLY=1 "on fm-bootstrap.sh itself (default unset/0 = unchanged behavior), not a fork" bin/fm-session-start.sh:21-24. AGENTS.md forbids the agent from doing the composition by hand: "Do not reimplement it by separately running its lock, bootstrap, initial wake-drain, or deferred-network components." AGENTS.md:171

The read-once contract

This is the prompt-economy clause that makes the digest pay for itself. It is printed verbatim:

Everything below is printed in full for this session start: every state/*.meta,
a compact data/backlog.md listing, a bounded tail of every state/*.status,
data/projects.md, data/secondmates.md, data/captain.md, data/captain-shared.md,
and data/learnings.md.
Do NOT re-read any of them after reading this digest, and do NOT bulk-read
data/backlog.md or state/*.status: re-reading everything defeats the entire
point of this command.

bin/fm-session-start.sh:806-812. It then lists the only reasons to go to a source directly: flagged ABSENT, unparseable, older status history or a capped line, a full task body, omitted queued items, unfinished network checks, or a truncation banner naming the stage that would have printed it bin/fm-session-start.sh:814-825. AGENTS.md states the same exceptions from the agent's side AGENTS.md:176.

Two design decisions sit behind its position. It prints before the data it governs, because "a contract that only arrives after the payload it governs is the first thing a truncated digest loses", and because it "carries the truncation caveat that keeps it honest when a stage below it never ran" bin/fm-session-start.sh:96-99. And absence is meaningful rather than empty: "captain.md absent means use the firstmate repo's built-in defaults, projects.md absent means rebuild it from the clones" AGENTS.md:206.

Ordering as truncation defence

The digest is delivered through harness hooks that cut oversized output from the tail, and this has happened: "a 70KB digest arrived as lines 1-435 of 578, cutting off eight lines before the live-task inventory. What a truncated tail drops must therefore be the CHEAPEST thing to lose." bin/fm-session-start.sh:86-90 So the order is by recoverability:

  • The lock, bootstrap, and wake queue stay first because they "establish mutation authority and this turn's work queue before anything else is read" bin/fm-session-start.sh:100-101.
  • Fleet state precedes context because it "changes every session and is exactly what recovery depends on" bin/fm-session-start.sh:93-95.
  • Curated memory goes last because it "is stable session to session, is already governed by a captain-set budget … and is recoverable with one targeted read" bin/fm-session-start.sh:90-93.

When it truncates anyway

The child writes straight to stdout, "so everything it emitted before the bound was hit is already delivered; the parent then prints a loud STARTUP TRUNCATED banner naming the stage that did not finish and the sections that were therefore never emitted, and still exits 0" bin/fm-session-start.sh:179-182. The banner tells the agent to reconcile the named stages and rerun, and that "a stage that cannot finish inside the bound is a fleet problem, not a reporting detail" bin/fm-session-start.sh:317-327. A completed digest records state/.session-start-complete with the lock pid only at the very end bin/fm-session-start.sh:997-1009, so a truncated run leaves no completion proof and the next clear or compact runs a full startup docs/sessionstart-nudge.md:35.

Whether the harness runs the digest or only asks the agent to run it depends on the harness surface. "The run tier exists because the nudge can only ask. An agent can defer an instruction, including when a first-command skill has its own read-only path." docs/sessionstart-nudge.md:14-15

The source of the session-open event decides how much of the digest is rebuilt:

SourceActionEvidence
startup, newFull digestdocs/sessionstart-nudge.md:24-29
clear, compact--reemit after a proven complete startup, otherwise full
resume, reload, forkDelegated to the nudge wrapper, normally silent when the lock is still owned
unreadable or unknownFull digest: "Taking the helm redundantly is cheap and idempotent"

--reemit is for a process that "ALREADY took the helm at its own startup and has only lost its context (a /clear or a compaction)": it skips the sweeps startup already reconciled but still drains the wake queue, because "queued records are this turn's work queue, they arrived after startup" bin/fm-session-start.sh:194-209. It prints its own heading saying so bin/fm-session-start.sh:617-625. On a Pi compaction it may also print the whole current AGENTS.md; see the refresh path.

Provenance of the digest text

The digest is machine output arriving in a conversation, so it must not be mistaken for the captain. Pi "is the only adapter that injects a message rather than hook stdout, so whatever it injects must carry operational provenance or the Ahoy skill would have to guess whether it was captain-authored"; the extension encodes it as session-start operational input docs/sessionstart-nudge.md:86 docs/sessionstart-nudge.md:92. The nudge carries the same kind docs/sessionstart-nudge.md:60. The envelope itself is documented under Communication.

Failure behaviour in one place

  • Lock refused: the digest still prints read-only sections; the agent "must not spawn, steer, merge, drain the wake queue, repair supervision, repair a checkout, or perform any other fleet mutation" AGENTS.md:179-180.
  • Slow network: "IN PROGRESS" with the unconfirmed checks named; the verdict comes later from bin/fm-startup-network.sh report or a check: startup-network wake AGENTS.md:185.
  • Hook failure: every ordinary transport path "exits 0, including malformed state and adapter errors, because a Claude SessionStart exit 2 blocks session initialization" docs/sessionstart-nudge.md:65.
  • Oversized on Pi: the extension keeps at most 512 KiB and appends "a loud PI SESSION-START DELIVERY TRUNCATED marker" docs/sessionstart-nudge.md:93.
  • Running inside a validation gate: both wrappers "stay silent for a no-mistakes gate agent" docs/sessionstart-nudge.md:56.
