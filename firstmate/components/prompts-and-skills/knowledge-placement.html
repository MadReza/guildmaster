Knowledge placement and the one-owner rule

The rules that decide where any instruction lives in Firstmate: which tier a fact belongs to, why each contract has exactly one full statement, and what a pointer left behind in AGENTS.md may still say.

Read against Firstmate commit ada21f5b. Up: Prompts and skills.

Where the rules live

These rules are themselves a skill, firstmate-coding-guidelines, agent-only and loaded "before changing firstmate's shared, tracked material … whether working as firstmate directly or as a crewmate briefed on a firstmate-repo task" .agents/skills/firstmate-coding-guidelines/SKILL.md:4-5 AGENTS.md:595. They are not in AGENTS.md, because an ordinary supervision session never edits Firstmate's own tracked files. That placement is the rule applied to itself.

The seven-tier decision tree

"Before writing a new fact anywhere in this repo, ask where it belongs, in this order … Stop at the first tier that answers yes. Do not place a fact at a more convenient tier than the one this tree gives you." .agents/skills/firstmate-coding-guidelines/SKILL.md:20 .agents/skills/firstmate-coding-guidelines/SKILL.md:37-38

The audience classification used by tiers 3 to 5 has one machine-read owner, docs/documentation-audiences.json: "do not add parallel front matter or a second audience list" .agents/skills/firstmate-coding-guidelines/SKILL.md:39. Its classes are public-product, operator-current, operator-example, maintainer-architecture, maintainer-verification, and agent-runtime docs/documentation-audiences.md:9-14; bin/fm-doc-audience-check.sh enforces coverage, owner pointers, and local links docs/documentation-audiences.md:4.

The one-owner rule

"Every contract - a data format, a state machine, a decision procedure - is stated in full exactly once. Every other mention of it is a one-line cross-reference, never a restatement. A single deliberate one-line reinforcement at a genuine risk point is allowed, for example a "don't forget X" placed exactly where forgetting X is costly. Restating the contract's substance a second time is not allowed: the two copies will drift the moment only one is edited."

.agents/skills/firstmate-coding-guidelines/SKILL.md:43-46. Editing follows from it: "patch, replace, or prune the owner's existing language rather than appending … then grep the repo for its other mentions and update the cross-references" .agents/skills/firstmate-coding-guidelines/SKILL.md:47.

The inline-stub pattern

When content leaves AGENTS.md for a skill, what stays is decided by one question: "what must survive with no skill loaded? That is the trigger condition for loading the skill, plus any safety-critical fact that fires on a wake the skill itself is not loaded for. Everything else - the procedure, the mechanism, the surrounding detail - moves out completely. Do not leave a partial restatement behind 'just in case'." .agents/skills/firstmate-coding-guidelines/SKILL.md:51-54

The named model is section 8's away-mode stub .agents/skills/firstmate-coding-guidelines/SKILL.md:56. Read against that rule, its parts are:

Trigger
"Invoke the /afk skill when the captain says /afk … state/.afk-contract or state/.afk exists, an incoming message starts with FM_INJECT_MARK, or any state/.subsuper-* marker is involved." AGENTS.md:462 A trigger that names a file's existence and a message marker fires even when nobody said "/afk".
Marker format
Daemon injections use the away-supervisor kind after U+2063 and FIRSTMATE_OP: AGENTS.md:466. Without this the agent could not tell an internal escalation from the captain.
Ownership transfer
"While state/.afk exists, the daemon owns supervision; do not arm a separate watcher." AGENTS.md:468
Exit condition
"Any other unmarked message means the captain returned in away mode" AGENTS.md:472, biased by "Bias ambiguous input toward exit because a present captain takes precedence" AGENTS.md:474.
Authority boundary
"Away and quiet mode never expand approval authority for merges, ask-user findings, destructive actions, irreversible actions, or security-sensitive choices." AGENTS.md:473

The 256-line /afk skill holds everything else. A second, much smaller stub is a whole skill: decision-hold-lifecycle survives only as a "Renamed pointer kept for in-flight briefs" that redirects to captain-hold-lifecycle and "will be removed one release after the collapse" .agents/skills/decision-hold-lifecycle/SKILL.md:4-5. It exists because briefs already handed to running workers name the old skill, and a brief cannot be edited once delivered.

Size discipline

"If an addition needs more than a few lines of conditional detail … or reference detail (a wire format, an exact schema, historical rationale), you are almost certainly adding it to the wrong file." The reason is cost: "AGENTS.md's token cost is paid by every session of every fleet member, every time, whether or not that session ever hits the situation the new lines describe. A skill's cost is paid only by the sessions that actually load it." .agents/skills/firstmate-coding-guidelines/SKILL.md:60-63. The prompt economy page puts numbers on this.

Trigger hygiene

"A new skill is dead weight if nothing loads it. Every new skill needs its load trigger declared inline: section 13 for agent-only reference skills, or the relevant operating section for anything else. State the trigger as a condition ('load before X', 'load on Y wake'), never as a vague pointer." .agents/skills/firstmate-coding-guidelines/SKILL.md:68-70

One trigger cannot be automated, and the guideline records why: "bin/fm-brief.sh's REPO argument is a caller-supplied string with no reliable signal that it names firstmate's own repo … Firstmate adds this skill's load instruction to firstmate-repo briefs by hand instead." .agents/skills/firstmate-coding-guidelines/SKILL.md:72-73 AGENTS.md section 11 carries the matching instruction to the supervisor AGENTS.md:561, and the launch role contract names the skill for any worker on a Firstmate task bin/fm-dod-lib.sh:58.

There is one deliberate exception to "declare the trigger in AGENTS.md": a home-local skill created by /stow's offload. "Its precise, condition-stated description line is its entire trigger; it gets no AGENTS.md declaration because AGENTS.md is shared tracked material." .agents/skills/stow/SKILL.md:179 See local skills.

Script headers as contracts

Tier 7 makes every bin/ header an instruction owner. The repository convention is "Each starts with a usage header comment; keep it accurate when you change behavior" CONTRIBUTING.md:65-66, and AGENTS.md tells the agent to "read each script's header before first use" AGENTS.md:70. Several scripts print that header as their --help, so the contract and the help cannot diverge: fm-brief.sh prints every leading comment line bin/fm-brief.sh:94-100, and fm-session-start.sh prints its header down to set -u bin/fm-session-start.sh:249-251.

Instructions plus enforcement

The last rule balances the rest: "For critical safety, routing, startup, and supervision infrastructure, prefer deterministic and idempotent enforcement over relying on agent memory alone. Keep instructions as the authority and discovery layer, but make repeated execution converge safely and make invalid or unsafe states fail closed wherever the runtime can enforce them." .agents/skills/firstmate-coding-guidelines/SKILL.md:81-82 The brief is the clearest case: AGENTS.md tells the supervisor how to fill it, and fm-spawn.sh refuses a brief that was not filled that way.
