Prompts and skills

How Firstmate is instructed: one always-loaded contract, a set of skills loaded only when their trigger fires, a once-per-session digest, per-harness supervision text, and executable briefs rendered for each worker. This is the part a successor most needs to copy or deliberately replace, because every other part of Firstmate is driven by these words.

Read against Firstmate commit ada21f5b. Terms follow Firstmate's own vocabulary (captain, first mate, crewmate, secondmate, brief), not Guildmaster's.

What this area is

Firstmate has no compiled core. Its behaviour is the product of an ordinary harness session (Claude Code, Codex, Pi, and others) reading instruction text, plus bash scripts that enforce what text alone cannot. The repository itself names the instruction surface: its documentation inventory classifies files as agent-runtime when they are "loaded or rendered as an operating contract for Firstmate agents rather than read as product documentation" docs/documentation-audiences.md:14. That class covers exactly AGENTS.md, CLAUDE.md, every tracked .agents/skills/ file, and the eight docs/supervision-protocols/ snippets docs/documentation-audiences.json.

Two further instruction channels are generated rather than stored: the session-start digest printed by bin/fm-session-start.sh, and the brief text built by bin/fm-brief.sh, bin/fm-dod-lib.sh, and bin/fm-spawn.sh. And one rule makes the scripts themselves part of the prompt: "read each script's header before first use" AGENTS.md:70.

Only some of this reaches a running first mate: "Only AGENTS.md, bin/, and .agents/skills/ are loaded by a running firstmate; public skills/ is an installer-facing surface" AGENTS.md:572. Once loaded, the text is frozen for that conversation: "A running agent holds AGENTS.md and every skill it has already loaded frozen from the moment it launched, and no verified harness offers a reload" .agents/skills/updatefirstmate/SKILL.md:20.

The design in five rules

These are the organising rules the rest of this area documents. Each is stated by Firstmate itself.

Pay every session only for what every session needs.
"AGENTS.md's token cost is paid by every session of every fleet member, every time … A skill's cost is paid only by the sessions that actually load it." .agents/skills/firstmate-coding-guidelines/SKILL.md:62-63
State every contract once.
"Every contract - a data format, a state machine, a decision procedure - is stated in full exactly once. Every other mention of it is a one-line cross-reference." .agents/skills/firstmate-coding-guidelines/SKILL.md:43-44
Put unconditional reads in a script, not in agent turns.
"Every one of those reads is UNCONDITIONAL at every session start, so they belong in a script, not in N agent turns." bin/fm-session-start.sh:11-12
Instructions are the authority; scripts enforce.
"Keep instructions as the authority and discovery layer, but make repeated execution converge safely and make invalid or unsafe states fail closed wherever the runtime can enforce them." .agents/skills/firstmate-coding-guidelines/SKILL.md:81-82
A brief is a contract, not advice.
"The scaffold is a safety contract, not a suggestion." AGENTS.md:567
