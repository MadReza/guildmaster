After the merge

A merge is not the end of delivery: the watcher turns the forge's merged state into one durable outcome, the supervisor refreshes the project clone and tears the worker down, and teardown refuses unless it can prove the work actually landed.

Read against Firstmate commit ada21f5b. Up: Delivery overview.

Detecting the merge

On a merged answer from a validated PR poll, the watcher does four things in order bin/fm-watch.sh:2439-2466:

  1. Reads the task's merge-authority record; with no matching record it logs that it is "recording an external merge outcome".
  2. Publishes the outcome through fm_merge_outcome_report … poll <authority>. A failure to record it exits the watcher cycle rather than continuing silently.
  3. Removes exactly the authority record it read, then retires the poll: a retirement receipt is published first and the artifacts are removed through it, so a crash between steps is finished by the next watcher start or the next fm-pr-check.sh bin/fm-watch.sh:2234-2253 bin/fm-pr-check.sh:54-60.
  4. Wakes the supervisor, unless the outcome had already been recorded (for example by firstmate's own merge), in which case it logs "absorbed duplicate merged PR poll result".

The outcome line itself, its destination, and its de-duplication are described on Merge authority.

What the supervisor does with it

  • A check: wake means "act on the named poll result, including merges" AGENTS.md:441.
  • "When any wake reports a merged PR for a project cloned in this home, refresh that clone through the guarded fleet-sync path" AGENTS.md:447. Wake-time refreshes can target one clone by name, "so the primary home also catches up when a secondmate reports a merge from its own home" docs/architecture.md:457-458.
  • "Tear down a ship task only after landing is confirmed." A refusal for uncommitted or unlanded work "is a stop-and-investigate result, never an obstacle to bypass", and teardown is never forced without explicit discard authority. Afterwards, record completion, keep only the configured recent Done history, and re-evaluate queued work AGENTS.md:401-404.
  • While the captain is away, the Pi supervision branch owns the same step: "A worker whose pull request has landed is finished, not stuck, and closing it is your job in both postures. A check: merge landed: wake names exactly that moment"; it claims the task's lease and runs bin/fm-teardown.sh <task> with no flags bin/fm-branch-prompt.sh:63-67. That rule arrived in the pinned commit after landed workers sat for nine hours during an away window; the return brief now lists them under "Landed, cleanup due" bin/fm-afk-return.sh:529 .agents/skills/afk/SKILL.md:74.

Teardown's landed-work proof

Teardown hard-resets and removes the worktree and kills its processes, so it "REFUSES if the worktree holds work that has not LANDED" bin/fm-teardown.sh:44-68. Work has landed when:

  • it is reachable from any remote-tracking branch (a fork counts, so upstream contributions pushed to a fork qualify); or
  • for a normal ship task, its PR is merged and the forge reports a PR head that contains the current local work (ancestor or equivalent patch ids); or
  • its content is already present in the up-to-date default branch as a clean tree match.

This recognises the squash-merge-then-delete-branch flow, "where the branch's own commits live nowhere on a remote yet the change is fully in main". A diverged copy is not treated as landed, because "path-set coverage, git cherry, and merge-tree containment each fail to prove content landed without also accepting unlanded edits to the same paths". When no pr= was ever recorded (the header's own example is "a yolo-authorized merge on a repo with no PR CI"), teardown looks up a merged PR whose head branch matches and fetches refs/pull/<n>/head if the branch was deleted. A forge lookup error falls back to the content check, and if that is inconclusive teardown refuses. Uncommitted changes are never landed. For local-only, a merge into the local default branch also counts (Local landing).

Once the landed-work refusals pass, and before anything is returned, teardown concludes a still-parked no-mistakes run it can prove is this task's, reaps processes whose working directory is the task's worktree, and sweeps orphaned remote job workers bin/fm-teardown.sh:225-278. It validates the PR-poll and merge-authority artifacts as single-link files on the state device and removes them with the rest of the task's volatile state bin/fm-teardown.sh:76-80 bin/fm-teardown.sh:1330-1368. The backlog item is closed with the PR link, or local main for a local landing, in the same locked step that removes the task record; the intended transition is written to state/<id>.backlog-close first so an interrupted cleanup can be finished at the next session start bin/fm-teardown.sh:15-29 bin/fm-teardown.sh:1517-1536. A backlog item that is still an open captain call is reopened with the deliverable recorded instead of being closed bin/fm-teardown.sh:30-43.

Finally, for a PR-based ship task, teardown runs bin/fm-fleet-sync.sh <project>, ignoring its result bin/fm-teardown.sh:3701-3703. The rest of teardown, including worktree-slot ownership, endpoint close, and lock recovery, belongs to Crew.

Clone refresh

bin/fm-fleet-sync.sh [<project-dir-or-name>] fast-forwards each clone's checked-out default branch to origin/<default> when safe and prunes local branches whose upstream is gone and that no worktree still needs bin/fm-fleet-sync.sh:2-5. Its guarantees:

  • One drift self-heals: a clean detached HEAD with no unique commits is re-attached to the default branch and then fast-forwarded, reported as recovered:.
  • Every other off-default state (a named non-default branch, a detached HEAD with unique commits, a dirty tree, a diverged default) "may hold real work, so it is left untouched and reported as a quantified, loud STUCK: ... N commits behind ... - needs attention warning". "Nothing is ever forced, stashed, or discarded" bin/fm-fleet-sync.sh:6-13.
  • local-only projects, clones with no origin, missing branches, and fetch failures are benign skips bin/fm-fleet-sync.sh:14-15. A directory under projects/ that is not the root of its own work tree is skipped as "not a clone root", so git discovery cannot walk up into the Firstmate checkout bin/fm-fleet-sync.sh:16-20.
  • Pruning never deletes the checked-out branch or one with a worktree; FM_FLEET_PRUNE=0 disables it. An orphaned .git/packed-refs.lock is removed only when provably stale bin/fm-fleet-sync.sh:21-26.

The same refresh also runs off the digest's blocking path at session start AGENTS.md:183 docs/architecture.md:455-463.

Landing changes to Firstmate itself

Firstmate is "its own repo, behind the same no-mistakes gate as any project", so a merged change to its instruction surface sits on main "until each running firstmate pulls it" .agents/skills/updatefirstmate/SKILL.md:14-17. Shared tracked changes ship "through this repo's no-mistakes pipeline and PR path, with the same merge authority as any other project" AGENTS.md:48. The captain's /updatefirstmate fast-forwards the running repository and registered secondmate homes from origin without touching project clones, and restarts every live secondmate, because a running agent holds its loaded AGENTS.md and skills frozen and "no verified harness offers a reload" .agents/skills/updatefirstmate/SKILL.md:19-26 docs/architecture.md:465-473. The shared fast-forward guard is bin/fm-ff-lib.sh: never forcing, merging, or stashing, and reconciling a clean secondmate divergence only when a three-way tree proof shows its whole local result is already in the target bin/fm-ff-lib.sh:1-38. The update mechanics themselves belong to the Remote and Persistence areas.

How it fails

SituationBehaviour
Outcome cannot be written during a pollWatcher logs and exits the cycle; the poll stays armed and is retried
Authority record cannot be retiredWatcher logs "published merge outcome … but could not retire its authority record" and exits the cycle
Poll snapshot changed during retirementRetirement deferred and recoverable
Merged PR whose head does not contain local workTeardown refuses; the extra local commits are unlanded
Forge unreachable at teardownContent check; refusal if inconclusive
Clone dirty or on a feature branchSTUCK: warning, clone untouched
Backlog close fails after cleanupFatal and loud; the pending-close record is replayed at the next session start
