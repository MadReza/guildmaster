Delivery

How a change gets from a worker's branch into the project, and who is allowed to authorise each step: a delivery mode fixed per task at intake, an optional external validation pipeline, a registered pull request watched to merged, a merge gate that proves every condition live, and a teardown that refuses until the work has provably landed.

Read against Firstmate commit ada21f5b. This is a Level 3 (component) view inside the supervisor's operational home; see Level 2: Containers for where it sits.

In flux

The code defines three delivery modes and treats the no-mistakes validation pipeline as a standard tool, but at least one estate has withdrawn that pipeline and ships direct-PR instead. This section documents the mechanism as the code defines it. Where the code assumes the tool, and what happens when it is absent, is listed on the validation pipeline page.

The shape in one paragraph

Every ship task leaves by exactly one mode: no-mistakes (the pipeline owns review, fixes, tests, docs, push, PR, and CI), direct-PR (the worker pushes and opens a PR itself), or local-only (no remote; firstmate fast-forwards the local default branch) AGENTS.md:353-355. The mode is resolved by the supervisor at intake from the captain's instruction and the project's registered posture, then passed explicitly to every command that needs it; no command looks it up AGENTS.md:315-320. Separately from the mode, the task's yolo flag decides only merge authority: off, the captain approves every merge; on, firstmate merges green, in-scope work itself; and no setting ever merges a red PR without the captain naming the waived check AGENTS.md:357-361. Workers never merge. Firstmate merges only through two guarded entrypoints, bin/fm-pr-merge.sh and bin/fm-merge-local.sh AGENTS.md:363, and every confirmed merge leaves a durable outcome that drives clone refresh and teardown.

What the area guarantees, and what it refuses

  • No inferred delivery. Ship briefs, spawns, and promotions refuse to run without an explicit legal mode, and a spawn refuses a brief whose recorded mode disagrees (details).
  • No self-answered findings. The worker that raised an ask-user finding never answers it, and --yes is banned (details).
  • No state from liveness. Validation is judged from the pipeline's attributed run step, never from a pane, the last status line, or a raw run record (details).
  • No merge that cannot be proved. The merge gate reads every condition live, binds the merge to the head it verified, and reports a merge as landed only after reading it back (details).
  • No silent landing. Every confirmed PR merge publishes one durable, role-routed outcome, at least once (details). Local landings are the exception (details).
  • No teardown of unlanded work. Teardown proves landing, including after squash merges, and refuses otherwise (details).

What is left to judgment
