Local landing

A local-only task never touches a remote; once its landing is approved, firstmate fast-forwards the project clone's default branch to the worker's branch through bin/fm-merge-local.sh, the one narrow place where firstmate itself changes a project's git state.

Read against Firstmate commit ada21f5b. Up: Delivery overview.

What it is for

Some projects have no remote at all, and the registry defaults such a project to local-only .agents/skills/project-management/SKILL.md:46. With no forge there is no PR to merge and no poll to watch, so the ordinary "firstmate never edits projects" rule needs one exception. The script header names it: "This is firstmate's merge gate-action (the captain's merge authority applied locally instead of via a GitHub PR). It is the one sanctioned exception to hard rule #1 'never run state-changing git in projects/', and it is narrow: it only runs for mode=local-only tasks, only after the captain approves (or yolo=on auto-approves), and only as a clean fast-forward" bin/fm-merge-local.sh:5-11. Hard rule 1 lists "approved local-only merge paths" among its few exceptions AGENTS.md:29.

The worker's side

The local-only definition of done: commit on fm/<id>; do not push, open a PR, or merge; "Keep your branch a clean fast-forward onto the current default branch - if main has advanced, rebase onto it so the eventual merge stays a fast-forward"; then report done [at=<epoch>]: ready in branch fm/<id> bin/fm-dod-lib.sh:264-273. The brief's rule 1 for this mode forbids pushing to any remote at all bin/fm-dod-lib.sh:68-69. Because the task worktree shares its object store and branches with the project clone under projects/, the branch the worker commits is directly visible to the landing script.

The guards, in order

Usage: bin/fm-merge-local.sh <task-id> bin/fm-merge-local.sh:17.

Actor role
"Landing local-only work is MAIN-owned; the Pi supervision branch reports readiness and never lands." It is deliberately not relocated under the away-posture record, "unlike the PR merge it has no record-side grant gate of its own, so a parked main keeps it held for the captain's return" bin/fm-merge-local.sh:42-51. fm_lease_forbid_branch exits with the lease refusal status for the branch actor bin/fm-lease-lib.sh:245-255, and the branch prompt restates that the script "still refuses you: local-only landing waits for the captain in both postures" bin/fm-branch-prompt.sh:114.
Incarnation
The task record's spawn generation is read, the per-task control lock state/.control-<id>.lock is taken, and the generation is read again; "task <id> changed incarnation while waiting to merge" refuses bin/fm-merge-local.sh:53-74.
Mode
A task whose record is not mode=local-only is refused with a pointer to bin/fm-pr-merge.sh bin/fm-merge-local.sh:76-78.
Clone state
The project clone must have fm/<id>, a resolvable default branch (origin/HEAD, else main, else master), be checked out on that branch, and be clean, "so the fast-forward lands predictably (firstmate never writes here otherwise)" bin/fm-merge-local.sh:80-108.
Fast-forward
"Clean fast-forward only: DEFAULT must be an ancestor of BRANCH." A diverged branch is refused with "Have the crewmate rebase … then retry" bin/fm-merge-local.sh:110-115.
Captain hold
The same open-hold check as the PR merge, under the same lock: a still-held or unreadable row refuses, "so a captain approval must be recorded as an answer --release before this entrypoint is invoked" bin/fm-merge-local.sh:12-16 bin/fm-merge-local.sh:117-131.
Landing
git -C <project> merge --ff-only fm/<id>; the lock is released; the script prints merged fm/<id> into local <default> (<before> -> <after>) in <project> bin/fm-merge-local.sh:132-138.

After a local landing

  • Teardown accepts local-only work as landed when it is merged into the local default branch, "as a fallback for the common case where there is no remote at all" bin/fm-teardown.sh:69-71. Otherwise it refuses with "local-only worktree … has work not yet merged into <default> and not on any remote" and names the landing script as the remedy bin/fm-teardown.sh:1808-1824.
  • The backlog item is closed with the note local main instead of a PR link bin/fm-teardown.sh:1517-1536, and bin/fm-landed-lib.sh counts "finished local-only merges" as deliveries in Recently Landed bin/fm-landed-lib.sh:19-27.
  • No clone refresh runs, because there is no origin to follow bin/fm-teardown.sh:3701-3703.

Observations

  • Unlike the PR merge, a local landing publishes no durable outcome: bin/fm-merge-local.sh does not call fm_merge_outcome_report and writes no merge-authority record. The only record of the landing is the git history itself, the script's stdout, and the backlog note teardown writes later. The supervisor's one-line "local-main outcome" to the captain AGENTS.md:364 therefore depends on the agent remembering to send it.
  • The header's "or yolo=on auto-approves" is not implemented in the script; no line reads yolo=. The approval check is the supervisor's, and the only mechanical approval signal is a released captain hold, which the script requires to be absent or released rather than present.
  • Local-only work is kept in the main home rather than routed to a secondmate AGENTS.md:267, and home seeding refuses to route a local-only project bin/fm-home-seed.sh:466-470.
