Engineering patterns

The same few techniques recur across dozens of records. Knowing them makes any single record predictable: how it is written, how a stale writer is rejected, and which way it fails.

Read against Firstmate commit ada21f5b. Up: Persistence.

1. One owner per record, and the header is the contract

Every record names its single writer, and that writer's header comment owns the format. The configuration guide owns only the top-level layout: "producer script headers and their help own exact child-file fields and mutation contracts" docs/configuration.md:11. Examples: fm-busy-event.sh is "the ONLY writer" of the busy-state record bin/fm-busy-event.sh:2-4. .lock-session is "written only by bin/fm-lock.sh" AGENTS.md:152. The away-posture record is "written only by bin/fm-afk-contract.sh" AGENTS.md:149. The steering-inbox library is the "ONE owner" of its record format, "none of them restates the format" bin/fm-task-inbox-lib.sh:5-12. A single owner means one place to change a format and one place to read it.

2. Atomic replace: write a sibling temporary file, then rename

A record that is rewritten is never edited in place. The writer composes the full new content in a temporary file in the same directory, validates it, and renames it over the target. A reader then sees either the old record or the new one, never a partial one.

Instances: task metadata bin/fm-spawn.sh:4514 bin/fm-pr-check.sh:131-145. The recovery marker, mode 0600 bin/fm-wake-lib.sh:651-663. The queue rewrite on acknowledgement bin/fm-wake-drain.sh:727. The relaunch journal bin/fm-control.sh:597-622. Decision cursors bin/fm-classify-lib.sh:1172-1179. The trust binding bin/fm-check-register.sh:33-40. Inherited config bin/fm-config-inherit-lib.sh:143-170. A same-actor lease refresh bin/fm-lease.sh:130-145.

The known cost of rename

Renaming over a symlink replaces the link with a regular file. That is why a code-root backlog must never be symlinked into a home: tasks-axi's rename "forks the queue on the first such write" docs/configuration.md:129. Firstmate's own record paths refuse a final-component symlink outright docs/configuration.md:316.

3. Append-only event logs, with state derived elsewhere

Where many writers report events, Firstmate uses an append. Status logs are "created once (>) and only ever appended to (>>)" bin/fm-classify-lib.sh:941-944. Queue rows are appended under a lock bin/fm-wake-lib.sh:1864-1866. The memory archive is "append-only" .agents/skills/stow/SKILL.md:134. Appending needs no read-modify-write, so a worker can report without a lock. Readers track a byte offset.

The discipline that makes this safe is that the log is never mistaken for current state: "A state/<id>.status line is a wake event, not current-state truth" AGENTS.md:163. Timestamps in the log "must never decide current state or decision closure" bin/fm-classify-lib.sh:293.

4. Exclusive creation as the decision point

When two actors race to create something, the filesystem's own create-if-absent operation decides who wins, so no separate check is needed. A lock is won by ln -s owner-dir lock bin/fm-wake-lib.sh:566. A lease claim is won by a hard ln of a prepared temporary file, which fails if the lease exists bin/fm-lease.sh:135. Steering-inbox sequence numbers "are never reused within a task: allocation scans both the inbox root and handled/" bin/fm-task-inbox-lib.sh:42-45.

5. Generation and identity binding to reject stale writers

A process can outlive its role. A hook can fire after its worker was relaunched. A watcher can close during handling. A pid can be recycled. Each such case gets a token, minted at the start of an incarnation and presented on every later write. A write carrying an old token is refused.

6. Refuse rather than proceed when a precondition cannot be proven

This is the most consistent stance in the code. Where a script cannot prove the condition that makes an action safe, it refuses, names what it could not prove, and leaves the evidence in place.

  • A session that cannot verify the session lock stays read-only AGENTS.md:179-180.
  • A git lock file is removed only on positive proof that it is abandoned. "ANY uncertainty ... returns non-zero" bin/fm-lock-lib.sh:14-15.
  • Teardown refuses before any record is removed when the endpoint close, landed work, check artifacts, or slot ownership cannot be proven bin/fm-teardown.sh:8-14 bin/fm-teardown.sh:44-51.
  • An unreadable slot claim "proves nothing either way and refuses" bin/fm-teardown.sh:108-111.
  • A fresh spawn refuses rather than waits when forced teardown owns the task set bin/fm-spawn.sh:1496-1506.
  • An inherited config item is removed downstream only when its absence is proven. An inspection error changes nothing bin/fm-config-inherit-lib.sh:192-197.
  • An unrecognized config/claude-permission-mode refuses every spawn. "Firstmate never falls back to a permission posture the captain did not choose" docs/configuration.md:376.
  • A state check without a valid binding is refused without execution bin/fm-watch.sh:2475-2480.

Where refusing would lose information, the failure direction is chosen deliberately. Readers prefer a duplicate to a loss: a bad presentation offset "reads from byte 0, preferring a bounded duplicate over a lost event" bin/fm-classify-lib.sh:26-28. A fold whose own read fails returns the last trusted set, "never a bare “empty” as if nothing were open" bin/fm-classify-lib.sh:954-959. An inbox escalation "deliberately queues the wake before writing the deduplication marker", so a crash produces "a rare duplicate rather than silently lose a wake" bin/fm-task-inbox-lib.sh:56-59.

7. Journal the intent before destroying its evidence

When an operation must delete the only record that describes what remains to be done, it writes the intent first. Teardown writes state/<id>.backlog-close before removing the metadata that holds the completion links bin/fm-backlog-transition-lib.sh:41-49. fm-control.sh relaunch journals each phase and preserves the prior metadata and brief beside the journal bin/fm-control.sh:569-581. Every append publishes downtime on the recovery marker before the row becomes visible bin/fm-wake-lib.sh:1852. Replay is designed to be idempotent, so running it twice is harmless bin/fm-backlog-transition-lib.sh:49-50.

8. Private-file discipline

Records that gate execution or authority are checked for more than content. The checks are: regular file, not a symlink, exact mode, one hard link, and on the containing directory's device bin/fm-pr-lib.sh:285-296. This applies to check scripts and their bindings, PR-poll sidecars, and task metadata during fm-pr-check.sh bin/fm-pr-check.sh:126-141. Lifecycle paths must also resolve inside their authorized root bin/fm-backlog-transition-lib.sh:711-737.

9. Durability that outlives any conversation

The design premise is that the agent's context is disposable: "A restart must be a non-event because durable state and live backend inventory, not conversation memory, are authoritative" AGENTS.md:256. The records described in this section are what a new session rebuilds from. Session start:

  1. takes the session lock AGENTS.md:187;
  2. replays interrupted backlog transitions for this home bin/fm-bootstrap.sh:1279-1312, and sweeps stale leases bin/fm-session-start.sh:734;
  3. drains and presents the durable wake queue with its open decisions and unread status AGENTS.md:192-197;
  4. prints every state/<id>.meta, a bounded tail of each status log labeled as event history, the away posture, and one alive-or-dead read of each recorded endpoint AGENTS.md:201;
  5. prints the curated memory files docs/configuration.md:244.

The same premise shows up in smaller rules. The away-posture record is written "in the same turn as /afk before any other work" AGENTS.md:467. data/captain.md stays canonical "even if harness memory mirrors it" AGENTS.md:94.
