Locks and leases

One portable lock primitive, reused at four scopes: the home's session, the home's set of tasks, one task's lifecycle, and one task's record. A lease adds a fifth, which of two supervision actors may change a task.

Read against Firstmate commit ada21f5b. Up: Persistence.

The portable lock primitive

bin/fm-wake-lib.sh describes itself as "Shared durable wake queue and portable lock helpers" bin/fm-wake-lib.sh:2. Every lock above except the git-lock proof is built from its fm_lock_* functions.

Shape on disk

A held lock is a symlink. It points to a private owner directory named <lock>.owner.XXXXXX that holds a pid file. Optional files are role, pid-identity, fm-home, and watcher-path bin/fm-wake-lib.sh:436-445 bin/fm-wake-lib.sh:473-485. Creating the symlink with ln -s is the atomic step: exactly one creator can win the name bin/fm-wake-lib.sh:554-579. Before creating it, the claimant writes and reads back its pid in the owner directory. Afterwards it checks that the link points at its own directory, and that no <lock>.steal is in progress bin/fm-wake-lib.sh:528-552. An older plain-directory lock is still understood and removed correctly bin/fm-wake-lib.sh:581-591.

Waiting, bounded waiting, and release

  • fm_lock_acquire_wait retries every 0.1 s with no deadline bin/fm-wake-lib.sh:1033-1038.
  • fm_lock_acquire_wait_bounded <lock> <seconds> waits inside a timed helper process. The helper then rewrites the owner pid to the caller's pid before it exits. "Before transfer the helper is the owner; after transfer the still-live caller is the owner", so ordinary stale recovery covers an interruption at any point bin/fm-wake-lib.sh:1040-1076. It returns 124 with the holder's pid when a live holder outlasts the deadline. Callers use it where they "must refuse rather than block" bin/fm-wake-lib.sh:1068-1077.
  • fm_lock_release removes the lock only when the owner pid is the current process and the link still points to that owner's directory. Otherwise it silently does nothing bin/fm-wake-lib.sh:1129-1146. A process can never release someone else's lock.
Finding: pid liveness only, except for the watcher lock

The generic primitive decides "held" with kill -0 on the recorded pid bin/fm-wake-lib.sh:48-54 bin/fm-wake-lib.sh:962-965. If the pid is recycled by an unrelated process, a dead holder's lock reads as held until that process exits. Only the watcher lock and the away-mode daemon lock record pid-identity: a start time plus the full command line, "keeps PID reuse a mismatch" bin/fm-wake-lib.sh:56-90. fm_watcher_lock_matches_pid compares it bin/fm-wake-lib.sh:139-152, and the daemon check uses "the same discipline" bin/fm-wake-lib.sh:324-346. The session lock goes further, as described below. The per-task and task-set locks rely on pid liveness alone.

A different problem: git's own lock files

bin/fm-lock-lib.sh is not a lock implementation. It is a staleness proof for git's index.lock and packed-refs.lock, used by teardown and fleet sync. A lock is provably stale only if the file exists, lsof shows no holder of the file or its worktree or .git directory, and its age is at least a caller-supplied threshold. "ANY uncertainty - lsof missing, an lsof error, an unreadable mtime - returns non-zero (NOT stale): fail safe, never remove a lock that cannot be proven dead" bin/fm-lock-lib.sh:1-17 bin/fm-lock-lib.sh:91-104.

The session lock

Problem solved. Only one supervisor session may mutate a home. A second session, a resumed session, or a forgotten terminal must not spawn, steer, or drain alongside the first. The charter: "If the session lock cannot be acquired and verified, report its exact diagnostic and remain read-only". A refused session "must not spawn, steer, merge, drain the wake queue, repair supervision, repair a checkout, or perform any other fleet mutation" AGENTS.md:179-180.

Files

  • state/.lock. Line 1 is the session's anchor pid: the harness process found by walking the shell's ancestry, not the transient pid of one tool call. For a Claude session with a trusted id, the anchor is CLAUDE_PID, "so a shared transient daemon or a front-end that outlives the session never keeps a dead session's lock alive" bin/fm-lock.sh:4-12 bin/fm-session-lock-lib.sh:251-271.
  • state/.lock-session. The trusted session id, written only by fm-lock.sh and only under the claim lock. It is refreshed on every confirmed acquisition, removed when the session proves no trusted id, and left byte-identical when unchanged bin/fm-lock.sh:14-21. The charter says "never touch" AGENTS.md:152.
  • state/.lock.acquire. The claim lock, the portable primitive serializing the pair's publication bin/fm-lock.sh:69.

Who owns it

Two signals decide ownership, "either one sufficient". The recorded pid may be in this process's contiguous harness ancestry, or the trusted Claude session id may match the sidecar. "Neither signal ever fails open" bin/fm-session-lock-lib.sh:4-13. The ancestry test is membership, not equality, because "the lock owner sits at an unknown depth in a contiguous Claude run" bin/fm-session-lock-lib.sh:262-283.

Acquisition

  1. Probe that state/ is writable with a temporary file. Otherwise exit 1 with "operate read-only until resolved" bin/fm-lock.sh:59-66.
  2. If this session already owns the lock, take the claim lock, refresh only the sidecar, and exit 0. Line 1 is never rewritten while its pid is alive, "because bin/fm-startup-network.sh compares that pid across its deferred sweeps" bin/fm-lock.sh:152-180.
  3. If a different live harness holds it, refuse, naming the pid and the recorded session bin/fm-lock.sh:182-201.
  4. Take the claim lock. If the prior session's deferred startup sweep still holds it, refuse rather than wait bin/fm-lock.sh:203-211.
  5. Re-check under the claim lock. Refuse a non-regular or unreadable lock file bin/fm-lock.sh:213-229.
  6. Publish the sidecar first, because "a fresh pid beside a previous session's id would let that session's resume own this lock". Then write line 1, read it back, and verify it bin/fm-lock.sh:230-275.

A two-field phase journal, LOCK_SESSION_PHASE and LOCK_SESSION_KIND, and a .lock-session.prev backup let the EXIT trap undo a half-published pair. If the sidecar changed but line 1 was not written, the previous sidecar is restored. If line 1 was written but not verified, the sidecar is removed so the lock is "ancestry-only" bin/fm-lock.sh:71-119 bin/fm-lock.sh:230-235.

fm-lock.sh status is read-only and always exits 0. "A held lock is not proof the holder is consuming wakes" bin/fm-lock.sh:23-27. Its classifier distinguishes free, held, stale, unreadable, and unknown bin/fm-session-lock-lib.sh:335-384. The status wording folds unknown into "stale (pid … dead or not a harness)" bin/fm-lock.sh:47-56.

The task-set lock

Problem solved. "A per-task lock cannot protect a task that does not exist yet." A forced secondmate teardown enumerates a home's tasks, locks them, and then re-enumerates while removing. A spawn that published inside that window "gets destructively processed while never lifecycle-locked". The comment records the observed failure: a record published 0.249 s after teardown began was removed, and its worktree returned to the pool, with both commands reporting success bin/fm-wake-lib.sh:1163-1176.

Rule. A fresh spawn takes state/.task-set.lock before its own locks and holds it through publication. It "refuses rather than waits", because "the home may be moments from removal, so there is nothing worth waiting for" bin/fm-spawn.sh:1483-1506. A relaunch is exempt: the existing task's control lock covers it bin/fm-spawn.sh:1492-1494. A forced teardown takes the same lock per home, parent before child, and refuses if it is held bin/fm-teardown.sh:2741-2751. "Both directions fail closed" bin/fm-wake-lib.sh:1172-1176.

The per-task control lock

state/.control-<id>.lock serializes lifecycle actions on one task. fm-control.sh takes it with a non-blocking try and dies with "another lifecycle action is already running for task <id>" bin/fm-control.sh:296-300. The same lock is taken by fm-pr-merge.sh before either forge merge bin/fm-pr-merge.sh:69, by fm-merge-local.sh bin/fm-merge-local.sh:12, by fm-promote.sh, fm-captain-hold.sh, fm-teardown.sh, fm-spawn.sh on relaunch, and fm-bootstrap.sh. The watcher takes it around a validated PR-poll execution, so a merge result and a concurrent lifecycle action cannot interleave bin/fm-watch.sh:2397-2404.

The per-task metadata lock

fm_meta_lock_path maps state/<id>.meta to state/.meta-<id>.lock. It refuses a path that does not end in .meta or an id outside [A-Za-z0-9._-] bin/fm-wake-lib.sh:1148-1161. Every script that rewrites or removes a record takes it: spawn, teardown, fm-pr-check.sh, fm-promote.sh, fm-captain-hold.sh, fm-send.sh (around inbox and remote writes), fm-inactive-reconcile.sh, fm-secondmate-reconcile.sh, and the Relay library.

Lock order

The order is written once, in forced teardown, and every holder must match it "so they cannot cycle". The order is each home's task-set lock first (parent home before child home), then per-task locks in the same parent-before-child order, sorted by id within each home, "each control lock before its matching metadata lock. No child lock holder ever reaches back for a parent lock" bin/fm-teardown.sh:2786-2793.

The supervision lease

Problem solved. On a Pi primary, two LLM actors share one home inside one process: main (the captain's chat) and branch (the persistent supervision conversation). A small overlap set could be mutated by both: steering or stopping a worker, post-landing cleanup, a task's backlog status, and stuck-worker recovery. "The lease is the merge-conflict analog" bin/fm-lease-lib.sh:4-12.

  • Format. state/.lease-<task> holds one line, <actor>\t<pid>\t<epoch>. A claim is written with a temporary file and ln (fails if the lease exists). A same-actor refresh uses a temporary file and mv. Everything is serialized by .fm-lease-command.lock. "Leases never coordinate across firstmate homes" bin/fm-lease-lib.sh:14-18 bin/fm-lease.sh:130-145.
  • Identity. The actor is $FM_SUPERVISION_ACTOR, injected by the Pi branch extension and never taken from agent memory. Any value other than main or branch is refused bin/fm-lease-lib.sh:19-23 bin/fm-lease-lib.sh:104-113.
  • Staleness through identity binding. A lease is live only in a Pi context, only while its pid is alive, and only while that pid is the current session-lock holder. A lease from an exited Pi session therefore goes stale "even if its pid was recycled", and "a non-Pi home never honors a leftover Pi lease" bin/fm-lease-lib.sh:24-33 bin/fm-lease-lib.sh:157-170.
  • Guard. fm_lease_guard passes when there is no lease, a same-actor lease, or a stale lease. It refuses with exit 6 when the other actor holds a live lease. In a Pi context it keeps the lease-command lock across the caller's mutation, closing the check-then-use race bin/fm-lease-lib.sh:182-217.
  • Role partition. Merging a PR, landing local work, spawning, and answering a decision refuse the branch outright. Under a live away-posture record, main's standing authority relocates to the branch, only for scripts that opt in with --away-relocated bin/fm-lease-lib.sh:53-74 bin/fm-lease-lib.sh:238-255.
  • Threat model, stated plainly. The guards are "CONFUSED-AGENT-GRADE". A deliberately forging shell running as the same user in the same process can evade them. Adversarial separation "is explicitly out of scope" bin/fm-lease-lib.sh:35-45.

fm-lease.sh sweep removes every provably stale lease and runs at session start. release-actor drops every lease that a replaced branch conversation held bin/fm-lease.sh:24-31. The Pi branch itself belongs to Supervision.

Worktree slot ownership

A Treehouse slot is reused across tasks. A fresh Treehouse-backed spawn therefore takes the project-identity lock in the local root home's state/ before slot allocation, holds it through metadata publication, and writes the slot's owner claim under that lock bin/fm-spawn.sh:130-140. Teardown holds the same lock while it proves and returns a slot. A claim that names another task makes teardown skip every step that touches the slot. A claim that cannot be read makes teardown refuse, and the operator must "never remove it, since an absent claim proceeds" bin/fm-teardown.sh:81-116. The claim functions are bin/fm-wake-lib.sh:1231-1366.
