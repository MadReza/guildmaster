Presentation cursors and folded decisions

Status logs only grow. Byte cursors bound by file identity let every drain read only what is new, without replaying old lines or dropping a decision that later lines buried.

Read against Firstmate commit ada21f5b. Up: Persistence.

Problem solved

Every drain prints a fleet-wide OPEN DECISIONS section and an UNREAD STATUS section AGENTS.md:193-196. Re-reading every task's whole status log on every drain would cost time in proportion to each task's lifetime history. The whole-file fold "re-reads and re-folds a status file's ENTIRE lifetime on every call, so its cost grows with total log size". The incremental sibling reads "only the bytes appended to a status file since its own last call" and folds them into "a persisted running open-set" bin/fm-classify-lib.sh:913-926. There are two further failure modes to avoid: re-printing lines already presented, and losing a decision because many unrelated lines were appended after it.

File identity: how a cursor knows it is still pointing at the same file

The design relies on one fact about status logs: "every one is created once (>) and only ever appended to (>>)". A cursor can therefore go stale in only a few ways: "a fold-version mismatch, a shrink (truncated), or the file at this path being a different file than before (replaced/rotated/recreated)". Each of these forces "a full re-fold of the whole current file from byte 0" bin/fm-classify-lib.sh:941-950.

The header describes identity as "a changed device+inode". The implementation is slightly stronger. Where the platform reports a birth time, the identity is strong:<dev>:<inode>:<birth>. Otherwise it is weak:<dev>:<inode> bin/fm-classify-lib.sh:1000-1017. The birth time catches an inode number reused by a recreated file. That is an addition to the header's description, not a contradiction of it.

The accepted gap is stated plainly: "A same-inode, same-size, in-place byte edit is NOT detected" bin/fm-classify-lib.sh:950-953.

The fold

Both the whole-file fold and the incremental fold apply the same per-line rule, _fm_decision_fold_line, "so the two strategies can never disagree on what is open" bin/fm-classify-lib.sh:922-925. The rule bin/fm-classify-lib.sh:678-737:

  • A line with neither a colon nor a complete [key=…] token is prose and never moves the set. The colon test reads the line with its time tag stripped, so a worker stamp like [at=10:30] cannot make prose look like a transition.
  • On a ship or scout task, a done: or failed: line closes every open decision.
  • needs-decision and blocked open (or replace) the entry for their key. resolved and captain-held remove it bin/fm-classify-lib.sh:128-129.
  • A key whose slug fails the charset is skipped. It is "never rewritten to default" bin/fm-classify-lib.sh:445-447.

Correctness invariant: "cursor advancement, age, and being buried under later appends never drop an open decision ... Only a line the shared fold rule retires removes one" bin/fm-classify-lib.sh:928-932.

Fold versioning

A persisted open set is only valid under the rule that produced it. FM_OPEN_DECISIONS_FOLD_VERSION is 9 at this commit bin/fm-classify-lib.sh:997. It "must be bumped whenever _fm_decision_fold_line semantics change, so persisted state from an older interpretation is discarded and rebuilt from byte 0". The version is suffixed with the task kind, because kind changes the fold bin/fm-classify-lib.sh:934-940. The history comments record each bump: bracketed tags, unbracketed correlation tokens, the terminal-closes-all rule, colon requirements, and the time-tag stripping bin/fm-classify-lib.sh:966-996. Versioning a cache by the rule that computed it is how Firstmate keeps a rule change from silently reinterpreting old state.

Failure behaviour

"The other real failure mode is OUR OWN read failing." On any stat, size, or read error, the function returns "the already-trusted persisted set unchanged rather than risking a silent invalidation that would wipe it - never a bare “empty” as if nothing were open" bin/fm-classify-lib.sh:954-959 bin/fm-classify-lib.sh:1123-1154. The cursor is rewritten with a temporary file and a rename bin/fm-classify-lib.sh:1172-1181. The drain calls it only after releasing the queue lock. Two overlapping drains "can at worst redo a little folding work twice - never drop an open decision" bin/fm-classify-lib.sh:960-968.

The status-presentation cursor

This cursor answers a different question: which status bytes has the supervisor already been shown? It keeps two independent offsets per task. The annotation offset drives the signal annotations and UNREAD STATUS. The outcome-backstop offset drives the Pi branch's STATUS OUTCOME BACKSTOP AGENTS.md:148. Reading an offset validates the whole manifest first. A duplicate task row, extra fields, non-numeric offsets, or a symlinked manifest all fail the read. An identity mismatch or an offset past the end reads as 0, "preferring a bounded duplicate over a lost event" bin/fm-classify-lib.sh:1294-1340 bin/fm-classify-lib.sh:26-28. The drain snapshots each task's end offset and identity, prints, and then commits the snapshot under .status-presentation-lock bin/fm-classify-lib.sh:1596-1639. A live lock holder makes the drain skip annotations and leave the cursors "retriable on the next drain" docs/watcher-continuity.md:74.

Legacy migration. When the manifest does not exist but an older per-task open-decisions cursor does, the presentation offset is read from that older cursor bin/fm-classify-lib.sh:1319-1325.

Trace: one decision across two drains

The resolved line is usually written by Firstmate, not the worker: an answer sent with bin/fm-send.sh <task> --resolve-key <key> '<answer>' records the closure "at answer time". A worker self-closes only a blocker that cleared without an answer bin/fm-classify-lib.sh:424-427 bin/fm-wake-drain.sh:488.

Deleting a cursor

The open-decisions cursor is "safe to delete (forces one full re-fold)" AGENTS.md:147. The code agrees: a missing cursor means no version, which forces offset 0 and a fold of the whole current file bin/fm-classify-lib.sh:1139-1141. Deleting .status-presentation-cursor resets every task's presentation offset to 0, so the next drain re-prints all unread lines. The inventory does not call this file safe to delete, and this page does not either. Teardown retires one task's row with a filtered rewrite under the presentation lock, never by deleting the manifest bin/fm-classify-lib.sh:1503-1575.
