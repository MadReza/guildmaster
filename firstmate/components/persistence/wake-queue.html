Wake queue and recovery marker

A durable queue holds every actionable wake until the turn that handled it acknowledges it by sequence number. A one-line recovery marker ties watcher downtime, presentation, and acknowledgement to a single generation.

Read against Firstmate commit ada21f5b. Up: Persistence.

Problem solved

The watcher is deliberately one-shot. "One actionable reason closes one watcher cycle" docs/watcher-continuity.md:3. Between that close and the supervisor's next turn there is a window where the event exists only in a process that has already exited. The supervisor may be mid-turn, crashing, or restarting. The queue closes that gap. "The durable wake queue preserves actionable events during the residual active-turn window" docs/watcher-continuity.md:42. A wake leaves the queue only after the turn that handled it runs the acknowledgement that the drain printed. Presenting a wake never consumes it.

How the watcher decides what is actionable, and how each harness is re-armed, belongs to Supervision. This page covers the records.

Appending a wake

fm_wake_append <kind> <key> <payload> takes the queue lock and calls the locked core bin/fm-wake-lib.sh:1823-1829. The core does four things bin/fm-wake-lib.sh:1837-1871:

  1. It refuses any kind other than signal, stale, check, or heartbeat with exit 2.
  2. It flattens tabs, carriage returns, and newlines in the key and payload to spaces, so a row is always exactly one line with five fields bin/fm-wake-lib.sh:1819-1821.
  3. It publishes downtime on the recovery marker first. Every queued wake therefore belongs to a recovery generation before it is visible.
  4. It increments .wake-queue.seq and appends the row with >>.

Callers that must commit another record atomically with the wake hold the lock themselves and call fm_wake_append_locked directly. Holding the lock "excludes the drain's acknowledgement, which deletes consumed rows under the same lock" bin/fm-wake-lib.sh:1831-1836.

Producers. fm-watch.sh is the main one: stale rows for panes and check rows for slow polls and rejected checks bin/fm-watch.sh:426 bin/fm-watch.sh:2470-2478. The others are fm-inbox.sh, fm-mail.sh, fm-procevent.sh, fm-startup-network.sh, fm-inactive-reconcile.sh, fm-contributions.sh, fm-merge-outcome-lib.sh, and fm-push-transition-lib.sh. Each calls fm_wake_append rather than writing the file directly.

Note: the sequence file is not written atomically

.wake-queue.seq is written with a plain > redirect bin/fm-wake-lib.sh:1858-1862. That is safe from concurrent writers because it only happens under the queue lock. A torn or non-numeric value reads as 0, so after such damage sequence numbers restart low. The code does not guard against a restarted sequence colliding with rows still queued. The .wake-queue.seq file is also absent from the charter's state/ inventory.

Presenting: fm-wake-drain.sh with no arguments

Session start runs the drain as step 3. It presents the records "prominently as this turn's first work queue" AGENTS.md:192. A plain drain does this:

  1. Bounded lock. A presentation drain waits at most FM_STATUS_PRESENTATION_LOCK_TIMEOUT seconds (default 10) for the queue lock. On timeout it prints WAKE DRAIN SKIPPED, naming the holder pid, and changes nothing. An acknowledgement always blocks instead bin/fm-wake-drain.sh:11-12 bin/fm-wake-drain.sh:627-639.
  2. Repair. Main retires rows that lost their five fields or their numeric sequence, because such a row "can never be presented and can never be named by an --ack-through cutoff: left alone it wedges the queue for good". It prints up to 20 of them verbatim, because "the queue was their only durable record" bin/fm-wake-drain.sh:80-122 docs/watcher-continuity.md:85.
  3. Claim. Each row is claimed by exactly one actor. Main claims every row not granted to the Pi supervision branch. The branch presents only rows the extension granted it bin/fm-wake-drain.sh:44-64 docs/watcher-continuity.md:71-79.
  4. Enter a generation. A queue with no marker (a legacy queue) or an acked marker first gets a fresh downtime generation. The marker then moves to handling bin/fm-wake-drain.sh:809-827.
  5. Deduplicate. Rows with the same kind and key collapse to the newest, and all heartbeats collapse to one bin/fm-wake-lib.sh:1982-2006.
  6. Print. The raw rows, then WAKE_ACK_REQUIRED: after handling completes run bin/fm-wake-drain.sh --ack-through <max-seq> --recovery-generation <gen> bin/fm-wake-drain.sh:840-861. Status annotations, UNREAD STATUS, OPEN DECISIONS, and the other sections follow. Those are covered on Presentation cursors and folded decisions.

An empty queue with an unacknowledged downtime generation still requires an acknowledgement, --ack-through 0. Open decisions buried in status logs can then resurface after an outage even when no row is queued bin/fm-wake-drain.sh:763-786.

Acknowledging

The acknowledgement carries "two separable facts: queue-row consumption is bound to the monotonic --ack-through sequence ..., while only retiring the episode is bound to --recovery-generation" docs/watcher-continuity.md:62. Both arguments are validated before any lock is taken bin/fm-wake-drain.sh:196-207. Under the queue lock the drain then does the following bin/fm-wake-drain.sh:627-760:

  • Main re-claims before cutting. A row that arrived between presentation and acknowledgement is claimed now, so "a direct or replayed main ack still owns every unreserved row through its cutoff" bin/fm-wake-drain.sh:652-659.
  • It writes every row that is not both at or below the cutoff and owned by this actor to a temporary file bin/fm-wake-drain.sh:689-702.
  • If nothing remains, it acknowledges the marker. A generation mismatch is not fatal. It is reported as "a newer recovery episode is pending" together with its remedy bin/fm-wake-drain.sh:708-726 bin/fm-wake-drain.sh:756-758.
  • It renames the temporary file over .wake-queue. On failure it exits 1 with "acknowledged wakes could not be consumed safely" bin/fm-wake-drain.sh:727-730.
  • If the cutoff removed none of this actor's rows while a presented row above it is still waiting, it says so and prints the exact command for the current wake. This keeps a stale acknowledgement from turning into a loop of re-presenting the same row bin/fm-wake-drain.sh:739-755.

A concurrently appended wake has a higher sequence number, so it stays queued and "keeps the episode pending for presentation" docs/watcher-continuity.md:65.

The recovery marker .watcher-down

A recovery episode is "one generation of state/.watcher-down, and it is retired only by the generation-bound acknowledgement the drain prints" docs/watcher-continuity.md:57. Every write goes to a temporary file with mode 0600 and is renamed under the marker's own lock bin/fm-wake-lib.sh:651-663. A new generation is <pid>.<epoch>.<random suffix> bin/fm-wake-lib.sh:656. A marker that is not a single-line regular file with a valid token reads as invalid bin/fm-wake-lib.sh:630-645.

Trace: one status line to an acknowledged wake

If the supervisor dies between steps 7 and 10, nothing is lost. The row is still in the queue, and the marker still names generation G. The next session's drain presents the row again, and the marker moves the episode to "announced" so recovery is shown once docs/watcher-continuity.md:58.

Guarantees, failures, refusals

  • At least once, never silently dropped. Only an acknowledgement or the repair of a structurally unusable row removes a row. The repair prints the rows it removes bin/fm-wake-drain.sh:80-122.
  • Actor isolation. A branch acknowledgement "can never remove a row it was not granted, so it can never swallow a main-owned row" bin/fm-wake-drain.sh:58-62.
  • A failed repair is not fatal. A retirement that cannot be written is reported, and the usable rows are still presented docs/watcher-continuity.md:86.
  • Refuses under a lock refusal. A session without the session lock leaves the queue untouched AGENTS.md:198.
  • Refuses a malformed acknowledgement. A missing generation, a non-numeric sequence, or extra arguments exit 2 before any lock is taken bin/fm-wake-drain.sh:196-207.
Finding: an unused restore helper

fm_wake_restore_queue concatenates a drained file back in front of the live queue bin/fm-wake-lib.sh:1972-1980. No script under bin/ calls it at this commit. It appears to be left over from a destructive-drain design that the non-destructive presentation replaced. Whether tests still use it was not checked.

Never delete .watcher-down: the charter says "never touch" AGENTS.md:146. Deleting .wake-queue discards every unacknowledged wake, because the queue is the only durable record of those rows docs/watcher-continuity.md:85. See What is safe to delete.
