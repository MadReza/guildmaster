Durable memory

Three curated files are printed into every session start: captain preferences, shared captain preferences, and learnings. A token budget keeps them small. A cold archive takes what ages out, so nothing is deleted outright.

Inspect, then update

These files are curated, not journals. Before a change, "inspect the current file and curate the matching bullet in place"; add a new bullet "only for a genuinely new durable preference" docs/configuration.md:245. Learnings are "created lazily on first learning" and follow the same aging and archive contract, "curate it instead of appending forever" docs/configuration.md:251-252. This is the opposite of a status log. A status log is append-only because it is an event stream. A memory file is rewritten in place because it is a current operating map.

Tiers and decay

The /stow skill is the single owner of the scheme. "No memory file header may restate" it .agents/skills/stow/SKILL.md:48-49. In outline:

  • Markers. <!--a:YYYY-MM-DD--> marks an aging entry and <!--p:YYYY-MM-DD--> a perishable one. The date is when the entry was last reinforced. <!--P--> pins an entry in a file whose default tier is not pinned .agents/skills/stow/SKILL.md:21-25.
  • Defaults by file. Entries in the captain files default to pinned, "because preferences and authority boundaries do not age". Entries in learnings default to aging .agents/skills/stow/SKILL.md:45.
  • Horizons. An aging entry is stale after 30 days, a perishable one after 7. With the opt-in config/stow-pass-horizon flag, an entry is also stale after 10 passes (aging) or 3 passes (perishable) that evaluated it without reinforcing it .agents/skills/stow/SKILL.md:38-39 .agents/skills/stow/SKILL.md:70-71 docs/configuration.md:271-274.
  • Refusing destruction on missing evidence. "A pre-existing missing or hand-dropped marker is never grounds for destructive treatment" .agents/skills/stow/SKILL.md:53.

The startup memory budget

The budget is one positive base-10 integer followed by exactly one newline. The file must be regular and single-linked, beneath a config/ directory that is not a symlink. "Malformed, multi-line, symlinked, hardlinked, special, or otherwise unsafe values are rejected rather than treated as a default" docs/configuration.md:261-262. The locked primary bootstrap writes a visible default of 7500 when the file is absent. A secondmate never creates its own default. It receives the primary's value docs/configuration.md:258-260. The estimate is ceil(UTF-8 bytes / 3) per file, "a conservative portable approximation rather than a provider-exact tokenizer" docs/configuration.md:264. Commands: bin/fm-startup-memory-budget.sh read and … report docs/configuration.md:263.

A secondmate's inherited captain-shared.md counts against the secondmate's own total, even though the secondmate cannot edit it docs/configuration.md:265. Each home is measured against its own allowance, "rather than against a fleet total" docs/configuration.md:266.

The cold archive

"Stale never means deleted: pruning an entry from an editable memory file always means moving it to data/memory-archive.md, this home's append-only, never-injected cold tier". It is never counted by the budget report. Each archived entry keeps "source file, tier, last-reinforced date, and the reason it left" under a dated pass heading .agents/skills/stow/SKILL.md:134-137. "Truncating a grown archive is a captain decision, not a mechanism" .agents/skills/stow/SKILL.md:146. A unique current fact is never simply removed. It is either archived with provenance or moved to a live owner that loads it on demand .agents/skills/stow/SKILL.md:111.

How a /stow pass runs, and its automatic cascade to secondmates, belongs to Prompts and skills.
