Wake-drain surfaces

Beside the queued wake rows, every run of bin/fm-wake-drain.sh prints up to four fleet-wide sections, each built so that one specific kind of fact cannot be lost between wakes.

Where this runs

Firstmate must "drain the durable wake queue before peeking, reading beyond the reason line, steering, or starting work" at the start of every wake-handling turn (AGENTS.md:428). The drain has two forms: a plain presentation, and --ack-through <sequence> --recovery-generation <generation>, which consumes rows after they were handled (bin/fm-wake-drain.sh:196-208). The queue, its rows, the per-actor split between the main session and a Pi supervision branch, and the acknowledgement protocol are Supervision material. This page covers what a drain prints about status, which is the observability half.

The header lists the job in order: present wake records, retire unusable rows, optionally acknowledge, "annotate every unread line for validated signal status keys, surface unread informational status lines, latest captain-facing statuses not covered by a newer branch outcome, OPEN DECISIONS, and captain-call record divergence, then assert liveness" (bin/fm-wake-drain.sh:1-7).

One locked presentation, committed only after it is printed

  1. Lock. state/.status-presentation-lock is taken with a bounded wait, FM_STATUS_PRESENTATION_LOCK_TIMEOUT seconds (default 10). If a live process still holds it, the drain prints STATUS PRESENTATION SKIPPED: lock remains held by live pid ...; retry on the next drain. and presents nothing else about status (bin/fm-wake-drain.sh:11-12, bin/fm-wake-drain.sh:580-595).
  2. Snapshot. status_presentation_snapshot records task TAB size TAB identity for every readable, non-symlink status file. Every later read in this presentation stops at that captured size, so an append that lands mid-drain is left for the next one (bin/fm-classify-lib.sh:1206-1219).
  3. Annotate queued rows. For each queued signal row, fm_wake_print_annotations prints the status lines still unread since the last presentation, each prefixed wake annotation: unread wake-EVENT since last drain, not current state (bin/fm-wake-lib.sh:2364, bin/fm-wake-lib.sh:2432-2434). A turn-ended-only row whose status bytes were already surfaced or deliberately absorbed is not re-annotated, because replaying it "makes a bare turn-end look like fresh progress".
  4. Prepare, print, commit. The four sections below are written to a temp file. Only after cat succeeds does status_commit_presentation_snapshot advance the offsets: "If the consumer closes or fails, leave the receipt behind so the next drain can recover the presentation" (bin/fm-wake-drain.sh:551-578).

The receipt is one manifest, state/.status-presentation-cursor, one row per task: task, file identity, presented offset, and outcome-backstop offset (bin/fm-classify-lib.sh:1294-1370). A changed identity or an offset past the end reads that file from 0. docs/architecture.md summarises it as a manifest that "records each status file's identity plus independent annotation and outcome-backstop byte offsets" (docs/architecture.md:104).

All four are silent when empty, "which is the common case". A section cut by its byte budget ends with a ... N more omitted (byte cap) line, so an omission is visible (bin/fm-wake-drain.sh:442-489).

UNREAD STATUS

status_line_is_unread_surface admits exactly two kinds of line: a note:, and a resolved or captain-held line on a reserved pending-reply- key whose note speaks that namespace. "Those lines never fold into OPEN DECISIONS, so the drain's unread-status surface is their only guaranteed presentation" (bin/fm-classify-lib.sh:1784-1808). The section runs on every drain, "including the empty-queue fast path - so a buried answer cannot be swallowed when the fold later advances the cursor" (bin/fm-wake-drain.sh:397-427). Its heading promises the lines are "not re-printed after this presentation", and the agent contract repeats that they "must be read this turn" (AGENTS.md:431).

STATUS OUTCOME BACKSTOP

This section exists for the Pi supervision branch, which handles fleet events on the main session's behalf and records each outcome in state/branch-outcomes.jsonl before delivering it (bin/fm-branch-outcome.sh:1-60). If a wake row is acknowledged but the branch never produced a covering outcome, the event could vanish. The drain therefore compares each task's newest non-blank event with the latest outcome that causally covers that task's log (docs/pi-supervision-branch.md:86-96).

  • It runs only for the main actor (bin/fm-wake-drain.sh:307).
  • It reads at most the final 64 KiB of each log through the captured endpoint, and defers a file that changes during the read. A latest line longer than that window is "intentionally unclassifiable and omitted" (bin/fm-classify-lib.sh:1221-1232).
  • Only a captain-relevant event qualifies. A parseable keyed needs-decision or blocked is skipped because it "belong[s] exclusively to the durable fold"; resurfacing a rejected reserved-key transition here "would let a foreign writer bypass the namespace guard". A line with malformed key syntax has no fold representation, so the backstop is its only presentation (bin/fm-wake-drain.sh:343-350).
  • Coverage is read from a fixed-size per-task index, state/.<task>.branch-outcome-index (at most 512 bytes), not by scanning outcome history. If the ready marker is missing the drain rebuilds the indexes with fm-branch-outcome.sh processed-init --held-lock under the outcome lock (bin/fm-wake-drain.sh:252-330).
  • Failures are named, never silent: STATUS OUTCOME BACKSTOP SKIPPED: branch outcome history could not be read safely, ... is busy; retry on the next drain, ... indexes could not be rebuilt, ... a bounded task outcome index could not be read safely (bin/fm-wake-drain.sh:313-325, bin/fm-wake-drain.sh:385).

Legacy outcome rows carry no status provenance, so when an event and an outcome share a timestamp second the drain "deliberately favors surfacing a plausibly later event; this can rarely duplicate an already handled legacy event" (docs/pi-supervision-branch.md:93).

OPEN DECISIONS

Built from the cursor-backed fold described on Status events and the keyed fold, and deliberately "rather than from the annotations above, so a decision buried under later unrelated appends cannot be silently missed" (bin/fm-wake-drain.sh:429-443). Each line is <task> [key=<key>] <verb>: <note>, with the key omitted when it is default. The section ends with the one action that closes an item, printed "at exactly the moment an answer gets written" (bin/fm-wake-drain.sh:484-488):

OPEN DECISIONS: close one by answering it: bin/fm-send.sh <task> --resolve-key <key> '<answer>'

fm-send.sh then appends the closing resolved line itself, so closure "never depends on the busy worker writing a matching resolved line", and after a delivered close it re-folds and fails loudly if the key is still open (bin/fm-send.sh:154-176). The agent contract treats this section as "actionable reconciliation input even when no wake record was queued" (AGENTS.md:430).

RECORD DIVERGENCE

A captain call has two records: the keyed decision in a status log, and a backlog task held for the captain. They are closed by separate acts. "Closing only on the status side therefore looks complete there while the durable record still says the captain owes an answer and keeps resurfacing it. The defect was never the separation; it was the silence" (bin/fm-captain-hold.sh:1736-1739).

The drain runs bin/fm-captain-hold.sh diverged under FM_DIVERGENCE_TIMEOUT (default 20 seconds) and prints one line per pair (bin/fm-wake-drain.sh:491-549). The command flags only a task that is still open and still carries captain-hold annotations whose key the status side closed with resolved. A captain-held close is not a divergence, because that verb is written only after verifying the transfer to that very task (bin/fm-captain-hold.sh:1748-1754). It compares status logs and backlog only when both belong to the same home, and stays silent if tasks-axi is missing or its listing cannot be parsed (bin/fm-captain-hold.sh:1802-1817).

It closes nothing: "A captain call closed wrongly disappears without review, which is strictly worse than the noise this prints" (bin/fm-captain-hold.sh:1741-1747). The drain's closing line names both directions of repair, recording the captain's words with answer or re-opening the status decision, and the agent contract says to treat it "never as proof the captain ruled" (AGENTS.md:432). The captain-hold lifecycle itself is documented under Backlog and decisions.

The liveness assertion

After presenting, the drain runs bin/fm-guard.sh so that "a lapsed supervision chain then surfaces on a plain drain-and-handle turn". A guard hiccup never changes the drain's exit status (bin/fm-wake-drain.sh:212-225). What the guard checks is Supervision material.

Failure behaviour

  • A presentation that cannot snapshot prints STATUS PRESENTATION INCOMPLETE: status snapshot could not be read. and commits nothing (bin/fm-wake-drain.sh:596-598).
  • If printing or committing fails, the prepared file is discarded and the receipt stays where it was, so the same lines are presented again next time (bin/fm-wake-drain.sh:565-576).
  • A divergence guard that times out or errors prints nothing and does not fail the drain, because "a supervision turn must still present its wakes when the backlog tool is having a bad day" (bin/fm-wake-drain.sh:499-503).
  • The incremental fold returns its last trusted set on an I/O error rather than an empty one (Status events).

Configuration

FM_STATUS_PRESENTATION_LOCK_TIMEOUT
Positive whole seconds to wait for the presentation and outcome locks; default 10, and a non-positive value falls back to 10 (bin/fm-wake-drain.sh:41-42).
FM_DIVERGENCE_TIMEOUT
Bound on the divergence guard; default 20 seconds (bin/fm-wake-drain.sh:510-512).
FM_CAPTAIN_RE, FM_CLASSIFY_RESOLVE_VERB, FM_CLASSIFY_CAPTAIN_HELD_VERB, FM_CLASSIFY_RESERVED_KEY_PREFIXES
Vocabulary overrides read by the classifier that every section uses.
