Bearings snapshot and board

Bearings is the captain's "pick up where I left off" report: one bounded, deterministic command produces the fleet facts, the agent ranks and words them into four fixed sections, and an optional interactive board lets the captain answer decisions in place.

The problem it solves

After a break, a night or a context reset, the captain needs the whole fleet in one read. The skill's goal is a "complete current snapshot from the fleet's current state, so the captain can resume in one read" (.agents/skills/bearings/SKILL.md:16). The risk is an agent that stitches that picture together from whatever it remembers, recent chat, or old reports. Bearings removes that by making the fact-gathering one command and forbidding every other source: "Do not create or consult a second fleet-state reader, parser contract, status-event-tail interpretation, visible-session recap, ad-hoc project probe, or ad-hoc gh-axi/gh query" (.agents/skills/bearings/SKILL.md:42-43).

The canonical fleet snapshot

bin/fm-fleet-snapshot.sh --json prints one fm-fleet-snapshot.v1 object. It "does not acquire the session lock, drain wakes, arm watchers, mutate backlog state, or write reports"; its only fleet-state mutation is atomically refreshing cached copies of remote home summaries under state/secondmate-summary-cache (bin/fm-fleet-snapshot.sh:1-10). Its header is the field contract: backlog records with normalised captain-hold fields, one tasks[] row per meta record, scout_reports[], main_inventory, secondmate_current, secondmate_landed, and contributions (bin/fm-fleet-snapshot.sh:12-118). "Human views must render this output instead of parsing state files again" (bin/fm-fleet-snapshot.sh:118).

How it stays honest about time and identity:

  • A task's current state comes from bin/fm-crew-state.sh <id>; its last status event is kept as paths.status_log.last_event, "historical wake-event data only, never current state", with age_seconds derived only from the [at=] tag and null when that is unknown (bin/fm-fleet-snapshot.sh:54-62).
  • hints.open_decisions is the output of the keyed fold (Status events), reconciled against current state (bin/fm-fleet-snapshot.sh:63-66).
  • Task records are captured at start. If a task's spawn_gen changes while observations run, the mutable evidence is discarded "rather than attributed to the replacement generation" (bin/fm-fleet-snapshot.sh:50-53).
  • For a secondmate, structured facts from its own home win; parent status and terminal reads are "historical, untrusted supplements only" (bin/fm-fleet-snapshot.sh:78-82).

Every cross-home read has an explicit bound "so one broken or unexpectedly large home cannot hang or explode the parent snapshot" (bin/fm-fleet-snapshot.sh:152-153). The main ones: all concurrent remote ledger reads share one FM_SNAPSHOT_BUDGET of 5 seconds; each crew-state read has 10 seconds; at most 20 secondmates, 20 children and 20 decisions per home; terminal reads are capped at 8 lines, 4096 bytes and 2 seconds (bin/fm-fleet-snapshot.sh:155-174, docs/configuration.md:1116). An observation date can be pinned with FM_SNAPSHOT_NOW (bin/fm-fleet-snapshot.sh:135).

Captain-hold buckets

Every captain-held backlog row gets exactly one hold_bucket, decided "only from structured fields" and never from hold reason or body prose: blocked if any blocker is unresolved, else dated while hold_until is in the future, else aged once an undated hold is at least FM_SNAPSHOT_UNDATED_HOLD_AGE_DAYS old (default 14), else live. captain_actionable is exactly hold_bucket == "live" (bin/fm-fleet-snapshot.sh:28-45). Aging "is a projection safety net only: the durable deferral remains re-holding with --until".

The Bearings projection

bin/fm-bearings-snapshot.sh is "a thin wrapper OVER the canonical bin/fm-fleet-snapshot.sh. It does not parse fleet state itself" (bin/fm-bearings-snapshot.sh:1-12). It projects the complete snapshot down to what a resume read needs and renders TOON by default, with --json as the parity form. The projection drops fields from its own output only; it never weakens the canonical snapshot.

How the read stays bounded and deterministic

One source
It shells out once to fm-fleet-snapshot.sh --json (bin/fm-bearings-snapshot.sh:234-241) and fails with "invalid canonical snapshot" if that output is not usable (bin/fm-bearings-snapshot.sh:243-244).
A pinned clock
NOW comes from FM_BEARINGS_NOW or the current UTC time, and is passed down as FM_SNAPSHOT_NOW, so both layers observe the same instant (bin/fm-bearings-snapshot.sh:233).
Explicit bounds
Each surface has a positive-integer cap validated at start: 6 landed rows (and per home), 20 in-flight, decisions, secondmates, gates, reports, recorded PRs and unhealthy endpoints (bin/fm-bearings-snapshot.sh:106-132).
Disclosed omissions
Anything cut by a bound, or not requested, is listed in omitted[] with the flag that reveals it, "so an absence is never ambiguous" (bin/fm-bearings-snapshot.sh:17-21, bin/fm-bearings-snapshot.sh:654-680).
No forge by default
Live GitHub discovery and checks run only under --include-prs; "all gh coupling lives in that branch and never in the canonical snapshot" (bin/fm-bearings-snapshot.sh:14-21).
No writes
"No locks or reports; the underlying snapshot's parent-side remote-ledger cache refresh is the only default fleet-state mutation" (bin/fm-bearings-snapshot.sh:92-93).

Default fields are schema, home, generated, prs, in_flight, secondmates, secondmate_reconcile, decisions_open, landed, gates, reports, recorded_prs, unhealthy_endpoints, omitted (bin/fm-bearings-snapshot.sh:148-155). Opt-in flags reveal more: --fields bodies,paths,actions,endpoints and the --all-* family (bin/fm-bearings-snapshot.sh:76-90).

Projection rules worth knowing

  • Each Underway row's name is the durable task title, or the task id when the title is blank, never the run status (bin/fm-bearings-snapshot.sh:28-32).
  • A live hold is a Captain's Call entry. blocked, dated and aged holds become Charted Next gates stating why, counted in omitted[]; --all-decisions moves them back and drops the gate, so no hold is in both (bin/fm-bearings-snapshot.sh:36-46).
  • Gates are ordered newest filed first before the bound is applied (bin/fm-bearings-snapshot.sh:49-51).
  • A broken main inventory, such as an in-flight backlog row with no meta, becomes an omitted[] entry and a (main-inventory) gate, "so the four-section chat cannot claim an empty fleet while main current state is broken" (bin/fm-bearings-snapshot.sh:54-58).
  • Landed work merges this home's Done rows with each secondmate's own Done rows, balanced across homes by default (bin/fm-bearings-snapshot.sh:66-75).
  • Only scout reports belonging to live or recently landed tasks are shown by default; --all-reports shows the full inventory (bin/fm-bearings-snapshot.sh:450, bin/fm-bearings-snapshot.sh:578-581). See Scout reports.
  • Contributions contribute only their captain rows, with counts for the other actors (bin/fm-bearings-snapshot.sh:24-26). See Contribution tracking.

Away mode

Before collecting, the projection asks bin/fm-afk-return.sh guard. An active away window refuses the whole read, "because the right answer there is to run the return first". An open return catch-up (exit 4) is reported as content: a single action-free (return-catchup) gate naming the blockers left (bin/fm-bearings-snapshot.sh:209-231). Away mode itself is Supervision material.

The four-section digest

The bearings skill is "the one owner of the /bearings chat-response format" (.agents/skills/bearings/SKILL.md:147). Every response has exactly these sections in this order, each always present with a fixed empty-state sentence:

  1. Captain's Call: only items needing the captain's own action now. "Nothing needs your action right now" is allowed only when contributions.proven_clear is true and no decision is recorded.
  2. Recently Landed: the bounded current baseline, rendered in full every time.
  3. Underway: one line of current state per direct report.
  4. Charted Next: queued or gated work and action-free integrity warnings.

(.agents/skills/bearings/SKILL.md:148-161.) "Every chat digest and file-mode report is a complete current snapshot, never a delta against a prior report", and file mode must never read an earlier data/status-report-*.md to decide what to include (.agents/skills/bearings/SKILL.md:166, .agents/skills/bearings/SKILL.md:81). The strict boundary keeps action-free items, such as a validating task, a declared paused: wait, or a completed scout's report pointer, out of Captain's Call (.agents/skills/bearings/SKILL.md:171).

Modes: plain /bearings is chat only; /bearings file replaces today's data/status-report-<YYYY-MM-DD>.md from scratch; /bearings lavish also builds the board. Natural-language requests such as "save this" do not switch modes (.agents/skills/bearings/SKILL.md:26-33). During an invocation the skill never tears down, merges, dispatches, steers, answers a decision or mutates backlog state (.agents/skills/bearings/SKILL.md:21-22). The one side effect it may record is a reconcile request for a secondmate whose own books disagree, through bin/fm-secondmate-reconcile.sh request --snapshot -, which records and returns without sending (.agents/skills/bearings/SKILL.md:64-71).

The interactive board

bin/fm-bearings-board.sh build <data.json> owns every board mechanic, so the agent's per-run work is only "compose the JSON, run build" (bin/fm-bearings-board.sh:1-8). The payload schema is fm-bearings-board.v1; the template is .agents/skills/bearings/assets/board-template.html; the board always lives at $FM_HOME/.lavish/bearings-board.html, so a rebuild keeps the same session URL and the same process-event source id (bin/fm-bearings-board.sh:82-87, bin/fm-bearings-board.sh:112).

What build guarantees, in order (bin/fm-bearings-board.sh:14-47):

  1. Fail-closed validation. Every renderer-consumed field must satisfy the schema, including an explicit repo on every row and a non-empty name on every Underway row; anything else "refuses before the existing board is touched" (bin/fm-bearings-board.sh:66-80).
  2. Captain's Call hygiene. A card is dropped when its task, PR or versioned artifact appears among the payload's own landed rows, or when fm-captain-hold.sh open says it is no longer an open call. A task whose state cannot be established is kept, "because a call wrongly hidden is worse than a card wrongly shown". Each drop is named on stderr as dropped-landed-card: (bin/fm-bearings-board.sh:49-55, bin/fm-bearings-board.sh:321).
  3. The reconcile choice. Every decision card gets a standard reconcile option injected by the script, and the validator reserves that value on every card type (bin/fm-bearings-board.sh:57-64).
  4. Serve first, then prove live. lavish-axi <file> exits 0 even when it refuses to reopen a session the captain ended, "so exit status alone cannot tell a live board from a dead one". build requires the server's fresh session listing to show the board open and refuses otherwise (bin/fm-bearings-board.sh:39-47).
  5. Bind before arm. The board is bound to the keyed-answer intake in bin/fm-captain-hold.sh before its listener is armed, "so the board can never produce an answer that has nowhere to go" (bin/fm-bearings-board.sh:21-25).

Injection escapes every < in the JSON as <, so a string containing </script> cannot end the data block (bin/fm-bearings-board.sh:82-86).

When the captain answers

An answer arrives as a procevent lavish <source-id> <sequence> wake. The runner has already fed decision answers into the keyed-answer intake, which closes or releases each captain-held task at answer time; the agent handles skipped: keys, merge orders and dispatch picks itself, then rebuilds the board from a fresh snapshot (.agents/skills/bearings/SKILL.md:122-137). A merge click is the captain's explicit merge word for that one PR, but only after re-verifying at wake time that the PR (resolved from the task's own meta, never from board bytes) is still open and green, and recording the answer before merging through bin/fm-pr-merge.sh (.agents/skills/bearings/SKILL.md:139-143). A Reconcile selection closes nothing; it becomes a durable re-check request (.agents/skills/bearings/SKILL.md:126-128). Captain-hold semantics belong to Backlog and decisions; the merge path to Delivery.

Failure behaviour

  • Missing jq: the projection exits 1 (bin/fm-bearings-snapshot.sh:207). A non-positive bound exits 2 (bin/fm-bearings-snapshot.sh:119-121).
  • A guard failure other than the catch-up code is passed through unchanged (bin/fm-bearings-snapshot.sh:219-222).
  • A gh call under --include-prs is bounded by FM_BEARINGS_PR_TIMEOUT (default 20 s) (bin/fm-bearings-snapshot.sh:117-118).
  • An unreadable secondmate home is reported as unreadable with provenance, never as empty (bin/fm-bearings-snapshot.sh:161-165).
  • A board whose session cannot be proven live is not armed (bin/fm-bearings-board.sh:39-47).
