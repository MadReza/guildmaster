Status events and the keyed fold

Every task reports through one append-only file of event lines; bin/fm-classify-lib.sh owns the grammar of those lines, decides which of them firstmate must see, and folds the whole stream into the set of decisions that are still open.

What the status log is

Each task has one file, state/<id>.status, described in the home layout as "append-only wake events, not current-state truth; bin/fm-classify-lib.sh owns their syntax" (AGENTS.md:103). A worker appends a line with a plain shell redirect. The launch brief gives the exact shape, echo "{state} [at=<epoch>]: {one short line}" >> $STATUS_FILE, and tells the worker to report only phase changes a supervisor would act on (bin/fm-brief.sh:516).

The worker is not the only writer. Each of these appends into the same stream:

  • bin/fm-send.sh --resolve-key <key> appends the closing resolved line when firstmate answers a decision (bin/fm-send.sh:154-176).
  • bin/fm-captain-hold.sh, inside a secondmate home, publishes needs-decision [key=captain-hold-<task>-<n>] and the matching resolved line on the parent channel (bin/fm-captain-hold.sh:194-201).
  • bin/fm-secondmate-report.sh writes the bracketed [corr=<16 hex>] form, and a remote secondmate's lines are mirrored into the parent stream verbatim (bin/fm-classify-lib.sh:452-454, bin/fm-classify-lib.sh:624-627).

The file is never rewritten. The incremental fold below relies on that: "every one is created once (>) and only ever appended to (>>) - never replaced, renamed, or rewritten in place" (bin/fm-classify-lib.sh:941-944). How lines travel to firstmate, and how the watcher notices an append, belongs to Communication and Supervision.

Line grammar

A status line is <verb> [<tags>...]: <note>. The verb is the text before the first colon, cut at the first [, so any number of bracketed [name=value] tags may sit before the colon in any order (bin/fm-classify-lib.sh:447-449, bin/fm-classify-lib.sh:506-535). Lines that carry no recognised verb, such as continuation prose or blanks, are skipped by the event scan, which returns the last recognised event rather than the last line (bin/fm-classify-lib.sh:155-181).

needs-decision [key=api-shape] [at=1788576000]: REST or gRPC for the new endpoint?
resolved [key=api-shape] [at=1788576300]: answered: use REST
needs-decision corr=0123456789abcdef [key=texte-du-mur]: wording for the banner
paused [at=1788577000]: waiting on upstream release until 2026-09-24T15:00Z

The captain-relevant set is the regular expression done:|needs-decision:|blocked:|failed:|PR ready|checks green|ready in branch|merged (bin/fm-classify-lib.sh:78). The free-text tokens exist only for legacy lines that lack a standard verb, and status_is_captain_relevant refuses them when the line leads with working, resolved, captain-held or paused (bin/fm-classify-lib.sh:204-228). A home can replace the whole set with FM_CAPTAIN_RE; the verbs paused, resolved and captain-held each have their own override variable (bin/fm-classify-lib.sh:67-71, bin/fm-classify-lib.sh:128-129).

The emission-time tag [at=<epoch>]

New writers may put [at=<epoch>] before the first colon. The value must be canonical unsigned decimal of at most 12 digits; anything missing, malformed or duplicated means the time is unknown (bin/fm-classify-lib.sh:284-297). The same header states the rule this whole area rests on: "never infer emission time from file mtime, a wake, or observation time", and "Time describes event history only and must never decide current state or decision closure" (bin/fm-classify-lib.sh:291-294).

Two different strippers exist on purpose. _fm_status_untimed removes only a well-formed tag, so a retry of an event is recognised as the same bytes (bin/fm-classify-lib.sh:348-370, bin/fm-classify-lib.sh:398-411). _fm_status_unstamped removes every tag-shaped run before the first real colon however malformed, so a worker who wrote [at=10:30] or left the placeholder <epoch> unsubstituted cannot move the head/note boundary and cannot hide a terminal event from its supervisor (bin/fm-classify-lib.sh:372-396). status_stamp_line stamps only a newly emitted line and never a copied historical one (bin/fm-classify-lib.sh:317-331); status_stamp_width tells a writer that caps a line how many characters the stamp will add (bin/fm-classify-lib.sh:334-346).

Decision keys [key=<slug>]

An optional key names a decision. It is accepted in two positions: between the verb and the colon, or as the first thing in the note. The second position exists because "that misplaced-colon shape is common real worker output whose stated key must never silently collapse into the shared 'default' bucket (issue #2109)" (bin/fm-classify-lib.sh:430-438). When both positions carry a token the before-colon one wins; a token deeper in the note is prose and can neither open nor close anything (bin/fm-classify-lib.sh:439-442). A line with no key uses the key default, which keeps the old one-open-decision-per-task behaviour. A stated slug outside A-Za-z0-9._- is rejected, and the line is skipped by the folds rather than rewritten to default (bin/fm-classify-lib.sh:443-446, bin/fm-classify-lib.sh:560-566).

Correlation tokens

A secondmate answering a marked request echoes an unbracketed corr=<16 hex> token between the verb and the key, for example resolved corr=<16 hex> [key=texte-du-mur]: .... Without special handling the verb would parse as resolved corr=..., match no fold rule, and "a captain decision goes silently missing" (bin/fm-classify-lib.sh:454-465). status_line_verb therefore drops exactly that token shape, and nothing else, after the first word (bin/fm-classify-lib.sh:506-535). The recognition is deliberately narrow: skipping any name=value word would let prose such as resolved x=1 [key=k]: ... impersonate a transition (bin/fm-classify-lib.sh:473-484). The token grammar is owned by bin/fm-pending-reply-lib.sh; this file states the shape a second time and a test pins the two together (bin/fm-classify-lib.sh:467-471).

Reserved key namespaces

A key beginning pending-reply- belongs to one library that alone may open and close it. Because every writer, local or remote, reaches the same stream, a foreign line could otherwise take the key over and "permanently block the owner's close" or clear the owner's decision with a bare resolution (bin/fm-classify-lib.sh:622-630). The fold accepts a transition on a reserved key only when its note begins with <namespace>...:; any other line is ordinary status (bin/fm-classify-lib.sh:631-656). The rule is consumer-side on purpose, so it "can never fail a whole delta or wedge a stream the way a writer-side rejection would" (bin/fm-classify-lib.sh:632-638).

The keyed open/resolved fold

Reading the log "last-event-wins" cannot represent "an earlier decision is still open after a later, unrelated event": a later done, paused or working line "silently masks a still-open needs-decision" (bin/fm-classify-lib.sh:413-419). status_open_decisions is "the ONE authoritative statement of the status-fold contract that fixes this" (bin/fm-classify-lib.sh:417-420). The per-line rule lives only in _fm_decision_fold_line, which both the whole-file fold and the incremental fold call (bin/fm-classify-lib.sh:615-621).

The rule, in the order the code applies it (bin/fm-classify-lib.sh:678-723):

  1. Declaration guard. A line with neither a colon nor a complete [key=...] token is continuation prose and cannot move the set. The test runs on the unstamped copy, so a worker-written [at=10:30] cannot make prose look like a transition.
  2. Terminal supersede. A done: or failed: line on a ship or scout task returns an empty set: every open key closes. The task kind comes from kind= in the sibling .meta, defaulting to ship; a missing or unreadable meta yields unknown, which does not supersede (bin/fm-classify-lib.sh:666-676). A secondmate's terminal event "may describe other work and cannot close an unrelated decision" (bin/fm-classify-lib.sh:422-423).
  3. Verb filter. Only needs-decision, blocked, resolved and captain-held continue.
  4. Key. An invalid stated slug drops the line. A reserved key without its namespace vocabulary drops the line.
  5. Transition. An opener drops any record for the key and appends key TAB verb TAB note; a closer drops the record.

Output is one tab-separated <key>\t<verb>\t<summary> line per open decision, most recently opened last (bin/fm-classify-lib.sh:725-754). The set is plain text, not an associative array, so the fold runs on bash 3.2 (bin/fm-classify-lib.sh:601).

Finding: the worker brief and the fold disagree about done

The ship brief tells every worker: "A decision or blocker you opened stays open until a resolved line carrying its exact key lands; a later done: or working: line never closes it, even when the answer is what started that work" (bin/fm-brief.sh:536; the scout brief carries the same sentence at bin/fm-brief.sh:445). The fold does close it: a done: or failed: line on a ship or scout task empties the open set (bin/fm-classify-lib.sh:700-702), and bin/fm-crew-state.sh repeats "Ship/scout terminal declarations supersede stale log decisions" (bin/fm-crew-state.sh:115-118). The working: half of the brief's sentence matches the code; the done: half does not. The practical effect is that a ship worker who writes done: without first resolving an open question removes that question from OPEN DECISIONS. Whether the brief or the fold states the intended contract is not settled by the source; the fold's version history records the terminal rule as a deliberate change (version 6, bin/fm-classify-lib.sh:985-987).

Readers built on the fold

status_current_line <file> <kind>
Returns the most recently opened still-open decision as <verb> [key=<key>]: <note>, or the latest event when nothing is open. bin/fm-crew-state.sh uses it so "open decisions survive unrelated events and continuation prose cannot hide a declaration" (bin/fm-classify-lib.sh:756-771, bin/fm-crew-state.sh:115-117).
status_has_open_needs_decision <file> [<run-id>]
True only while a needs-decision (not blocked) is open. With a run id it matches only the key nm-<run-id>-<step>, so an unrelated earlier question is never read as this validation gate's escalation (bin/fm-classify-lib.sh:773-802).
status_key_closing_verb <file> <key>
Prints the verb that last moved a key: the opener while open, resolved or captain-held once closed, nothing if never stated. The difference between the two closers is what the RECORD DIVERGENCE surface tests. A grep pre-selects candidate lines so the cost is the log's transitions, not its lifetime length (bin/fm-classify-lib.sh:824-887).
scan_open_decisions <state>
Walks every *.status in a state directory, rejecting symlinks, and prefixes each open decision with its task id (bin/fm-classify-lib.sh:889-911). The fleet snapshot publishes the same fold as hints.open_decisions (bin/fm-fleet-snapshot.sh:63-66).

The incremental, cursor-backed fold

The whole-file fold re-reads a task's whole lifetime on every call. The drain runs a fleet-wide scan on every wake, so it uses status_open_decisions_incremental, which folds only the bytes appended since its own last call into a persisted open set (bin/fm-classify-lib.sh:913-927). Its correctness invariant: "cursor advancement, age, and being buried under later appends never drop an open decision" (bin/fm-classify-lib.sh:928-932).

The cursor is a hidden sibling file, state/.<task>.open-decisions-cursor, holding version=<fold-version>:<kind>, offset=, ident= (device and inode), then the folded set. It is written atomically by temp file and rename (bin/fm-classify-lib.sh:934-937, bin/fm-classify-lib.sh:1172-1180). It is thrown away and rebuilt from byte 0 when the fold version or task kind changes, when the file shrank, or when device and inode differ. A same-inode, same-size in-place edit is not detected, "a deliberately accepted gap because no code path in this repo ever does that to a status file" (bin/fm-classify-lib.sh:941-953). If its own stat, wc or read fails, it returns the already-trusted set unchanged rather than an empty set (bin/fm-classify-lib.sh:954-959, bin/fm-classify-lib.sh:1120-1127).

FM_OPEN_DECISIONS_FOLD_VERSION is currently 9, and the comment above it is a changelog of fold semantics: bracketed tags ending the verb (4), correlation tokens (5), terminal supersede and kind in the version (6), terminal rule only with a colon (7), colonless lines without a key are not transitions (8), colon tests on the unstamped copy (9) (bin/fm-classify-lib.sh:977-997). The number must be bumped with any semantic change so persisted state from an older interpretation is discarded.

This is the library's second documented exception to its pure-read rule, after the absorb classification (bin/fm-classify-lib.sh:30-40). A test-only seam, FM_OPEN_DECISIONS_READ_PROBE, records how many bytes each call folded, so a test can prove the cost stays bounded by new appends (bin/fm-classify-lib.sh:1156-1161).

Classifying events for wakes

The library header says it is sourced by both the always-on watcher and the away-mode daemon "so the overlapping triage policy lives in one place instead of two copies that can drift apart" (bin/fm-classify-lib.sh:1-8). The watcher and daemon themselves are documented under Supervision; the classification primitives are these.

The absorb rule is positive-evidence-only: absence of evidence always leaves the caller's escalation schedule untouched (bin/fm-classify-lib.sh:2134-2143, bin/fm-classify-lib.sh:2240-2243). A declared pause is re-surfaced once every FM_PAUSE_RESURFACE_SECS, four hours by default, because an hourly recheck "only produced nagging (the 2026-09-07 away-window audit)" (bin/fm-classify-lib.sh:93-106).

Span classification and the presentation marker

For a wake, the question is not "what is the latest line" but "what did this append say". status_span_first_actionable_record captures one size-and-identity endpoint and reports every actionable event from a start offset up to it, joined in source order with ; , so the caller reports the complete span before committing its endpoint (bin/fm-classify-lib.sh:1919-1942). A keyed opener is included only if the whole-file fold still names it as live; a reserved-key transition the fold rejects is surfaced as a reconciliation signal instead. Return codes separate "actionable" (0), "nothing actionable" (1) and "could not classify" (2, no committable endpoint).

The library header states the marker discipline that goes with it: a presentation marker stores the last reported file signature and the last successfully classified position separately. After a failure only the reported signature advances, "so the same observed state alarms once while every unclassified byte remains for recovery", and a missing or suspect position reads from byte 0, "preferring a bounded duplicate over a lost event" (bin/fm-classify-lib.sh:15-28).

The phase fold, which is evidence only

status_open_activities runs a second fold over the same stream: a working or paused event opens a phase for its key, and a later terminal, decision or resolved event with that key closes it. Its own comment limits it: "It is never authoritative current crew state, and consumers must not let an open phase outrank a structured home snapshot or fm-crew-state result" (bin/fm-classify-lib.sh:1852-1860). The secondmate charter's matching rule is to close a keyed phase with resolved [key=<work-slug>] when it ends without another reportable state (bin/fm-brief.sh:339).

What this component refuses to do

  • It never infers current state from a tail of the log; that is bin/fm-crew-state.sh's job (bin/fm-crew-state.sh:1-12). See Event is not state.
  • It never lets a time tag decide state or closure (bin/fm-classify-lib.sh:293-294).
  • It never widens token recognition beyond what a firstmate library actually writes (bin/fm-classify-lib.sh:473-484).
  • It never rejects a writer's line; bad lines are simply not transitions, so one malformed append cannot wedge a stream (bin/fm-classify-lib.sh:632-638).

Who depends on it

  • Wake-drain surfaces: OPEN DECISIONS, UNREAD STATUS, the outcome backstop and record divergence are all built from these readers.
  • bin/fm-crew-state.sh, the current-state reader, reconciles the log through status_current_line.
  • bin/fm-fleet-snapshot.sh and so Bearings publish the fold as hints.open_decisions.
  • bin/fm-captain-hold.sh diverged uses status_key_closing_verb.
  • The watcher and the away-mode daemon (Supervision) use the classification and absorb primitives.
