Event is not state

The rule Firstmate repeats more than any other in this area: a line that says something happened is history, and deciding what to do next needs a separate read of what is true now.

The rule as the source states it

  • "A state/<id>.status line is a wake event, not current-state truth; bin/fm-crew-state.sh owns current-state reconciliation" (AGENTS.md:163).
  • "A status line is a wake event, not current state; use bin/fm-crew-state.sh when current state matters, especially before re-escalating an old decision, blocker, or pause" (AGENTS.md:434).
  • "Crew status files are append-only wake-event logs, not current-state fields" (docs/architecture.md:102).
  • The current-state reader explains why: crews "append only wake-worthy transitions ... and nothing when they silently resume, so tail -1 of that log reports the last EVENT, not the current STATE" (bin/fm-crew-state.sh:4-9).

The same caveat is printed on every surface that shows raw events: the session-start digest labels each status tail "wake-EVENT history, not current state" (bin/fm-session-start.sh:529), drain annotations say "wake-EVENT observed at drain, not current state" (bin/fm-wake-lib.sh:2432), and the inbox view ends with "the last event line is history, not current state" (bin/fm-inbox.sh:1072).

The general shape of the guard

Every guard above follows one of three patterns.

Fold, do not tail
Where the question is "what is still owed", the answer is a fold over the whole stream with explicit open and close verbs, not the last line: the keyed decision fold.
Reconcile against a source that cannot go stale
Where the question is "what is this worker doing", the log is reconciled against evidence that changes by itself when the world changes: a run step, a pane, a worktree write, a forge read. bin/fm-crew-state.sh is the owner, and it reports which source won (bin/fm-crew-state.sh:22-24).
Label the history
Where raw events must be shown, the surface says so in its own text, as the digest, annotations and inbox view do.

The captain-facing version of the rule is in the process-event skill: "A wake is not news by itself. Report what the source actually produced and what it changes, never the event line, the result path, or the runner" (.agents/skills/process-event-sources/SKILL.md:166-167).

An inconsistency worth knowing

The inbox view reads the last event with tail -1 (bin/fm-inbox.sh:1067), which is the raw last line, not last_status_line's last recognised event. A trailing line of continuation prose would therefore be shown as the "last event". The view does label it as history, so no decision is taken from it, but it is the one place found in this area that reads the log by raw tail rather than through the classifier.
