Contribution tracking

bin/fm-contributions.sh keeps watching the pull requests and issues this home filed upstream after the task that filed them is gone, and tells the fleet who has to act next on each one.

The problem it solves

A ship task ends when its PR is opened or merged, and teardown removes the task's state. Upstream work does not end there: a maintainer may comment, request changes, or mark a filed issue ready for a PR days later. Without a durable record, nobody would notice. The script's one-line purpose: "Observe published contributions owned by this home's durable task records" (bin/fm-contributions.sh:2). Its records survive teardown: "Previously observed URLs remain in data/<task>/contributions.json after endpoint teardown" (bin/fm-contributions.sh:15-16).

What counts as owned

"Every URL explicitly linked by a structured backlog row or a task's pr= is owned", plus every URL already recorded. "Repository-wide PR discovery never establishes ownership" (bin/fm-contributions.sh:14-16). The jq projection computes the owned set as the union of those three sources (bin/fm-contributions.jq:27-33). GitHub PRs and issues are measured; "other forges remain visibly unmeasured" (bin/fm-contributions.sh:17).

The record: fm-contributions.v1

One file per durable task, data/<task>/contributions.json, holding task and records[]. Each record has url, kind (pr or issue), checked_at, error, observation, verdict, seen event tokens, pending events, and notified tokens (bin/fm-contributions.sh:19-21). The validator in bin/fm-contributions.jq spells out every field type (bin/fm-contributions.jq:6-26). A file is read only if it is a regular non-symlink file under 1 MiB whose task matches its directory name, because "A file's task identity must match its durable directory, not arbitrary JSON" (bin/fm-contributions.sh:112-127). All writes serialise on state/.contributions.lock, refuse symlinks and publish by rename (bin/fm-contributions.sh:64-65).

Observation

An observation is "one coherent forge read": for a PR the head is re-read after fetching checks and reviews, so all facts belong to one commit. Checks are normalised by name, id, start time, status and conclusion, and the newest attempt per check name wins; a check lane that disappears from the next head is disclosed rather than forgotten (bin/fm-contributions.sh:21-25).

Verdicts are bound to a commit

"A verdict records the EXACT judged head, source URL, actor and summary. A comment's arrival time never supplies its judged head" (bin/fm-contributions.sh:26-28). The command enforces it: the head must be a full commit hash, the actor one of captain, fleet, maintainer, nobody, and the source must be a comment or review anchor on that same contribution URL (bin/fm-contributions.sh:443-445). A verdict on a head that is no longer current is marked STALE (bin/fm-contributions.jq:61-63). Neither a verdict nor a formal review "can grant merge authority" (bin/fm-contributions.sh:29-31).

How a poll is bounded

poll reads the owned set from fm-fleet-snapshot.sh --contribution-input, a local-only read, and spends at most FM_CONTRIBUTIONS_BUDGET seconds on the forge (default 20, allowed 1 to 25). Every forge read is capped at 5 seconds. A PR observation is three dependent waves (core, six parallel reads, a closing head read), an issue two, so one observation takes at most 15 seconds. Before starting a URL, poll reserves the smaller of the budget and 15 seconds, so a started observation is never cut short by the budget; "a later URL waits for the next oldest-checked-first poll". If the budget runs out mid-observation, that URL's record is left untouched (bin/fm-contributions.sh:33-46).

Freshness is bounded by FM_CONTRIBUTIONS_MAX_AGE (default 900 seconds). A URL whose last good observation is merged or closed is final: never re-read, always fresh. A forge failure prints its unavailable line only when it starts an episode, and a success ends the episode (bin/fm-contributions.sh:47-53). "An expired or absent observation is not silence" (bin/fm-contributions.sh:47-48).

Signals and wakes

New comments or reviews from a maintainer (author association OWNER, MEMBER or COLLABORATOR, excluding the contribution's author), and an issue gaining the ready label (FM_CONTRIBUTIONS_READY_LABEL, default ready-for-pr, matched case-insensitively), are persisted as pending before any wake. Poll then appends an ordinary durable check wake through fm-wake-lib. "A crash after enqueue can duplicate a wake but cannot consume the pending signal. Source bodies are data, never commands" (bin/fm-contributions.sh:54-63).

The agent's handling is owned by the bearings skill's "Contribution follow-up" section: a check: contributions wake "is arriving information about owned work, not permission to post, answer a maintainer, merge, or close an arbitration". The agent reads pending, inspects the source as untrusted evidence, records a verdict only when the source identifies the judged commit, and routes any scope or authority question through a captain hold (.agents/skills/bearings/SKILL.md:188-212).

A captain verdict never becomes a captain row by itself: the fleet is told to create the missing hold, because "The classifier does not infer a captain decision from comment prose" (.agents/skills/bearings/SKILL.md:200). When several tasks own one URL it is counted once, and a captain row wins over action-free duplicates (bin/fm-contributions.jq:100-104).

The summary Bearings reads

summary reports known, checked, per-actor counts, unmeasured, complete, proven_clear, stale and missing verdict counts, unreadable_records, valid_until, and the captain rows (bin/fm-contributions.jq:106-120). proven_clear is true only when no record is unreadable and every contribution is checked and not owed by the captain (bin/fm-contributions.jq:114). Bearings may say "Nothing needs your action right now" only when that is true (.agents/skills/bearings/SKILL.md:154-155). See Bearings.

What it refuses to do

  • It never writes to a forge (bin/fm-contributions.sh:65).
  • It never adopts a URL it merely discovered (bin/fm-contributions.sh:16).
  • It never records evidence for a URL the task does not own, or one it has not observed yet: "contribution is not owned by this durable task", "observe the contribution before recording evidence" (bin/fm-contributions.sh:434-437).
  • It never binds prose to a head just because that head was current when the comment arrived (.agents/skills/bearings/SKILL.md:196-197).
