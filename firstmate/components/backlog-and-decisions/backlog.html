The work queue

The backlog is each home's durable list of work items. It records their state, dependencies, holds, date gates, and completion links. Every routine command reaches it through one wrapper, so it cannot fork into two copies.

Read against Firstmate commit ada21f5b. The row format belongs to the external tasks-axi tool; its quoted help comes from the installed tasks-axi 0.2.5. Up: Backlog and decisions.

What problem it solves

Everything under way must survive a restart, and "a restart must be a non-event" AGENTS.md:256. The backlog is where outstanding work lives between sessions. The context digest does not hold it, and neither does a worker's pane. AGENTS.md names three owners for the details: ".tasks.toml, docs/configuration.md, and current tasks-axi --help own the backlog schema, compatibility, retention, and routine command syntax." AGENTS.md:543

The backlog holds work items and nothing else: "It tracks work items only, never agents; persistent secondmates never appear as backlog items" AGENTS.md:535. A secondmate is "recorded in the secondmate registry and runtime state, never as a backlog work item" AGENTS.md:333. The transition gate enforces this. Its first exemption is kind=secondmate, with the stated reason "secondmates are not backlog items" bin/fm-backlog-transition-lib.sh:283-286.

The store

The code root tracks a .tasks.toml that pins the default adapter:

backend = "markdown"

[markdown]
path = "data/backlog.md"
archive = "data/done-archive.md"
done_keep = 10

.tasks.toml:1-6. The file tree lists data/backlog.md as "task queue, dependencies, history" AGENTS.md:93, and .tasks.toml as the "tracked tasks-axi markdown backend config for the default backlog backend" AGENTS.md:65.

Each home has its own backlog. "Work routed to a secondmate is recorded in that secondmate home's own backlog, not the main backlog." AGENTS.md:536 Other adapters, and the manual alternative, are covered in Backends and manual mode.

Row format (markdown adapter, Level 4)

Firstmate never writes this format itself. tasks-axi owns it, and handoff delegates moves to tasks-axi mv so that "the format has exactly one parser and cannot drift out of sync" bin/fm-backlog-handoff.sh:11-15. Firstmate's own test fixtures show the shape. The rows below are synthetic, copied from a regression test:

Sections
## In flight, ## Queued, and ## Done. Handoff seeds a fresh secondmate backlog with exactly this three-section scaffold, because left alone "tasks-axi mv writes its own # Backlog title format, which is not firstmate's home-backlog convention" bin/fm-backlog-handoff.sh:1056-1065. On the markdown adapter, "tasks-axi and manual edits produce the same ## In flight, ## Queued, and ## Done sections" docs/configuration.md:126.
Title-line metadata
Parenthesised repo, kind, priority, hold, hold-kind, hold-until, and dated since, merged, reported, or done. The snapshot strips these keys to recover the title bin/fm-fleet-snapshot.sh:438.
Body
Indented continuation lines. "Item bodies must use at least two leading spaces … because tasks-axi treats only two-or-more-space lines as body." bin/fm-backlog-handoff.sh:41-43 A captain-held row's first body line is the machine-written Captain hold set: <UTC> stamp (hold-set stamp).
Kind
Free metadata such as ship, scout, docs, or captain. It does not create a type: "There is no separate decision type: any captain-held task is the same primitive, whatever kind its row carries." bin/fm-fleet-snapshot.sh:28-29

States, overlays, and who moves them

Firstmate reads the three flags that matter for dispatch as one triple, "<state> <held> <blocked>", taken from tasks-axi show bin/fm-backlog-transition-lib.sh:508-517. Only two triples may be dispatched: in_flight no no and queued no no bin/fm-backlog-transition-lib.sh:821-826. A held row, a blocked row, and a Done row are all refused before any endpoint or local copy is created docs/configuration.md:107.

Dependencies

A dependency is a blocked-by edge from one item to another. Firstmate never follows edges itself before dispatch. It asks tasks-axi, which reports blocked: yes on the row, and the dispatch triple refuses anything blocked. After each cleanup, teardown prints the follow-up it owes: "Run bin/fm-tasks-axi.sh ready for dependency-cleared candidates, check date gates, and dispatch only work whose blockers are gone and date is due." bin/fm-teardown.sh:1560 The standing rule is: "Re-evaluate queued work after every teardown and heartbeat, dispatching items only when dependencies and time gates have cleared." AGENTS.md:541

The read-only snapshot does its own resolution for presentation. "Repeated blocker tokens remain ordered; a blocker resolves only when its structured record is Done, and missing ids stay open." bin/fm-fleet-snapshot.sh:26-27 bin/fm-fleet-snapshot.sh:545-554 A blocker id that is absent from the backlog therefore never counts as satisfied.

Across homes, tasks-axi mv moves "a whole connected set (a blocker and its dependents) atomically with blocked-by links preserved". It "refuses a move that would strand a dependency across the two files" bin/fm-backlog-handoff.sh:34-39.

Date gates

The date gate is a property of a hold: tasks-axi hold <id> --reason … --until YYYY-MM-DD, which the help text describes as a "date gate; inactive on and after that date". The snapshot relies on the same contract: "a hold-until date still in the future keeps a captain hold out of captain_actionable until it is due (tasks-axi's own contract: the hold is inactive on and after that date)" bin/fm-fleet-snapshot.sh:144-146. Once the date passes, tasks-axi stops reporting the row as held, but it keeps the annotations. That is why an expired captain deferral is still answerable (expired holds) docs/captain-hold-lifecycle.md:23.

Firstmate has one sanctioned way to defer a captain call to a date: fm-captain-hold.sh hold <id> --reason … --until <date>. The wrapper checks the date shape before passing it on bin/fm-captain-hold.sh:835-840 bin/fm-captain-hold.sh:892-898. Other hold kinds (external, load, parked, future) exist in tasks-axi, and the fixture above shows an external hold. The presentation buckets classify captain holds only; a non-captain row "carries null" bin/fm-fleet-snapshot.sh:38-39.

Not settled by the source

No Firstmate script creates a non-captain hold kind. Their use appears only in tasks-axi's own help and in test fixtures. The source read here does not show which workflow, if any, is expected to use external, load, parked, or future holds.

Retention

Done rows are history, and the backlog keeps only a bounded amount of it. done_keep = 10 and archive = "data/done-archive.md" are pinned in .tasks.toml .tasks.toml:5-6. The rule is "keep only the configured recent Done entries" AGENTS.md:544. On the tasks-axi path, tasks-axi done prunes as part of the close: its help lists --keep <n> (default from config), --no-prune. tasks-axi prune "Trim[s] a section to the N most recent tasks, archiving the rest (never deletes)". A manual home owes the same trim by hand. Teardown prints "move $ID to Done, keep Done to the 10 most recent" bin/fm-teardown.sh:1562.

Done records stay in their home. Handoff refuses them: "Done records stay with their home and are pruned/archived" bin/fm-backlog-handoff.sh:981-984. The retained Done rows feed Recently Landed on Bearings. At session start they are "pure weight", so the startup digest omits them bin/fm-session-start.sh:131-133.

The wrapper: bin/fm-tasks-axi.sh

"Every routine firstmate backlog read or mutation goes through this command rather than a bare tasks-axi" bin/fm-tasks-axi.sh:7-9.

Why it exists

"The tracked .tasks.toml paths resolve against the directory tasks-axi runs in, not FM_HOME, so a bare tasks-axi run from the code root addresses the code root's data/ whenever the home lives elsewhere." A symlink cannot fix this: "tasks-axi writes by renaming a temp file over its target, which replaces a symlink with a regular file, so linking the code-root copy into the home forks the queue on the first such write" docs/configuration.md:128-129.

How it addresses the home

  1. The data directory is FM_DATA_OVERRIDE, else $FM_HOME/data, else the code root's data/ bin/fm-tasks-axi.sh:32-33 bin/fm-tasks-axi.sh:48-50.
  2. fm_backlog_tasks_axi_addressing resolves the addressing root: the data directory's parent. On the markdown adapter it also resolves the file <data>/backlog.md bin/fm-backlog-transition-lib.sh:265-278.
  3. The wrapper exports that file as TASKS_AXI_FILE, "rather than a trailing --file so the no-command dashboard works too". For a non-markdown adapter it clears any inherited TASKS_AXI_FILE bin/fm-tasks-axi.sh:27-30 bin/fm-tasks-axi.sh:117-124.
  4. It makes relative --to and --*-file values absolute against the caller's directory, because tasks-axi will run from the backlog root. --report stays as given, since it is stored verbatim as a link bin/fm-tasks-axi.sh:9-15 bin/fm-tasks-axi.sh:85-108.
  5. It runs cd into the root, then exec tasks-axi bin/fm-tasks-axi.sh:126-127.

Refusals

Each refusal exits 2 with nothing run bin/fm-tasks-axi.sh:35-44:

  • tasks-axi is missing from PATH.
  • The caller passed --file. The wrapper owns the addressing, and "tasks-axi would silently let the last --file win". The error reads "this command always addresses this home's backlog at $DATA; drop --file, or run tasks-axi directly for another backlog" bin/fm-tasks-axi.sh:94-96.
  • The data directory, or its backend configuration, cannot be resolved.
  • <data>/backlog.md is itself a symlink, because "the first write would replace the link with a private copy, exactly the fork this command exists to prevent" bin/fm-tasks-axi.sh:118-120.

Otherwise the exit status is tasks-axi's own.

Detecting a fork that already happened

Bootstrap looks for the damage a bare call would leave. If the code root's data/backlog.md or data/done-archive.md exists and is not this home's own file, it prints BACKLOG_RECONCILE: code-root <file> is not this home's <file>; tasks-axi wrote the code root instead of this home, so rows in it may be missing here - merge it into this home's copy and move it aside bin/fm-bootstrap.sh:1537-1546. This check runs "even in a read-only session" docs/configuration.md:130.

Bounded reads

A backlog read that hangs at session start would blind the whole session. fm_backlog_row_show therefore bounds each read, with FM_BACKLOG_ROW_TIMEOUT_SECS defaulting to 10. "the first bound hit latches FM_BACKLOG_ROW_SHOW_WEDGED and every later read in the same sweep returns immediately, still naming its own item so nothing is silently skipped" bin/fm-backlog-transition-lib.sh:401-419. A mutation under a held lock can be bounded through FM_TASKS_AXI_TIMEOUT, which uses GNU timeout, gtimeout, or a perl watchdog. With no mechanism at all it refuses rather than running unbounded bin/fm-backlog-transition-lib.sh:319-394. fm-captain-hold.sh refuses to treat a timed-out read as absence, because "every caller below would otherwise spend it as one - minting a duplicate task, skipping a keyed answer, or reporting a task that exists as missing" bin/fm-captain-hold.sh:359-379.

How the backlog reaches a session

Session start prints a compact listing as a recovery input, "not a reporting surface" bin/fm-session-start.sh:129-130:

  • Done rows never appear.
  • Every in-flight, held, and blocked row appears in full, with hold_kind, hold_reason, and blocked_by.
  • Only the plain ready-queued list is bounded, by FM_SESSION_START_QUEUED_LIMIT (default 20). An exact remainder count is printed bin/fm-session-start.sh:134-143.

The groups are tasks-axi's own filters, so "this script never reimplements task state" bin/fm-session-start.sh:144-150 bin/fm-session-start.sh:478-499. In manual mode it prints only headings and title lines bin/fm-session-start.sh:151-156.

Keeping notes honest

The item body is the task's notebook. AGENTS.md sets its hygiene:

  • "Keep free-form notes free of temporary paths, moving versions, ephemeral identifiers, and copied state that will rot."
  • "Inspect the current task note before replacing its considered body, and archive the superseded body when recoverability matters rather than appending by default."
  • "Preserve durable structured identifiers, dependencies, and completion artifact links."

AGENTS.md:547-550

The archive option is tasks-axi update --body-file … --archive-body. The compatibility probe requires that flag bin/fm-tasks-axi-lib.sh:7-8, and answer uses it for every resolution record bin/fm-captain-hold.sh:936.
