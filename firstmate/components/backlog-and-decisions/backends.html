Backends and manual mode

Two separate choices decide how a home's backlog is written. The first is whether Firstmate mutates it through tasks-axi at all, or leaves it to hand editing. The second is which tasks-axi adapter holds the rows. A single gate turns those choices into "transition automatically", "skip", or "refuse".

What "compatible tasks-axi" means

"Compatible means tasks-axi --version reports FM_TASKS_AXI_MIN or newer, tasks-axi update --help exposes --archive-body for recoverable note rewrites, and tasks-axi mv --help exposes [<id>...] for atomic multi-ID moves required by secondmate handoffs." bin/fm-tasks-axi-lib.sh:6-9 The floor is FM_TASKS_AXI_MIN=0.2.4 bin/fm-tasks-axi-lib.sh:45.

  • A version it cannot parse is incompatible. "An unparseable version is incompatible, never assumed current, so a development or vendored build cannot pass a floor it was never checked against." bin/fm-tasks-axi-lib.sh:82-84
  • The feature probes stay even when the version passes. They are "defense in depth for stripped or forked builds that advertise a current version without those flags" bin/fm-tasks-axi-lib.sh:12-13.
  • The verdict is reused, but only within one process and one hop. It is memoised in-process. A parent can pass it to one child through FM_TASKS_AXI_COMPATIBLE=0|1, and sourcing the library consumes that variable, "so the verdict reaches the child that needs it and never leaks onward into a spawned agent's environment, where it could outlive a tasks-axi upgrade" bin/fm-tasks-axi-lib.sh:30-43 bin/fm-tasks-axi-lib.sh:47-52.

fm-captain-hold.sh adds one probe of its own. tasks-axi hold --help must mention --kind captain, or the command fails with "tasks-axi does not expose the captain-hold contract" bin/fm-captain-hold.sh:353-357. Bootstrap reports an installed but incompatible build as MISSING: tasks-axi bin/fm-bootstrap.sh:1491-1493. Bootstrap "requires compatible tasks-axi on every profile" docs/configuration.md:122.

The single gate

fm_backlog_transition_applies <config-dir> <data-dir> <kind> is "the single gate" for automatic transitions. Spawn, teardown, and bootstrap all call it bin/fm-backlog-transition-lib.sh:23-28 bin/fm-backlog-transition-lib.sh:280-317. It has three outcomes. 0 means transition automatically. 1 means an exemption, "never errors", with the reason stored in FM_BACKLOG_TRANSITION_SKIP. 2 means refuse before mutating anything.

The documentation states the scope: "The gate does not apply to persistent secondmates, manual-backend homes, or markdown homes without a backlog file, preserving their existing persistent-agent, manual, or ad-hoc lifecycle behavior while configured non-markdown adapters remain active without that file." docs/configuration.md:113 On the refusal side: "missing or incompatible tasks-axi, an unresolvable configured data directory, or one containing a control byte fails lifecycle work before mutation" docs/configuration.md:115.

The manual alternative

Writing manual into the local config/backlog-backend forces "manual backlog editing" docs/configuration.md:123. Such a home "owns its backlog file outright: the lifecycle transitions above are skipped there, dispatch and completion never fail over the file's contents, and a completed teardown prints the hand edit that is owed instead" docs/configuration.md:124.

  • Dispatch. The gate returns 1, so spawn never probes the row. It does not refuse a missing or held item, and it does not move anything bin/fm-spawn.sh:3104-3133. AGENTS.md keeps the duty with the supervisor: "a manual-backend home retains the hand-editing contract in docs/configuration.md" AGENTS.md:331.
  • Completion. Teardown prints the edit it did not make: "Backlog: $ID just finished ($BACKLOG_SKIP_REASON). Update $backlog_display - move $ID to Done, keep Done to the 10 most recent, then re-scan Queued and dispatch only work whose blockers are gone and date is due." bin/fm-teardown.sh:1561-1562
  • Startup listing. Session start prints headings and title lines only, labelled manual backend. It keeps every held and blocked title line by reading the line's own markers bin/fm-session-start.sh:151-156 bin/fm-session-start.sh:511-517.
  • What manual does not change. Handoffs "bypass that routine-backend choice … the config/backlog-backend=manual knob governs firstmate's own hand-editing of its backlog, not this validated helper" docs/configuration.md:117 docs/configuration.md:120. fm-captain-hold.sh never consults the manual knob either. It calls tasks-axi directly through its own addressing bin/fm-captain-hold.sh:340-357, so a captain hold on a manual home still needs a compatible tasks-axi.

The setting also suppresses one routine fact: "suppress the verbose BOOTSTRAP_INFO: tasks-axi available fact, not missing-tool reporting" docs/configuration.md:123 bin/fm-bootstrap.sh:1523-1526.

Header and implementation disagree

The library header says that absent or any non-manual value "keeps the default tasks-axi backend path, falling back to manual mutation when the tool is not compatible" bin/fm-tasks-axi-lib.sh:16-17. The lifecycle gate does not fall back. An incompatible tasks-axi returns 2, and spawn and teardown refuse bin/fm-backlog-transition-lib.sh:312-315, which matches docs/configuration.md:115. The only fallback found is a read: session start's listing drops to the title-line form, labelled "tasks-axi unavailable or incompatible" bin/fm-session-start.sh:515-516. The "manual mutation" wording therefore describes no mutation path at this commit.

Non-markdown adapters (Beads)

"A home may instead select another tasks-axi adapter such as Beads through its own .tasks.toml or TASKS_AXI_BACKEND; firstmate still uses only tasks-axi verbs for routine backlog reads and mutations, and the adapter maps start and evidence-bearing done transitions to its native statuses and evidence fields." docs/configuration.md:102 The lint enforces the boundary: it rejects a "direct Beads CLI invocation" because "Backend adapters belong behind tasks-axi" bin/fm-lint.sh:168 bin/fm-lint.sh:389.

  • Addressing. The data directory's parent is always the working root. --file <data>/backlog.md is passed only for markdown, because on any other adapter "--file would override the adapter's own workspace path" bin/fm-backlog-transition-lib.sh:30-39. fm-captain-hold.sh does the same bin/fm-captain-hold.sh:334-351.
  • Captain rows. The create path passes --kind captain, which is metadata ("Beads native type task"). It also sets BD_DUE_REQUIRED=false "rather than inventing a due date or registering a types.custom captain issue type" bin/fm-captain-hold.sh:43-48 bin/fm-captain-hold.sh:873-882 docs/configuration.md:103-105.
  • Migrated holds. A home that moved from markdown to Beads resolves old attested ids through the migration's marker notes, or as a last guess through the configured prefix (legacy identities). That resolution "reads its graph path, binary, and prefix from the root .tasks.toml [beads] section only" docs/configuration.md:114.
