Automatic transitions

Dispatch and cleanup move the backlog row themselves, in the same process and under the same lock as the task record they create or remove. If the move does not land, they refuse or fail loudly rather than report success.

Read against Firstmate commit ada21f5b. Up: Backlog and decisions. The rest of fm-spawn.sh and fm-teardown.sh belongs to Crew.

The invariant

"In ordinary successful lifecycle state, state/<id>.meta exists <=> this home's backlog row for <id> is In flight; the one teardown crash window is represented by state/<id>.backlog-close. The script performing the mechanical record change owns the paired backlog transition and runs it in the same process, under the per-task meta lock it already holds, before it reports success. Nothing else - not a later agent turn, not a printed reminder - is load-bearing for the pairing."

Why they refuse rather than report success

AGENTS.md states the contract: "When the automatic transition gate applies, dispatch and completion move the item themselves - bin/fm-spawn.sh and bin/fm-teardown.sh own those transitions and refuse rather than report success without them - so what remains yours is filing the item before dispatch, recording decisions, and keeping notes current" AGENTS.md:540. The reasoning appears in three places.

  • A reminder is not a mechanism. Before the fusion, the backlog could fall out of step whenever an agent forgot the separate edit. Now "the ordinary successful path cannot leave the backlog and live task set out of sync" docs/configuration.md:106. Teardown's own comment reads: "Closing the backlog item is this script's own last act on the record, not a printed instruction for a later turn" bin/fm-teardown.sh:1539-1542.
  • A refusal early is free; a refusal late strands things. Spawn proves the row can move "BEFORE any endpoint, worktree, or record exists: a refusal here costs nothing to unwind, while the same refusal after publication would strand a live pane" bin/fm-spawn.sh:3100-3103.
  • An exit code is not proof. After an interrupted spawn, the exit path re-reads the row, "because the commit's own exit status has been observed to agree with a row that did not actually move (fm-yi4j evidence, 2026-09-05)". It then reports "exactly what was verified or attempted - never intent phrased as outcome" bin/fm-spawn.sh:4531-4537.

Dispatch: fm-spawn.sh

  1. Preflight, before anything exists. If the gate applies, a missing row refuses with the command to fix it: "task $ID has no backlog item in this home, so dispatching it would leave a worker no record owns; add it first (bin/fm-tasks-axi.sh add $ID '<title>' --kind $KIND) and re-run". A row that is not dispatchable refuses "before creating its endpoint or local copy". A gate result of 2 refuses because the data directory is inaccessible bin/fm-spawn.sh:3104-3133. Under the away posture, the supervision branch may dispatch only queued no no rows bin/fm-spawn.sh:3117-3122.
  2. A pending close blocks a new worker. Spawn refuses while state/<id>.backlog-close exists: "finish or repair that close before dispatching a new worker" bin/fm-spawn.sh:3140-3143.
  3. Publish the record first. The meta is published under the per-task meta lock bin/fm-spawn.sh:4513-4519. The lock is held through launch delivery, so teardown "cannot observe or complete a fresh provisional record between its state check and tasks-axi start" bin/fm-spawn.sh:4579-4584. Spawn needs no crash marker, because "it publishes the meta first, so a crash leaves the meta itself as the evidence that the row is owed a start" bin/fm-backlog-transition-lib.sh:50-52.
  4. Commit. fm_backlog_dispatch_transition re-probes the row, refuses one that is no longer dispatchable, and runs start only for queued no no. A row already In flight is accepted as-is bin/fm-backlog-transition-lib.sh:828-850. The call is bounded by FM_TASKS_AXI_TIMEOUT (default 30 s here) and retried once bin/fm-spawn.sh:4928-4945.
  5. Failure. A fresh dispatch rolls back the record and busy state, then prints "its record was removed so no worker is left that the backlog does not own - close out endpoint $T and local copy $WT by hand". If the rollback itself is incomplete, spawn says so bin/fm-spawn.sh:4946-4960 bin/fm-backlog-transition-lib.sh:852-867.

Completion: fm-teardown.sh

  1. Gate. A gate result of 2 refuses: "task $ID cannot be torn down because its backlog data directory is inaccessible". A result of 1 records the skip reason bin/fm-teardown.sh:488-497. When the gate applies, the record must carry a spawn_gen that "identifies one exact incarnation", or teardown refuses bin/fm-teardown.sh:499-543.
  2. Ask about the captain. Teardown asks, "before any destructive step, so 'cannot tell' can refuse while everything is intact" bin/fm-teardown.sh:545-562. On any exit other than 0 or 1 it prints "fix that read and retry rather than risk closing a captain call with no recorded answer".
  3. Choose the deliverable. A scout closes with --report <data>/<id>/report.md. A local-only ship closes with --note "local main". Any other ship closes with --pr <url> from its own record bin/fm-teardown.sh:1518-1537. A scout without a report, or one that fails the completion gate, is refused earlier bin/fm-teardown.sh:3280-3293.
  4. Record the intent. fm_backlog_close_marker_write stages and validates the record, then publishes it atomically bin/fm-teardown.sh:3427-3442. If it cannot be recorded, teardown is "retaining every durable task record" and exits.
  5. Clean up, then transition. After the endpoint, worktree, and inbox are gone, and still under the meta lock, teardown runs close or retain bin/fm-teardown.sh:3668-3685. On failure it reports "its endpoint and local copy are cleaned up, but its backlog item could not be closed atomically … the pending close is recorded and the next session start retries it" and exits 1.
  6. Tell the supervisor what happened. backlog_refresh_reminder prints what already happened. After a close it prints "Run bin/fm-tasks-axi.sh ready for dependency-cleared candidates …". After a retain it prints "still held for the captain with its deliverable recorded. Relay the question and close it only with bin/fm-captain-hold.sh answer." When the gate was skipped, it prints the hand edit that is owed bin/fm-teardown.sh:1543-1564.

None of this loosens the landed-work gates: "the transition runs only on the paths that already proceed to remove the record" bin/fm-teardown.sh:28-29.

Retain: cleanup never closes a captain call

The hold policy prefers holding the very work item a question gates. "the backlog row a finished task's cleanup is about to close is routinely the captain's own call" docs/captain-hold-lifecycle.md:36. When open returns 0, only the close changes. fm_backlog_retain runs three steps bin/fm-backlog-transition-lib.sh:580-671:

  1. It appends one line to the end of the body, Deliverable of the finished work: <PR url | report path | note>, unless that exact line is already present.
  2. It copies a supported artifact into the row's structured fields: any --pr, or a --report only when it is exactly data/<id>/report.md bin/fm-backlog-transition-lib.sh:571-578.
  3. It runs tasks-axi reopen, which returns the row to Queued with its hold intact.

The row "remains on the appropriate Captain's Call or Charted Next decision surface instead of reading as work still under way" docs/captain-hold-lifecycle.md:38. --force does not lift this, "because it authorizes discarding unlanded work, never the captain's question" docs/captain-hold-lifecycle.md:45.

Known gaps, recorded upstream

Two retained deliveries cannot reach the row under tasks-axi 0.2.5. A local-only delivery's note is lost, "because --note exists on tasks-axi done but not on tasks-axi update". A relocated report is lost because "tasks-axi accepts only data/<id>/report.md". Both are "recorded for separate upstream work" docs/captain-hold-lifecycle.md:40-43.

The pending-close record and its replay

Only teardown needs a durable record. "it removes the meta and with it the completion links, so a process killed between the two halves would leave nothing to reconstruct the close from" bin/fm-backlog-transition-lib.sh:41-44.

Format (Level 4)

id=<task-id>
data=<absolute data directory>
spawn_gen=<the incarnation this close belongs to>
cleanup_incomplete=0|1
mode=retain                      (only for a captain-held row; absent means close)
arg=--pr
arg=https://…/pull/N             (or --report / --note pairs)

Writer: bin/fm-backlog-transition-lib.sh:1109-1118. Validator: bin/fm-backlog-transition-lib.sh:905-960. The note local main is serialised as local%20main and restored on replay bin/fm-backlog-transition-lib.sh:1101-1108 bin/fm-backlog-transition-lib.sh:1178-1180.

The validator refuses a record with control bytes, an unknown line, duplicate fields, a mode other than close or retain, an id that differs from its filename, or a missing data or spawn_gen. It "pins the data path to this home's configured root before any recovery mutation" bin/fm-backlog-transition-lib.sh:45-48. Writer and replay share this one validator, so teardown "never publishes or acts on a close replay would reject".

Healing drift: records without a moved row

The same sweep then walks every state/*.meta. It skips any meta whose pending-close record survives, because "A pending close remains authoritative even when replay failed". It heals exactly one case: "Heal only the unambiguous case: a queued row for a record this home already owns. A held row is the captain's to move, and a closed row is a contradiction this sweep must not resolve by resurrecting the item." bin/fm-bootstrap.sh:1318-1369 Secondmate records and Orca cleanup-recovery records are excluded. The sweep "never reads or writes another home" bin/fm-bootstrap.sh:1246-1253.

An interrupted spawn

If a signal arrives while the commit is running, spawn defers it. On exit, spawn_report_preserved_state re-reads both halves under the same lock. It reports "verified preserved" only when the record is present and the row reads in_flight no no. If the row did not move, it moves it and verifies again. Otherwise it tells the operator exactly what to close out by hand bin/fm-spawn.sh:4538-4567. The regression suite is tests/fm-backlog-atomicity.test.sh docs/configuration.md:109.
