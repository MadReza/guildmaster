Record divergence

One captain call can be written down twice: once as a keyed decision in a status log, and once as a backlog task held for the captain. Closing one record does not close the other. diverged reports when the status log says a call is resolved but the backlog still holds it. The wake drain prints that report every turn, and nothing is closed automatically.

Read against Firstmate commit ada21f5b. Up: Backlog and decisions. The status log and the OPEN DECISIONS fold belong to Communication; the drain belongs to Supervision.

The problem

"A captain call can have two records, and closing one does not close the other. A resolved [key=...] line closes the status-log fold; the structured captain-held task closes only through answer. Until this guard existed, closing on the status side alone left no trace of the disagreement: the fold went quiet, the durable record kept saying the captain owed an answer, and nothing warned." docs/captain-hold-lifecycle.md:161-163 The script comment puts it briefly: "The defect was never the separation; it was the silence." bin/fm-captain-hold.sh:1734-1739

Exactly what is flagged

"It flags exactly one condition: a task still open and still carrying the captain-hold annotations, whose key was closed on the status side by the resolve verb, resolved through the collapsed identity (the key is the task id) or the legacy derived one." docs/captain-hold-lifecycle.md:166

Three states are deliberately not divergence docs/captain-hold-lifecycle.md:169-172:

The two closing verbs are told apart by status_key_closing_verb in bin/fm-classify-lib.sh docs/captain-hold-lifecycle.md:170. tests/fm-classify-decision-key.test.sh pins that function, including "treats a prose mention as no transition" docs/captain-hold-lifecycle.md:214.

How it runs

  1. Same home only. The command runs only when STATE is $FM_HOME/state, "since tasks-axi reads that home's backlog and a mismatch would report one home's logs against another's tasks" docs/captain-hold-lifecycle.md:175 bin/fm-captain-hold.sh:1805-1810.
  2. Cheap candidate set. One tasks-axi list gives every open task id. It reads only the first two comma-separated fields, "so a title containing commas or quotes cannot shift them" bin/fm-captain-hold.sh:1772-1785. It then does one [key=…] token scan per status log bin/fm-captain-hold.sh:1787-1793.
  3. Precise check only where needed. For each open id whose own key appears in a log (the id itself, or <origin>-decision- stripped for a legacy row), it asks status_key_closing_verb. When the verb is resolved, it reads the row and confirms Not Done and hold_kind: captain bin/fm-captain-hold.sh:1817-1851.
  4. Output. One line per divergence, <task-id>\t<origin>\t<key>\t<title>, "nothing when the two records agree". The title is sanitised, because it is "the only free-text field here" bin/fm-captain-hold.sh:1769-1770 bin/fm-captain-hold.sh:1839-1843.
  5. Silent failure. "If tasks-axi is unavailable or its listing cannot be parsed, the guard cannot read the structured record and prints nothing." It deliberately "skips the mutation-oriented compatibility floor" on this per-wake path bin/fm-captain-hold.sh:1811-1816.

In the wake drain

print_record_divergence_section runs diverged under FM_DIVERGENCE_TIMEOUT (default 20 s, and a non-positive value falls back to 20). It caps each item at 220 bytes and the whole section at 2000 bytes, announcing any omissions bin/fm-wake-drain.sh:504-548. It is "Bounded and silent like OPEN DECISIONS above", and "A guard failure never changes the drain's exit status - a supervision turn must still present its wakes when the backlog tool is having a bad day" bin/fm-wake-drain.sh:499-503. The section header reads:

RECORD DIVERGENCE (answered in the status log, still held in the backlog - nothing was closed automatically):
…
RECORD DIVERGENCE: reconcile each one - record the captain's own words with bin/fm-captain-hold.sh answer <task> --decision-file <path>, or re-open the status decision when that resolution was not the captain's word.

bin/fm-wake-drain.sh:539 bin/fm-wake-drain.sh:548. Session start's drain prints the same section AGENTS.md:197.

How the supervisor must read it

"Treat any RECORD DIVERGENCE section as a contradiction between two records of one captain call, never as proof the captain ruled; load captain-hold-lifecycle and reconcile it in whichever direction the evidence supports." AGENTS.md:432 The skill adds: "a call can dissolve because its premise was false, or turn out to have been a question of fact rather than the captain's to answer. Reconcile it with what actually happened - answer when the captain's own words exist to record, and a fresh needs-decision line re-opening the status decision when that resolution was not the captain's word." .agents/skills/captain-hold-lifecycle/SKILL.md:53-54

The regression suite reconstructs the silent case and the false-signal boundary. It shows that "the backlog task, its hold, and the status log all survive the report unchanged and the printed hint names both reconciliation directions" docs/captain-hold-lifecycle.md:193.
