Firstmate, as a C4 model

A navigable study of how Firstmate works, written as the foundation for designing its successor. It describes Firstmate as it is, with every claim tied to the file that proves it.

What Firstmate is

Firstmate is an "agent distro". It is not an app, a model, a harness, or a CLI. It is a cloned directory of instructions, skills, scripts, and state conventions, and any supported terminal coding agent can follow it README.md:36-39. Launching a harness inside the clone makes that session the first mate and makes the user the captain README.md:40.

The captain talks to that one agent only. The first mate turns requests into tasks. It spawns an autonomous worker for each one in its own git worktree, inside a visible terminal session. It supervises the workers with a bash watcher that costs no tokens while idle, and it hands back finished pull requests, approved local merges, or investigation reports README.md:32-33 docs/architecture.md:11.

It never edits a project itself AGENTS.md:27-28. It never merges without the captain's word or a standing per-project grant AGENTS.md:32-33. It never tears down unlanded work AGENTS.md:34-35. It keeps every obligation on disk, so a restart loses nothing VISION.md:43-45. Larger fleets can add persistent secondmates: full Firstmate homes of their own, local or on an SSH host, that still report to the primary README.md:34.

The C4 levels used here

Level 1, System context
Firstmate as one box: the captain, and every external system it touches. That covers agent harnesses, session backends, Treehouse, forges, no-mistakes, tasks-axi, Relay, mail, voice, notifications, and remote hosts.
Level 2, Containers
The running pieces and stores inside one instance, with a numbered table of every interaction. The pieces are the supervisor agent, session start, hooks, watcher, wake queue, steering inboxes, status logs, operational home, toolbelt, backend adapters, workers, and secondmate homes.
Level 3, Components
Inside each area section below: the scripts and records that make up one container, and how each is used.
Level 4, Code
Only where a record format or protocol needs it, for example a status line, a wake-queue row, or an inbox record.

How to read these pages

  • A citation such as bin/fm-watch.sh:3-4 links to that line range at the studied commit. Script headers are treated as each script's contract, and the implementation as confirmation.
  • Boxes headed "Not settled by the source" mark behaviour the code does not decide. They are not guesses.
  • These pages use Firstmate's own words: captain, first mate, crewmate or worker, scout, secondmate, brief, backlog. Guildmaster's vocabulary lives in the repository's TERMINOLOGY.md, which maps each Firstmate term to its successor.
  • Authors adding pages follow AUTHORING.md.
