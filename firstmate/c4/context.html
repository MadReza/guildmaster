System context

Firstmate as one system: the one person it serves and every external system it touches. The next level, Containers, opens the box.

Read against Firstmate commit ada21f5b (2026-09-22). Every citation links to that commit.

The system in scope

Firstmate describes itself as "an agent distro for running a crew of agents": a directory of instructions, skills, tooling, policies, and state conventions that turns a general-purpose coding agent into a supervisor README.md:36-40. There is no app to install. Launching a supported harness inside the clone makes that session the first mate, and makes the user the captain README.md:39-40.

Two parts make up one running instance:

  • The tracked code root: AGENTS.md, bin/, .agents/skills/, docs, and hooks. It is shared template material AGENTS.md:44-48. Only AGENTS.md, bin/, and .agents/skills/ are loaded by a running first mate AGENTS.md:572.
  • The operational home selected by FM_HOME. It holds the private data/, state/, config/, and projects/ directories, while the scripts still come from the code root AGENTS.md:54, docs/configuration.md:11-15. All of them are gitignored AGENTS.md:47.

Its stated scope is narrow: "the command layer, not the workshop". Validation belongs to no-mistakes, CI belongs to the forge, and merge policy belongs to the configured authority VISION.md:71. It "owns exactly one thing: the layer between the captain's intent and the agents that carry it out" VISION.md:8.

At this level Firstmate is drawn as one box, but it can contain several copies of itself. Persistent secondmates are full Firstmate homes of their own, local or on an SSH host. They are still direct reports of the primary, not a second architecture AGENTS.md:23. They appear as containers on Level 2.

External systems

This list comes from the commands and URLs the scripts actually invoke. A scan of every HTTPS host named under bin/ finds only GitHub, myfirstmate.io, api.typesafe.ai, Bedrock runtime, and tool-install or documentation URLs. Firstmate never calls a model provider's API itself: models are reached through the harness CLIs, typesafe.ai, and Bedrock.

Deliberately not external systems

  • Codex App is not a runtime backend: "Codex App is not a selectable Firstmate runtime backend" docs/codex-app-backend.md:3, and fm-backend.sh leaves it out on purpose bin/fm-backend.sh:69.
  • Trace context reaches no collector. It only injects TRACEPARENT into a spawned agent's shell, and "firstmate emits no spans itself" bin/fm-trace-context-lib.sh:5 bin/fm-trace-context-lib.sh:71.
  • Project repositories are cloned under projects/, but they are the objects of the work, not collaborators. Firstmate is read-only over them except for narrow guarded paths AGENTS.md:27-31.
